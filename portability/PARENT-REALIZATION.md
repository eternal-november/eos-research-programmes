## Elementary leaf and counted frontend

The local work alphabet is fixed native64 register operations, including addition/subtraction with one carry flag, comparison, shifts, conditional selection and fixed-register transfer. Its price is at most one work unit per operation, as in RUNTIME-PORTS. A64-bit operation does not mean a256-bit multiply/divide or a globally addressed memory access. Four-limb arithmetic and physical address traversal are counted separately. These finite mathematical circuit laws are source assumptions, not measured device prices.

Use one fixed address tree for C and one for private R/W per processor, each with depth at most13. Uninstalled leaves are inert. Padding a tree does not allocate another physical memory word. Existing C and private arrays retain their physical identity. A private-word leaf contains its four64-bit registers; a C leaf contains its actual192 sign-decoded bit coordinates. An active request carries a bounded address/phase header down one path; the reply returns on those fixed links. Inactive nodes do not evaluate an exponential mux fanout. At a hop, at most20 native work covers header capture/selection/forwarding, up to four64-bit reply transfers with acknowledgement, and local scrub/release. A private leaf uses at most12 work for its four local registers and finite capture/commit control. A C leaf uses192 fixed bit captures and16 packing/control work. Thus a routed private-word access costs at most272 and a C capture468. The maximum128 bits of state per internal node includes request/reply staging and phase; it is not hidden in the programme's W.

The coherent local capture/commit law is explicit: a qualified read returns the actual selected local word at its capture event, and a qualified write changes that selected local word at its commit event. It does not validate that word. This is a fixed-width local data law of the same scope as the existing raw snapshot primitive. The new parent does not derive coherence from Python list indexing. An implementation using skewed limb reads must instead establish stability through that read interval or expose the intermediate samples; the atomic quotient is not licensed for that implementation merely by counting work.

## Opcode computation and total outcomes

The interpreter executes the captured opcode, never a host-language controller/helper function. Result identities and successful-bit comparisons belong to checking, not a runtime success gate: the divider returns its computed result, and the native writer completes its fixed control path without testing whether C matches an intended word. LI sign-extends the112-bit immediate; register results are masked to256 bits. Boolean AND/OR use the frozen ISA's truth-value convention, not bitwise conjunction. Shifts clamp their signed count to[0,256]. Invalid register reads return0 and invalid register writes do nothing. Out-of-range W/C indices return0 or make no write. Stack underflow/overflow halts. Unknown opcodes are paid no-ops. Unknown or wrong-arity I/O encodings are paid no-effects, without a child offer. Removed legacy opcodes consume the existing absence decoder and retain unrelated current conversions.

For DIV/MOD, the runtime implementation is a256-round unsigned restoring division over four64-bit registers, followed by signed floor correction. A round costs at most32 native operations:4 input-bit selection,12 four-limb shift,4 subtraction-with-borrow,2 take-predicate operations,4 conditional selections,3 quotient-bit operations and3 finite-round control operations. Initialization, zero testing, signed magnitudes, quotient/remainder correction and return fit128 additional work. The resulting8320 bound plus2816 frontend is11136, below16384. A zero divisor returns0. The minimum signed value divided by-1 wraps only at the final256-bit register result. The executable checks signed boundary cases and deterministic varied inputs against the frozen floor convention. Four-limb add/subtract/compare/shift and fixed4x4-limb multiplication retain the separately stated128/256 bounds under the same native64 alphabet.

The source leaf permits unsuccessful outcomes. With insufficient parent work, closed power or an occupied parent, no instruction captures another token. An invalid PC uses a finite paid attempted parent and halts. A stalled clock supplies no next control edge; that discrete transition retains its control index, work and parent. Any elapsed physical flow of its retained drive remains governed by the separate native flow law, as exposed below. Loss of the reserved work leaves a real partial-effect wait. Neither digital reset nor a new invocation fills the cell. These failed branches receive no nominal completion promise; their time/incident projection must be retained by the parent source.

## One parent, one completion, retained body

There is one20480-work ready/pending cell per processor. Actual transfer from the finite operating stock fills it before launch. Launch converts that same cell into the occupied parent, pays the capture work, and stores an immutable descriptor of the body, actual instruction and necessary operands. A new launch or recharge is refused while occupied. The local one-shot completion strobe is consumed before a port callback; even a reentrant callback cannot issue another completion. Unused work is dissipated once at completion, and another instruction requires another physical recharge.

A CPU reset may change architectural PC but cannot clear, rebind or duplicate this parent. Actual source power loss also blocks fresh parent recharge. A read instruction such as LOADC uses its addressed current word at the actual memory-read stage, not a launch-time snapshot or a protected template. A source power loss blocks new launches while an already funded suffix continues on its captured body. Fresh rearm must wait for that suffix and perform the actual PC-entry/reset order. The module tests power loss and reset after capture, mutation of current C/registers, replay, reentrant completion, blocked recharge and a depleted operating stock. Its finite BankWork account checks transfer/spending/dissipation conservation rather than creating a fresh20480 gift for each instruction.

## Native STOREC and its observation boundary

The literal native child retains the same captured body, unsigned256-bit address and192-bit data. It executes256 address-capture steps,256 address-comparison steps,192 data-capture steps, six steps per bit,192 scrub steps and32 completion/control steps. Every step debits8 from the same CPU parent; the one-unit mechanical envelope is also debited. Full work16641 plus2816 is19457, leaving1022 above the retained unit floor. No second private instruction budget or separate write capsule is added. Invalid addresses finish after512 steps without a write.

The executable exposes partial physical words. After the first written bit of a zero-to-all-one operation, actual C equals1, neither the old nor final word. A no-clock-edge transition or source power loss retains the control state, partial effects and original body. The exposed native drive mode is retained too. Such a transition does not simulate elapsed physical flow: if the clock stops while a bit drive is engaged, that paid force can still move the bit. The checker exhibits this countercase. The existing physical flow/work law must govern that interval; no frozen-bit conclusion or nominal completion deadline is granted to a failed clock. The paused completion test uses a disengaged bit boundary. Local fetch/LOADC cannot overlap because the one parent remains occupied. The ordinary remote code-query/own-read routes are absent in this family; outgoing field setters retain earlier captured bit values rather than rereading C during the write. Under those observer/exclusion conditions, programme-visible observations admit the atomic STOREC quotient at completion. Physical bit, reaction, work and external-intrusion observations do not receive that quotient and remain in the source state.

The2080-step native duration remains longer than one ordinary retirement interval. Its complete frontend/native bound remains below1/64, so the existing larger pending-operation drain consumer can cover it after its actual binding is supplied. No all-opcode lower retirement-rate claim is restored. A failed or partially executed physical write is not represented as a successful atomic write; its partial coordinates and causal debt remain explicit.
