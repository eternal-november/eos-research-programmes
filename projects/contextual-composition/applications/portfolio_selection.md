## C — Full: eager versus lazy consistent random-function service

**Parameters and motivation.** Finite nonempty key/value sets A,B; query bound N; one owned service handle and finite call counter. Eager implementation samples a uniform function A→B once. Lazy implementation samples an independent uniform value only on a first query and remembers it. Clients may choose queries adaptively, repeat them, and retain code aliases without duplicating authority.

**Inputs.** Same finite O1 probability/cost and causal-tree content; actual O4 private store and bounded method interface. Both sides expose precisely the same call-only interface. Internal table/cache/init steps may be hidden only by the declared permitted private-event normalization. No public inspection of table/cache or timing-dependent branches.

**Discriminating target.** For every admitted bounded adaptive client, equal public query/reply/capability observations and a coupled external total-cost inequality: eager initialization pays |A| unit sample costs; lazy pays the number of distinct queried keys (at most |A|); common per-call overhead is identical. Establish a conditional-uniform invariant for unqueried eager coordinates given the observed history/cache, plus accumulated-credit accounting. Then exhibit the actual finite history-span comparison obtained from the joint law and verify the categorical endpoints.

**Already available / new work.** O4 supplies service syntax/semantics and O5 supplies finite coupling-to-history lifting. The contextual equality/cost result is **not an immediate O5 local simulation corollary**: at a fixed eager table f and lazy cache lacking a, eager output δ[f(a)] cannot be coupled to a nondegenerate uniform fresh answer with equality. A distributional invariant and whole-budget argument are genuine additional obligations. Do not assume an intensional cache inspection operation or an observer that branches on the external accounting cost. Handle early stopping explicitly. Whole-run comparison does not imply per-method cost domination.

**Boundary.** This is information-theoretic finite uniform sampling, not cryptography or an infinite random oracle. Existing sample-once-table versus stored-table implementation is not enough: lazy generation and resource accounting are essential.
