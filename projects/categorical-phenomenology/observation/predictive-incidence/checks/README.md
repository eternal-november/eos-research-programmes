# Exact bridge checks

Run from the enclosing deliverable directory with Python 3.10 or later:

```sh
python3 checks/run_checks.py --verify checks/results.json
python3 -O checks/run_checks.py --verify checks/results.json
```

The standard library is sufficient. No floating-point arithmetic, random data,
network access or external packages are used. Every condition remains enabled
under `python -O`. The runner recomputes the results and compares the entire
deterministic JSON snapshot byte-for-byte. It excludes timestamps and runtime
details. Running without an option prints the result. Regenerate an intentionally
changed snapshot using `--write checks/results.json`.

## Threshold-transition model

The existing row i has response 1[i≥j] for tests j=1,...,n+1. The constant-true
test j=1 and constant-false test j=n+1 are explicitly supplied. The latter is
essential: the empty support is not generated by intersections of nonempty
upper tails. The unknown transition is an arbitrary function δ:[n]→[n]. An
additional primitive query (i,j), 2≤j≤n, returns 1[δ(i)≥j]. The state bound and
existing incidence table are inputs, not empirical conclusions of these checks.

Rows in machine-readable logs are zero-based. Threshold values and transition
values keep the paper's labels 1,...,n. Query counts charge each distinct added
primitive call once. No query at a known constant threshold is charged or made.

### Exhaustive adaptive testing

Every function [n]→[n] is checked for n=1,...,6: 50,069 functions in total.
The adaptive tester uses only oracle responses. Each completed row's value is
verified exactly. A successful transcript forces every compatible transition
to be monotone. A failed transcript forces a specific adjacent inversion.
Every preimage of every old threshold support is independently checked against
the upper-tail closure.

Maximum added query counts found by exhaustive enumeration:

| n | Adaptive | Independent binary recovery | Full added table |
|---|---:|---:|---:|
| 1 | 0 | 0 | 0 |
| 2 | 2 | 2 | 2 |
| 3 | 6 | 6 | 6 |
| 4 | 9 | 8 | 12 |
| 5 | 12 | 15 | 20 |
| 6 | 15 | 18 | 30 |

The stated bound 3n−2 passes. The observed n≥3 maxima are 3n−3; finite checks do
not prove this sharper formula. Independent binary recovery here uses ordinary
per-row midpoint search. This comparison is not a claim that the adaptive
algorithm is query-optimal, or uniformly better at every finite n. In
particular, the binary-recovery maximum is smaller when n=4.

### Interval criteria and minimum certificates

Every product of nonempty intervals [L_i,U_i] is checked through n=4. Every
compatible function is enumerated, independently of the proposed criteria:

- All compatible functions are monotone iff U_i≤L_(i+1) at every adjacent pair.
- Some compatible function is monotone iff L_i≤U_j for every i<j.

At n=3 and n=4, every subset of primitive queries is enumerated for each
interior constant transition δ≡c. The minimum monotonicity certificate has
2n−2 queries. For every individually necessary query, the snapshot supplies a
nonmonotone alternative that changes only that query's response.

The separate positive-ambiguity construction is checked for k=1,...,8, n=2k.
Exactly 3k−2 queries leave intervals [2i−1,2i] in the first k rows and fix the
remaining rows at n. All 2^k compatible transitions are enumerated and are
monotone. They give identical acquired responses; exactly k additional
threshold probes distinguish and recover every one of them. This records an
accepting certificate with substantial remaining predictor ambiguity, unlike
the scanning tester's accepting runs, which recover every transition value.

The absent-empty-support variant is also tested for every enumerated function:
preservation of only the nonempty tails is equivalent to monotonicity **and**
δ(n)=n. Constant δ≡1 is an explicit counterexample to a monotonicity-only claim
for each n=2,...,6.

## Partial incidence columns and closure

Subsets of the n labelled objects are represented by bit masks. A context is a
family of distinct column supports; repeating an identical attribute would not
change these closure questions. All such contexts are enumerated for n≤3.
For n=4, all contexts with at most three distinct columns are enumerated.

For each context, every partial column with positive P, negative N, and
unqueried entries is checked against every completed column. A closed
completion exists exactly when cl(P)∩N is empty; when it exists, cl(P) itself
is a compatible minimum closed completion. This covers 63,525 partial columns
and 195,088 partial-column/completion pairs.

The certainty criterion is also checked against every completion: all
completions are closed iff U=H\N and every U\{u} for u∈U\P are closed.

For every fully specified new column A, the update identity
C_new = C_old ∪ {C∩A : C∈C_old} is checked. The increase in predictive row
classes equals the number of old row classes split by A, and the number of new
extents is at least that split count. A recorded example has already-separated
rows, no row split, and an enlarged extent family.

Every literal attribute restriction of those contexts is checked directly:
injectivity of restriction on the intent family, equality of the extent closure,
and retention of every proper meet-irreducible support agree. There are 11,644
such restrictions in the enumeration.

## Dynamic saturation and independent permutation examples

Finite dynamic saturation is checked for every unary transition and output
set on n≤4 objects, and every pair of transitions and output set on n=2 objects.
For each machine, all retained support families containing the empty-word
support are checked. All generator preimages belong to the retained closure
exactly when that closure equals the ideal support closure. This covers 13,512
retained families. Tests here range over distinct ideal supports, which is
sufficient for the closure property, rather than infinitely many words with
duplicate supports.

An independent bit-mask implementation checks the cycle/transposition examples
at n=2,4,8, including the full support orbit, meet-irreducibles, separating rows,
and reconstructed transitions. It agrees with the separate
`../check_alternative.py` results. Exact query and execution accounting is:

| n | Separating tests | Observed extents | Ideal extents | Required retained supports | Distinct reset queries | Total letters | Longest query |
|---|---:|---:|---:|---:|---:|---:|---:|
| 2 | 1 | 2 | 4 | 2 | 5 | 6 | 2 |
| 4 | 2 | 4 | 12 | 6 | 15 | 49 | 6 |
| 8 | 3 | 8 | 164 | 70 | 51 | 539 | 20 |

The exact suffixes and reset-query words are included in `results.json`.
These are certificates for supplied state covers and the particular discovered
suffixes. They do not include the cost of discovering them or certifying a
state bound. Logical generation of unmeasured supports is not counted as a
physical observation.

## Scope

These bounded exact checks support the examples and catch convention errors.
They do not prove the general theorems, empirical promises, asymptotic bounds,
or any novelty claim. The mathematical arguments and prior-art audit remain
separate. No finite experiment list here is claimed to establish the input
state bound or exhaustiveness without an external promise.
