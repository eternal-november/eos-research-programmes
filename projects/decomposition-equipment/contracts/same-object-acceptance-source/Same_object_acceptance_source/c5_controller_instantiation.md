## 3. Representative circuit: actual functions and source annotation

The representative has independent named fair events U0,...,Un. Conditional on their joint value x in X=B^(n+1), initialize r0=U0 and process the earlier seven-step two-update tile. The product source preparation μ_X has weight 2^(-(n+1)) at each x. This is a mathematical description of the local product of the already licensed one-bit sources, not a centralized global table or an additional device able to inspect every source value. The old compiler explicitly conditions on an external joint source value; the witness store restricts each stage to its locally exposed coordinate.

For one tile, input parity a and source-port coordinates u,v are retained. With slots s,t for held source/current mailbox, b,c for accumulator outputs, the seven chronological functions are:

1. `expose_u`: set s=u and emit the labelled zi value; all other live wires unchanged.
2. `deliver_u`: set t=s through the named source-to-XOR delivery/copy and retain its event identity.
3. `xor_1`: set b=a+t, emit the labelled r_i value; make b available at the single authorized parity handoff slot.
4. `expose_v`: set s=v under the second source-event ID and emit z_(i+1).
5. `deliver_v`: set t=s through the second named delivery/copy.
6. `xor_2`: set c=b+t and emit r_(i+1).
7. `seam`: deliver c to the next tile's input register, or to the terminal-copy register.

These are explicit finite functions on the available-wire bundles. Readiness flags check the specified preconditions; unused source coordinates/side values and emitted output records are retained where needed. Initialization (`expose_U0`, initial delivery) and final copy to d are additional actual stages, so the whole representative path has s_rep=7m+3 stages for n=2m. The two ownership charts annotate the SAME common elementary witness path; differing internal/external copies do not change the path values or erase ticks.

The imported local license check has already shown that each exposure is from its named representative source port, each delivery has its authorized sender/receiver, b is not independently redrawn, and one tile's outgoing parity is precisely the next incoming parity. Induction gives

    r_i=U0+sum_(j<=i)Uj, zi=Ui, d=rn.

Reading the completed captured-record output therefore gives the existing bijection g:X->V. Composing with μ_X gives uniform V; it does not give the actual source law for every S in K_phys. The external output record can be collected for proof/readout without becoming a controller-readable global state. Its material storage, if requested, is separately charged.

## 4. Actual physical controller: separate terms and pointwise meaning

Now discard the representative source preparation entirely. Initial early bits are actual physical captures x=(r0,z1,...,zn), available according to the checked sensor schedule. They may have ANY joint law allowed by K_phys. Write p_i for controller registers; they are not the environmental intermediate captures r_i.

The physical-controller tile is a three-stage path with input (a,u,v)=(p_(i-1),zi,z_(i+1)). Its finite value functions, suppressing unchanged side wires and attached event/permission records, are exactly:

**Column path**

    c1: B^3 -> B^2,  c1(a,u,v)=(a+u,v),
    c2: B^2 -> B^2,  c2(b,v)=(b,v),
    c3: B^2 -> B,    c3(b,v)=b+v.

c1 is the first owner's XOR; c2 is the licensed one-bit handoff to the second owner, NOT an absent action; c3 is the second XOR. zi and z_(i+1) stay at their permitted input owners until used.

**Row path**

    r1: B^3 -> B^3,  r1(a,u,v)=(a,u,v),
    r2: B^3 -> B^2,  r2(a,u,v)=(a+u,v),
    r3: B^2 -> B,    r3(b,v)=b+v.

r1 is the actual authorized two-bit sensor-to-accumulator delivery; r2,r3 are the two accumulator operations. The identity value function of r1 does not make its delivery permission or time free. These are carrier-level formulas; the full arrows include the updated available-slot/phase records and unchanged side wires.

Both composites are h(a,u,v)=a+u+v. This is pointwise equality for all eight triples, with no probability premise. Intertile parity sends and the initialization/gate stages give a full actual schedule. Induction over the tile sequence gives p_n=r0+sum_i zi for every actual early stream. Compilation does not synthesize new observations of environmental r_i or d.

The earlier matched unit-latency fixture remains exactly as proved: one capture-availability tick, three ticks per tile, one intertile seam tick, one final gate tick, total 2n+1. ## 8. Cost and representation: interpretation is not a hidden runtime demand

This application is mathematical certificate interpretation. It neither changes physical service execution nor adds a necessary probabilistic experiment. The shipped normalized compiler's 445n+597 operation count is untouched and is NOT claimed to include C5 syntax generation, a full K′ table, or normalization.

An optional executable C5 exporter can stream the already fixed stage list, emit its singleton/group partition, increasing index maps, arrow descriptors and right-comb syntax. There are s identity leaves and s-1 binary constructors for s>0. Contiguous interval labels can be stored as endpoints, and tail composites as shared DAG pointers, rather than copying every suffix. Each stage descriptor references its fixed local function and explicit side-wire map; this gives a finite compact expression representation, subject to a separately checked descriptor interpreter. Its parsing, symbol checks, node allocation, graph/permission access and witness-store retention costs must be measured/certified and added as C_C5 if the exporter/checker is actually run.

This is not a claim that all of K′ is cheaply tabulated. A live wire bundle can have exponentially many valuations, and K′ contains all functions between its selected carriers. If the original implementation insists on explicit tables, charge their actual total sizes (at least sum_j |A_(j-1)| log2|A_j| for the selected full stage tables, plus any requested category/composition tables), as well as the graph representation. Those tables can be prohibitive. The finite theoretical construction remains valid, but timely certifiability under that implementation may fail. No local-factorization efficiency advantage follows.

Likewise, retaining a conditional external source tuple as a semantic finite product is not a new permitted global internal sampler, and a full emitted proof trace is not free runtime memory. The earlier local mechanism/capture/communication bounds are the operational implementation; the finite category is a semantic carrier construction. This distinction is necessary to avoid a global history table disguised as locality.
