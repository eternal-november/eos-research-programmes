# Executable stopping interface built from the released learned predictor

## Plain-language abstract

This example takes the already learned twelve-channel environment model and gives three of its predicted readouts a declared physical meaning: sensing delay, command delay, and braking strength during one maneuver. A small controller chooses a speed using its actual action history and a timestamped clearance measurement. It never sees the future delay or braking outcome. Its local clock eventually commands braking even when a remote stop message is lost.

The important positive result is conditional, but concrete. Knowing the relevant action history permits a higher speed while every admitted outcome stops before a protected boundary. Forgetting an older action can instead certify motion whose modeled collision probability is about 25%. A second example uses learned joint probabilities to permit extra speed at a much weaker, approximately 9.2% risk bound. That number is not remotely a deployable collision-safety target; it demonstrates the statistical-to-physical interface, not practical robotic assurance.

The controller runs as bounded-memory integer C code and agrees with an independently implemented tick simulator on 28,800 decisions. The physical calibration and timing contract are stipulated for this synthetic model. No robot, sensor, actuator, or real-time hardware was validated.

## 1. What is reused and what is added

The input is the released `reusable_environment_discovery_20261029/examples/runs/n12/executable_candidate.json`, SHA256 `c00be728d116c33f393570ef81816c359a82b32e94dc36931663cf84190657af`. Its learned response functions and joint innovation block[0,5,10] are reused without retraining or selecting new samples. Three learned response channels determine this task. Their response functions depend on current action ports[7,3,5] and capped run memories on ports[1,4,6,8,10]. The response catalogue discovers those dependencies; the physical interpretation of the three chosen response channels is supplied.

A trial is ONE prediction step, not one step per10 ms physical tick. The random output describes complete post-maneuver telemetry. Its values are unknown when the controller commits. The simulator chooses an output once and retains it for the entire maneuver. It does not redraw braking or switch worlds halfway through execution.

**Additional essential premise:** the existing binary action/readout law remains valid under the added speed command and physical execution protocol. In this synthetic plant the added mechanics do not feed back into the source generator. Real braking can depend on speed, load, surface, temperature and battery condition; then these must be conditioned on, calibrated, or included in the learned action interface. The existing all-feedback theorem does not certify new physical action semantics automatically. The favorable history is an observed supplied context; the example does not prove that executing actions to create it is physically safe.

## 2. Physical units and schedule

Distances are integer micrometres; speeds are millimetres/second; control ticks are10 ms. The calibrated static boundary measurement is1280 mm, with10 mm maximum error and10 mm strictly protected reserve, leaving1260 mm for motion. The initial vehicle is stationary. The clearance packet must have the correct authority, not be future-dated, and be no older than 100 ms. A stale/missing/invalid packet, absent rest-since-capture certificate, or unknown action history causes no launch. The packet API includes the rest-since-capture certificate as a separate externally justified predicate; merely being stationary now is not sufficient. Stationarity and a static boundary mean packet age does not consume distance in this particular initial condition. A moving vehicle or approaching obstacle needs an additional age-dependent travel subtraction.

The declared telemetry-to-physics map, with clipping, is:

- sensing delay = clip(150+50Y0,0,1000)ms;
- command network delay = clip(150+50Y5,0,1000)ms;
- braking deceleration = clip(2500+500Y10,500,5000)mm/s².

These are deliberately explicit **synthetic calibration assumptions**, not properties learned from physical measurements. No claim is made that the old synthetic data already measured a real braking device.

For chosen speed v, the vehicle ramps from rest at 1000 mm/s². The nominal ramp takes v milliseconds and traverses v²/2 micrometres. The nominal cruise lasts 100 ms after that scheduled ramp endpoint, then reaches the stop-sample checkpoint. The sensor response takes its realized delay; computation consumes a budgeted 10 ms; the remote stop packet takes its realized network delay. Independently, the hard watchdog lease expires 310 ms after the scheduled ramp endpoint, making the local brake request eligible. A late acknowledgement never restarts that timer. The sample request is latched at or after its scheduled time; it is not a single equality-triggered pulse that can be missed. Nominal computation takes 10 ms. All additional timing overhead has one shared 10 ms end-to-end budget: sample-request dispatch lateness, acknowledgement dispatch lateness, watchdog scheduling lateness, and physical brake engagement delay sum to at most 10 ms. These are not four independent 10 ms allowances. Periodic polling that can add 10 ms plus an actuator that separately takes 10 ms does not satisfy the premise. The code does not measure or prove this hardware timing contract. `check_timing_budget.py` exhausts integer allocations, including nonzero lateness at all four stages, and verifies the mechanical engagement envelope. This is NOT 10 ms after an arbitrarily late software tick. Thus the brake onset bound, relative to ramp completion, is

    min(100 + sensing_delay + 10 + network_delay, 310) + 10 ms.

A guaranteed local braking path and its included physical actuation deadline are assumptions. Missing the hardware deadline invalidates this contract. The C execution is not a WCET proof for a target processor.

The simulator integrates velocity by the trapezoid rule each10 ms tick. Braking decrements speed byb/100 per tick, saturating at zero. For the final fractional stopping tick this is conservative compared with constant decelerationb stopping earlier within the tick. Its integer closed form is independently used in C. The computed stopping envelope violates the protected boundary when its accumulated upper travel reaches or exceeds the conservative clearance. The simulator field named `collision` records this conservative violation; it need not be a true collision for every lower-travel physical trajectory. `check_physical_envelope.py` separately checks the tick envelope against exact rational constant-deceleration stopping distances. The exhibited adverse 1000 mm/s trajectory has no rounding gap and is an actual collision in the exact synthetic plant. No claim covers a pedestrian entering after launch, collision from another direction, loss of braking authority, or infinite-horizon operation.

## 3. Exact-support assurance and stringent risk budgets

Conditional on the previously certified exact mean-response event and the declared residual alphabet, every possible relevant residual triple lies in{-1,+1}³. Checking all eight possible physical outcomes can therefore give physical-risk bound 0, without paying a probability-estimation TV error. This is a support argument, not an empirical observation of zero failures. The C and Python implementations separately track whether any structural outcome is unsafe; zero empirical frequency of an unsafe outcome does not activate the hard-support branch. A negative unit test checks this distinction at the stringent risk budget.

At 1260 mm clearance, current actions all−1 and all retained run counters zero,900 mm/s is support-safe;1000 mm/s is not. When action port10 has had two consecutive+1 actions before the same current all−1 action,1100 mm/s is support-safe: its worst stopping distance is 1259.5 mm. Only 0.5 mm remains beyond the already subtracted 10 mm reserve: the demonstration tolerates no additional unbudgeted delay or calibration error. This passes operational risk budgets10^-3,10^-4, and0 conditional on the physical/model premises. It does not turn a99%-level statistical identification confidence statement into unconditional10^-4 real-world reliability.

Across all task-relevant memory states with these same current actions, the conservative physical support reaches minimum braking500 mm/s² and the watchdog deadline. A memory-blind guarantee therefore permits only 800 mm/s on the tested speed grid. The learned contextual support permits 900 or1100 in the displayed contexts. A direct supplied whole model with the same history distinction would give the same result; the benefit is finding and executing the appropriate finite history interface, not a unique way to prove stopping safety.

## 4. Nonzero-risk demonstration and fair comparisons

In the zero-run context, the selected1000 mm/s trajectory collides only for residual(+,+,−), whose empirical joint mass is10277/131072. The previous H=1 transcript-TV bound is at most13247/1,000,000, outward-rounded and checked by squaring. The resulting upper risk is approximately0.0916543, which is below the deliberately loose illustration budget0.1. A robust support-based guardian under the same fixed schedule permits 900 mm/s. Even a worst-outcome guardian randomized over this speed grid at risk 0.1 has expected requested speed at most930 mm/s: all speeds above 900 fail in the same adverse row, so their total probability is at most0.1, and the largest speed is1200. This is a comparison of requested speed, not throughput.

Multiplying the *learned marginal frequencies* instead of retaining their common event predicts approximately0.124706, rejecting1000. The fair-independent idealization is1/8. In this case dependence enables a less conservative decision; it is not an independence-underestimation counterexample. A direct full three-readout joint table gives exactly the same risk as the decomposition. Decomposition's added value is the learned task scope, recursively maintained history and reusable common-source interface; it does not create a new safety advantage over identical full joint information.

**Controller-class limit:** these speed comparisons fix the specified ramp/cruise-checkpoint/watchdog-stop protocol. An earlier planned stop may improve safety under a different task specification. The example does not prove global optimality over every controller, nor does maximizing requested speed alone establish useful task completion. In the exact synthetic plant the commanded ramp is attained; real achieved progress additionally needs tracking guarantees.

## 5. Negative tests

- **Missing fourth history bit:** at 537 mm clearance, histories of port10 `[-,+,+,+]` and `[+,+,+,+]` have identical last three actions. The correct run states are3 and4. At700 mm/s their modeled collision probabilities are respectively32721/131072≈0.249641 and10277/131072≈0.078407. The risk 0.1 controller must refuse the first and may admit the second. Replacing the first by the second state creates false assurance. A causal replay reconstructs these run states from actions; they are not simulator mode inputs.
- **Ignored10 ms computation:** in the all-zero-run context the adverse1000 mm/s trajectory travels1310 mm if computation is wrongly omitted, but1320 mm in the timed model. At 1315 mm clearance the untimed guard falsely accepts the geometry.
- **Missing stop packet:** watchdog braking still occurs, but it does not guarantee the already risk-qualified trajectory is safe. Some weak-brake realizations collide under timeout. Any such packet loss outside the certified source family needs its own probability budget or a support-safe admission rule. It cannot be declared a free, universally safe fallback. In contrast, the warm-history 1100 mm/s exact-support branch remains safe under a lost acknowledgement: every calibrated braking outcome stops by 1259.5 mm even when braking waits for the watchdog. This robustness assumes loss does not invalidate the calibrated braking lower bound. The checker also supplies an uncalibrated weaker-brake counterexample; unknown physical brake failure is not covered. The soft statistical claim must exclude unmodeled loss as a calibration premise or separately charge its probability; the existence of a watchdog does not establish a packet-loss distribution.
- **Unknown history/stale initial observation:** no launch. During a launched maneuver the controller cannot revoke already traveled distance by switching to a rejection state.
- **Wrong authority/stale maneuver sequence:** ignored by the local executor. Brake is latched after a valid stop or watchdog expiry.

## 6. Implementation and verification

`controller.c` uses12 bytes of capped history, integer physical calculations, eight joint outcomes per speed, and at most48 outcome evaluations per admission. Probability comparisons use integer cross-multiplication with the outward rational TV bound. The compiled task cone uses only five memory counters, while twelve are retained for simple compatibility with the source interface. A future minimization can remove the unused counters; no such saving is claimed here.

`check_c_controller.py` compares all 600 relevant memory states ×8 relevant current action choices ×3 clearances, totaling 14,400 decisions per budget, repeated at risk 0.1 and10^-4 (28,800 decisions total), against the tick simulator. It also checks recursive state updates. The C executor tests all six nonzero speeds and four sensing/network delay combinations, plus wrong authority, stale sequence, timeout and latched braking. Host compilation uses warnings-as-errors and undefined-behavior sanitizer. These establish reproducible reference-code behavior, not embedded timing, actuator calibration, or hardware safety certification.

## Reproduction

Run `bash examples/run_checks.sh` from the milestone directory. Python standard library and a C11 compiler are sufficient. The frozen learned candidate is included in `examples/inputs/`; the old raw training data are not needed to reproduce this bridge. This does not revalidate the old learning theorem or regenerate its training evidence. Runtime history callbacks must faithfully record the same action ports used by the predictive law; a gap invalidates initialization and requires refusal or reconstruction from four trusted actions before a new launch.
