## Concrete correction requested

Lemma D's one-update local path argument is correct only when the incoming off-path messages used in that query are current. Updating only r-to-q does not recalibrate every directed message. After a subsequent change r2/query q2, a nominally off-path message may still be stale from the earlier change.

Example: a three-leaf star has leaves a,b,c. Update a and query b; a-to-center and center-to-b are refreshed, while center-to-c is stale. A later query c with no new factor update still needs center-to-c recomputation. More generally, a second update on another branch can require incoming messages whose dependency sides contain old, unpropagated changes.

Fix options: state the lemma for one update from a fully calibrated cache; or maintain versions/dirty dependencies and recompute the union of pending dirty-factor paths needed for the query. Charge all needed work, including possible global work. Arbitrary repeated updates cannot inherit the displayed single-path cost without this invariant. This is a recoverable implementation/theorem-accounting issue, not rejection of the approach.
