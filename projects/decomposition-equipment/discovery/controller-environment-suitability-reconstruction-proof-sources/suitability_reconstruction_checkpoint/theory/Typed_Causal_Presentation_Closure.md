# Resource-sensitive causal realization of a typed decomposition presentation

## Frozen scope

This theorem concerns a FINITE specified hardware architecture, finite state/event charts, and the original typed decomposition syntax. Source expressions and execution histories can be arbitrarily long. Memory, ports, permissible primitive operations, and observation timing are explicit inputs, not freely increased by the proof. The memory budget includes driver state, private stores and protocol-phase storage unless an external phase/clock interface is explicitly supplied. A phase label in the semantic graph does not by itself grant the controller that clock. The result checks an installed controller when its tables are fixed, or synthesizes within the specified finite table libraries when they are variables. It does not solve unrestricted distributed synthesis.

The structural completion construction supplies a nonempty finite family Omega of persistent PHYSICAL environment realizations from the charts and a finite fibre D(omega) of candidate mathematical decomposition witnesses for each world. Pure factorization/coordinate choices are not adversarial environment moves. The purpose here is not another theorem about that enumeration. It is a finite-generator recognition theorem for ONE causal controller realization that works across that family and remains coherent under every generated typed refinement and declared crossing comparison. Its finite constraints include shared implementations, actual readout timing, and resource bounds. Ordinary graph exactness is insufficient.

The core mechanisms are finite-state realization, commuting update diagrams and induction on generated operations. They are not individually new. The intended contribution is their explicit, two-sided, resource-sensitive realization in the existing witnessed decomposition presentation, together with necessary obstructions that its prior graph semantics alone cannot express.

## 1. Operational data are generated, not inferred from a completed trace

For each component color c, give a finite open staged environment graph W_c. A decision state x exposes ONLY the declared pre-action observation b_c(x). A physical request a is then selected; an adversarial record e with source x and request label req_c(e)=a produces its declared reply y_c(e) and target t(e). The event can carry hidden fields needed for cross-component matching; those fields are not part of b or y unless an actual sensor operation delivers them. Terminal states and a terminal request/answer alphabet are separately declared. Local idle records permit a component not currently acting to remain in the same state.

These tables arise by assembling supplied request/reply generators: sensing, actuator command, environment choice, and memory commit have distinct roles. Shared ports identify the SAME actual record field. A request generator precedes the response generator that answers it; a memory commit reads only its permitted old memory and delivered response. Serial assembly respects those phase ports. Parallel assembly joins only named shared ports. Thus a source generator's operational tables can be computed from its local primitive tables by finite tuple formation, rather than assigning choice ownership to an already completed graph afterwards.

A declaration that rearranges spatial coordinates is not permission to reorder the physical request/reply clock. An attempted assembly that connects a response to an earlier request input is rejected by the protocol phase/type check. Any actual feedback goes through an explicit state/memory boundary; no instantaneous fixed-point solver is inserted.

Environment decomposition boundaries, controller register boundaries, and physical request/reply coupling interfaces are distinct. For example a clock boundary J, a register boundary I, and an observation interface O need not factor through one another. Supply the actual maps to O and require their generator/cut squares to commute; do not assume observations factor through J. Paired environment/controller signatures use an explicitly supplied common occurrence schema or occurrence correspondence, rather than identifying unlike boundary objects. The coupled graph maps below are induced only after those separate coupling squares pass.

Let S be a finite original signature with actual dynamic generator maps

  w_g: W_c -> P(W_c1,...,W_ck).

Keep the original ordered occurrences, boundary graphs, nullary convention, and declared equations. Exact generators have bijective state and event maps. A finite set of additional crossing comparisons is supplied as explicit arrows between specified profile diagrams: each arrow has its named occurrence transport, its state/event maps on compatible tuples, and its boundary maps. The finite relations are pairs of parallel composites of these arrows and original substitution maps, with identical source/target diagrams. Their supplied equations are checked on actual state/event records. This is a generated diagram category, not an assertion that all semantic crossings exist, and not an undeclared symmetry of the planar calculus. Interface-change generators, if included, carry their actual maps and their permitted observations; they receive the same causal tests below.

The staged construction does not make every old graph-span generator operationally admissible. The new conditions recognize the admissible subfamily and give counterexamples when graph refinement would require unavailable information.

## 2. A physical controller architecture and finite unknowns

For each physical memory component j specify a finite carrier M_j (or an explicit finite bound), its owner, and which ports can read/write it. A memory occurring in several charts is ONE physical component, not independent copies. The root memory carrier is the actual compatible tuple of these physical stores and their shared boundary stores. Local component memories M_c are their specified views or candidate bounded implementations.

A physical primitive identifier tau has ONE selected table from a finite allowed library. Its input port tuple contains exactly its permitted old memory, pre-action observations, request and delivered reply fields. Private ports are not automatically visible to a central coordinator. An idle update is identity. A table candidate whose implementation would read another private port is absent from the library even if an abstract finite function with the desired behavior exists.

For each color c the assembled controller has action and update maps

  alpha_c: M_c x B_c -> A_c,
  delta_c: M_c x B_c x A_c x Y_c -> M_c.

These maps MUST be computed by evaluating the selected typed select/decode/commit primitive tables along the specified finite, phase-respecting wiring diagram. They are not independent unknown functions and are not selected afresh in each chart. Evaluation orders the primitive nodes by the declared request/reply/memory phases, feeds each port its actual permitted predecessor value, and reads the designated root request and commit ports. Shared primitive identifiers use the same table during every evaluation. An unavailable input or instantaneous dependency cycle rejects the candidate. Thus a solution constructs the physical program, not merely a root action table coinciding accidentally with local behavior. If the architecture contains private local sensors, alpha_c/delta_c denote the global semantic tuple of local outputs, while each coordinate is still computed only by its owner's permitted primitives. Giving this semantic tuple does not create a runtime central observer.

For a primitive decomposition g, candidate memory representation maps

  eta_g: M_c -> P(M_c1,...,M_ck)

come from the declared finite architecture interface language. They must respect owners, aliasing of the SAME shared store, and memory boundary maps. They are not arbitrary lookups that could introduce an undeclared communication channel. A representation map is semantic bookkeeping when it merely projects actual distributed stores; any map requiring new runtime computation must have a permitted implementation. Marked exact memory refinements require bijectivity to the specified compatible-memory tuple.

For each persistent physical environment completion omega, the environment graphs may vary and each d in D(omega) supplies its candidate w_g maps. Interpret the conditions below separately for a selected coherent d_omega, or on the disjoint union of physical worlds retaining omega. All physical controller tables, stores and implemented eta maps are chosen ONCE, before omega, and may not depend on that hidden coordinate. Pure coordinate identifications in the mathematical witness may vary with omega, but may not be used as runtime operations. A semantic memory projection that is merely notation must be distinguished from an implemented adapter. Environment completions that mismatch an action interface are failing cases, not removed from the universally quantified set.

## 3. Deriving the finite elementary constraints

The coupled controller/environment graph K_c has states (x,m). A state has a defined action a=alpha_c(m,b_c(x)); its actual events are pairs (e,m) with s(e)=x and req_c(e)=a. Their target is

  (t(e), delta_c(m,b_c(x),a,y_c(e))).

An undefined action, unavailable command, or nonterminal state with no event is blocking failure. Distinct adverse e remain distinct, even when they share endpoints/replies. The controller never chooses e.

A support R_c subset W_c.states x M_c records possible coupled states. It need not factor into separate environment and memory marginals. Initial states for EVERY omega must be included, and R must be closed under EVERY coupled adverse record. Composite supports retain that same omega through every block; they never choose fresh world matchings independently in different leaves or at later times. For fixed chosen tables, the least such support is computable by reachability. More general supplied inductive supports can be used, but cannot omit reachable states.

The following tests are finite, evaluated on these actual states and records.

(A) Universal action/task test. At each reachable (x,m), the assembled command is admitted and satisfies the specified local command constraints. Objective predicates are tested at the root/task-monitor positions where they are declared; a projected component is not assigned an extra local safety or termination obligation merely because it occurs in a decomposition. At a stopping state the same output table must choose an action from the intersection of demanded action sets over all actual states with its identical available code/input. An empty intersection is a failure certificate. Mere pairwise compatibility is insufficient for general action sets.

(B) State representation test. For each g and every (x,m) in R_c, the tuple

  (w_g^0(x)_i, eta_g(m)_i)_i

has the prescribed matching state boundaries and lies in the corresponding local supports. No substitution of independently chosen memory codes is allowed.

(C) Command assembly and selection test. The decomposition comes with the actual permitted output wiring compile_g from its component request-port tuples and declared shared ports to the root request ports. Evaluate that wiring on the selected local controller outputs and require that it is defined and equals the root request computed by the SAME primitive-table program. This finite command-assembly equation prevents independent selection of a convenient root command with no local implementation. A compilation node may use only ports present in the supplied hardware diagram. Then, at such a state, every actual root event e selected by alpha_c projects to events w_g^1(e)_i selected by their corresponding local action tables, with idle factors treated by their stated protocol. This forward implication gives simulation. The reverse direction for relative exact reconstruction is checked ONLY on the specified retained joint selected-event relation by (F). An unselected root event may project to a locally selected tuple outside that relation; relative exactness does not forbid this. Do not impose an unconditional selection iff on all ambient events. In the ordinary full-product exact branch the bijection of complete selected-event targets in (F) provides the required converse. This is a test on actual request fields, NOT an assumption that all strategies descend.

(D) Update cube. For every selected root record e and every coordinate i,

  eta_g(delta_c(m,b_c(x),req_c(e),y_c(e)))_i
    = delta_ci(eta_g(m)_i, b_ci(w_g^0(x)_i),
               req_ci(w_g^1(e)_i), y_ci(w_g^1(e)_i)).

This tests whether the SAME permitted memory update can accompany the actual decomposition record. The right side must use only the local inputs delivered by the actual request/reply primitives. A completed event's hidden bit cannot be substituted for an absent reply. Include unchanged boundary-memory equations as well. For k=0, eta_g takes values in the memory boundary, not a singleton; the cube is the actual boundary update equation.

(E) Shared occurrence/crossing test. Every repeated physical primitive uses its ONE selected table. Interpret both sides of each declared parallel equation and crossing comparison on the bounded memory carriers using eta and the named occurrence transports, and require equality on the actual reachable support. If a claim is made about the whole typed memory calculus rather than only the reachable controller, require equality on the full stated carriers. Do not silently switch these scopes. Corresponding environment equations are already checked on actual records. In the relative-exact branch, compare the retained joint target relations as well as the maps under the named occurrence transport. For composite crossings those target relations are the recursively generated supports defined in the proof, not independently guessed marginal joins. A separately supplied refined target must pass equality with that generated support before it inherits exactness.

(F) Exact reconstruction test, when requested. The combined state map (w_g^0,eta_g) and combined selected-event map induced by (w_g^1,eta_g) are bijective between the prescribed root support and the specified compatible local support relation. The latter is a JOINT relation supplied by the actual crossing witnesses, not the natural join of independent marginal supports unless equality with that join has separately passed. These bijections are tested explicitly. For nonexact generators retain the forward simulation without falsely claiming reverse reconstruction.

All six tests are finite checks on actual tables, masks, equalities, and bijections. Their variables are the bounded controller implementation and resource-respecting memory representations. They do not quantify over unbounded histories or ask an oracle whether a global causal strategy exists.

For guaranteed termination in the finite model, use the ROOT coupled graph with the actual task monitor, stopped at its first declared successful stopping state. Require that every reachable nonstopping root state has an admitted transition and that its reachable nonstopping graph has no directed cycle. Projected local idle loops are not independently treated as failure when the root protocol progresses. Equivalently supply a strictly decreasing rank on its nonstopping transitions. For safety only, no termination claim follows.

## 4. Finite-generator realization theorem

**Theorem.** For the finite architecture and generated presentation just specified, the following are equivalent.

1. There is one permitted controller/runner implementation with the stated memory carriers, shared physical operations and observations, realizing the primitive and generated decomposition diagrams on their actual reachable supports, satisfying the given safety/stopping task for every admitted persistent environment completion and every adverse history. For the exact branch, the specified refined coupled descriptions reconstruct the same actual executions; for the general branch they preserve them forward. The implementation obeys the declared crossing comparisons.
2. There is a single permitted selection of physical controller tables/stores/adapters such that, for EVERY physical omega in Omega, SOME coherent mathematical witness d_omega in D(omega) and support annotation satisfy (A)–(E), plus (F) for every marked exact primitive and the finite termination condition when demanded. This is a finite quantified constraint system: existential physical implementation, universal physical world, existential mathematical witness. It is not an existential search over convenient worlds and not a demand that all arbitrary mathematical factorizations work.

For a prescribed common witness, fix d before omega instead; that is a stronger target. A world with D(omega) empty makes the demanded decomposition-supported realization fail but is not discarded from Omega and is not thereby declared intrinsically unsafe.

Moreover a solution constructs the actual runner, and elementary generator tests certify every finite source tree and refinement forest, with no bound on tree depth or execution length.

**Soundness proof.** Use the globally selected physical tables, stores and wiring to instantiate one runner. Fix an arbitrary physical omega and choose its mathematical witness d_omega supplied by condition 2; this choice occurs in the proof, not in the runner. Its action is selected before the adverse record by construction; all inputs are permitted by the hardware library. Initial coverage and closure show by induction that every execution in every omega remains within R. Test (A) supplies nonblocking/safety and the terminal demand. A strict finite rank, when supplied, gives termination against every adversary; alternatively absence of a nonstopping cycle in the finite reachable graph gives the same conclusion.

For a primitive g, (B) gives the state part of a map on coupled graphs. Test (C) puts every selected event in the local selected-event relation. Test (D) is exactly its target-incidence equation; its source-incidence equation is (B). Thus g induces an ACTUAL graph map on the coupled controller/environment executions, derived from causal tables rather than postulated operational exactness. In the exact branch, (F) gives its inverse on the declared joint support and on actual events.

Substitution composes the state and event maps at each original occurrence. At the next memory commit, composing two update cubes gives the update cube for the composite: substitute the inner equations into the outer equation coordinate by coordinate. The forward command implications compose along the same actual selected events; the reverse selected-event reconstruction uses the retained joint-support inverses below. Empty profiles retain their memory boundary maps; repeated colors retain different occurrence addresses. The original Calc associativity identifies the two flattenings, so both coupled maps and updates coincide. Induction on the original tree proves the statement for every generated operation, and induction on its forest proves it for every semantic refinement built from those generators. For the marked branch, exactness is relative to an explicitly retained joint support; it is NOT automatically exactness onto the whole compatible product in the original Calc. Define the joint support of a substituted operation constructively as follows. A flattened leaf tuple belongs to it precisely when each inserted block belongs to its inner joint support and, after applying each inner inverse, the recovered tuple of parent records belongs to the outer joint support. Retain all typed cut-boundary coordinates during this test. An empty block is tested and inverted using its actual boundary coordinate; when every block is empty, the overall boundary remains. This construction is a subgraph because every primitive joint support and inverse respects incidence.

Each substitution therefore has an explicit inverse: split the leaf tuple by the original occurrence addresses, invert the inner blocks, test the outer relation, and invert the outer map. Both directions are identities by the primitive bijections. At three levels, either bracketing tests the same inner and outer joint constraints and reconstructs the same uniquely determined internal records. Thus the joint-support substitution is associative and its unit is the diagonal singleton support. This proves relative exact reconstruction under every generated tree WITHOUT replacing a correlated support by the natural join of its marginals. Only in the special case that each retained joint support is the entire compatible product may one identify this branch with the original Calc's ordinary exact marking.

Declared equations hold by (E), and substitution of equal coupled maps preserves them. A generated path of crossing comparisons therefore has the stated composite, and any relation generated by the declared crossing equations is respected. This does NOT assert coherence for unlisted semantic crossings. Applying the coupled graph maps at every execution step proves all-history naturality; the memory update induction makes this a causal statement, not just a permutation of completed records. QED soundness.

**Necessity proof.** Take the globally fixed actual finite physical tables, stores and implemented representation maps of the realization. For each physical omega, take its stipulated coherent mathematical witness d_omega; a mere coordinate proof choice is not an adverse environment selection. Let R be the union of states reachable under all admitted omega and all adversaries, retaining omega in the state when necessary. Initial coverage and closure are immediate. The action and terminal requirements give (A). Restrict the realization's representation of every primitive to states and selected events: its source/target equations give (B)–(D), with actual physical input restrictions inherited from its implementation. Shared primitives and declared crossing equality give (E), and actual exact reconstruction gives (F). If every adverse execution terminates, the reachable nonstopping finite graph has no directed cycle: a reachable cycle could be repeated by the adversary. Hence the finite termination test holds. QED necessity.

The necessity direction is relative to realizing the SPECIFIED decomposition/architecture, not to arbitrary controllers that solve the task while ignoring that architecture. The theorem must not be advertised as proving that failure of this architecture means no imaginable robot can operate in the environment.

## 5. Relation to cut encodings and resource optimality

The separate Operational_Cut_Capability theorem derives the actual encoding constraints at cuts from the reconstructed record fibres and continuation demands. Its kernel tests determine when a next cut code is computable from the old code and the delivered readout; tagged-union tests force the SAME physical operation table across multiple charts. Terminal action intersections handle genuinely relational tasks. These are the concrete local forms of (A), (D), and (E), not a replacement of the task by arbitrary commuting tables.

For each fixed finite memory-bound vector, the constraints are finite. Their solution set records actual realizations, not only individual cut chromatic numbers. The feasible resource profiles are those for which the simultaneous system has a solution. Minimal profiles need not be unique, and minimizing each cut independently need not give a realizable profile. Exhaustive finite search decides a supplied bounded profile; no polynomial-time or unbounded architecture search is claimed.

Given candidate cut encodings, an update failure is an explicit pair of actual histories with the same current code and available readout but different required next code. A terminal failure is a code fibre with empty joint demand intersection. A crossing failure is incompatible values forced for the SAME physical memory/table occurrence by distinct charts. An exactness failure is an actual missing/multiple joint state or event preimage. These obstructions distinguish unavailable information, insufficient memory, inconsistent assembly and missing environmental correlation rather than calling all failures 'unsafe'.

A legal spatial refinement that passes the same finite causal constraints preserves the implemented task. A change that moves a cut across a physical observation may change the required memory: it must be retested, not licensed by the underlying completed-record bijection. The interlock family derives this change from actual original-Calc witnesses: block and interleaved observations have the same completed worlds but exponentially different memory requirements.

## 6. Scope and unresolved scientific burden

This theorem makes the finite generator test and its all-generated causal consequence explicit. It does not establish a new general game-solving or automata-minimization mechanism. It also does not automatically provide a small constraint system: actual completion supports and candidate memories can be large. Structural tractability requires additional separator or presentation bounds. A model-relative compatibility theorem is not empirical certification of the robot's environment.

The crossing doctrine is the one generated by the specified operational generators and equations. General semantic crossings, arbitrary virtual-equipment restrictions, and all 2-Segal recognition are not silently discharged. The theorem is a bounded operational enrichment and recognition result, with two-sided controller/environment instantiation, not completion of the original research contract. Adversarial support semantics covers zero-error/all-outcome requirements; stochastic probabilities, expected cost and almost-sure objectives require probability kernels and separate preservation arguments.

## 7. Operational model/comodel/runner connection

The request/reply primitives provide a concrete, restricted connection to the earlier model/comodel motivation. For every request type a there is a declared reply type Y_a. An environment state x determines the actual response relation

  Resp_a(x) subset { (record, reply, next-state) }.

The record is retained even when two replies and next states coincide. Empty response means the request is unavailable or blocks according to the declared protocol. A controller state selects a request using its permitted observation and supplies a continuation/update for each delivered reply. The runner performs the actual request/reply coupling, invoking only its implemented sensing, actuation and memory operations. Persistent hidden physical alignment remains part of the environment response state across requests.

Thus the environment supplies interpretations of effectful requests, while the controller supplies a program using them; a driver may itself use lower-level requests to implement a higher-level request interface. Their roles are relative to the interface, not a permanent label saying that the robot is always the model or always the comodel. The finite wiring and cut-code equations decide whether this proposed implementation actually exists with the allowed memory and information flow.

This is an operational connection, not a proved equivalence with a particular algebraic-effects comodel or runner category. To claim that identification one must specify the effect theory and its equations, show the response interpretation respects them, and prove the corresponding universal property. None is silently imported here. In particular, ordinary nondeterministic response support does not supply probabilities, scheduler assumptions or an observation policy.

The environment semantics is therefore the structured family of available interactions, persistent response correlations, observation timing, and typed decompositions through which they can be realized. Modal properties such as 'a bad reply is possible' or 'this request is always enabled' are induced queries of that structure. They are not substitutes for the retained interaction and implementation witnesses.
