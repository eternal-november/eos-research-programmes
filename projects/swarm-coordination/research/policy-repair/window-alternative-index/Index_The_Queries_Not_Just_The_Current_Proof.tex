\paragraph{What changes.}
A receiver has a live duty with one appointed service cut $d$. The parties cannot execute earlier on a different appointment. Several authorized suppliers may independently certify the same physical effect at that cut. Each named key has an empty or closed integer availability window, a current supplier, and a strictly monotone authority epoch. A window denotes verified ability to supply the named effect at any one admitted cut in the interval. It is not permission to mint a new duty, a promise to serve many simultaneous requests, or a status lamp. Each duty in the model has its own allocation and a separate physical exclusion law. A trusted source at the receiving boundary reports keyed transitions; the measured algorithm maintains the eligibility computation, not that source's detection, authentication, or physical proof.

Receiver $i$ is eligible iff there is an authorized subscribed key $k$ with $d_i\in W_k$. Subscribe unresolved and absent keys too: a role repair can make an absent supplier usable and replace the witness without changing the original duty. A change in lawful alternatives explicitly edits that subscription. Before executing any effect, retrieve the current proof by key and recheck its actual provider, scope and epoch at the responsible gate. We model atomic source/decision cuts. An already issued command in flight needs its own fencing and physical settlement; invalidating a cached ticket cannot undo it. A new epoch with the same window preserves a Boolean choice, not an older concrete authorization.

\paragraph{Kind of maintenance.}
For each key maintain a balanced ordered index of its subscribed $(d_i,i)$, and for each receiver maintain its currently valid keys. A change from $W$ to $W'$ touches only the subscriptions at cuts in $W\triangle W'$. Report the two signed differences by bounded range enumeration; each difference consists of at most two intervals. Each reported pair changes exactly once, and no other pair's truth changes. Key subscription edits insert or remove a point and evaluate that one key. In the unchanged receiver code, a previously empty alternative can now provide a current stamped witness; merely retaining the key whose previous check succeeded would lose it. If one option is removed, a remaining current valid key preserves eligibility. Neither the monitor nor its cost calculation assumes that a previously selected concrete witness is still valid.

Let $N$ be the maximum subscribed receivers per key, $E$ the number of live subscriptions, $M$ the backed key count, $D$ the number of subscription insertions/removals, $S$ the accepted source deltas, and $K$ the sum of predicate crossings on affected key-receiver pairs. Given deltas with source check costs $T_j$, the update bound is
\[
 O\!\left(\sum_j T_j+(S+D)\log(1+N)+K\right)
\]
after the separately charged initialization. The tree prunes all but the range output and its two search boundaries. A current available-key list allows retrieval with one scoped proof fetch, and calls to the gate and proof validation are additional charged demand operations. An explicit per-pair cache needs to change each of its $K$ changed cells; this is not a universal lower bound on compressed representations. The state retains $O(M+E+\#\text{receivers})$ records, not past notifications. Bounded records require a bounded key universe; exact increasing epochs can still grow in bit length. The replay stores current stamps accordingly, not a bounded-round-generation protocol.

\paragraph{Source of the dependency discovery.}
The typed delta is the reason the index knows which key to examine. If it only learns that an update may have happened and must discover the changed keys by reading independent records, on an unchanged replay every unread coordinate could instead have become the decisive change. A zero-error algorithm must read all $M$ in the worst case, assuming such silent changes and the unchanged replay are admitted. If the source certifies the changed key, this lower bound does not apply. Similarly, an authority amendment that invalidates the interpretation of a window has to supply a validated new interpretation; a receipt on the old key alone cannot preserve it. The result thus isolates an actual delivery/provenance obligation rather than charging only a traversal of a free dependency graph.

\paragraph{Comparable controls.}
A direct cached monitor keeps the same authoritative records and valid alternatives, and scans subscriptions to a changed window; it already skips a same-window provider replacement. In the 4,096-subscriber sparse-crossing family, 128 updates change 127 cells. The direct scan visits 520,192 incidences; the index visits 1,524 nodes. Initialization charged 49,153 index update visits and 4,083 rotations instead of 4,096 direct subscription writes (plus common eligibility setup). Dynamic subscription edits are not free either: in the small churn replay the index performs 5,024 update visits and 655 rotations, with 8,147 range visits compared to 8,228 direct incidence visits and 1,620 subscription writes. Counts are separate operations, not a conversion into wall-clock speed-up or overall dominance. Full-state recomputation and tree invariants agree on 216 replay prefixes; exhaustive small windows give 5,887 set checks. The replay includes a previously absent key populated as an old supply is withdrawn, a same-window replacement and a rejected stale stamp.

\href{https://www.cs.cmu.edu/~guyb/papers/ABH06.pdf}{Acar, Blelloch and Harper's change propagation} is the direct reference for maintained read dependencies. \href{https://pmc.ncbi.nlm.nih.gov/articles/PMC9468080/}{LiveLTL} carries unfinished temporal obligations, and \href{https://smlab.cs.tau.ac.il/syntech/dupdate/index.html}{dynamic GR(1) bridges} preserve a changing controller's temporal obligations during transition; neither is a claim about this specific typed window index unless the source interpretation is built. A direct version of this same range optimization ties. The result is a scoped R2 maintenance and source-obstruction result, not a new tree algorithm, validation of a physical bulletin channel, independent held-out proof transfer, or satisfaction of I1.
