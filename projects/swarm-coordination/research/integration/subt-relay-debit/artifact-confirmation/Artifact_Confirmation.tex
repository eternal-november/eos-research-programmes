\title{An Artifact Report Is Not Its Confirmation}
\date{27 November 2026}

\maketitle
\paragraph{Audit.} The selected interfaces supply three separate
facts: a report reached the scorer, the score effect is recorded,
and a qualified confirmation reached the scout. A stock tutorial
callback can clear the scout's obligation without any score effect.
A closed scorer can also return the same visible response on two
histories with different scoring effects. Neither fact is a
statement about a physical rescue or a full cave run.

\paragraph{Pinned comparator.} At SubT commit \texttt{083c6a8acb0c25aa1a35e34517e628cd3b52ae77}, \texttt{GameLogicPlugin.cc} lines 2068--2199 and 2271--2375 distinguish scoring from its result, and \texttt{BaseStationPlugin.cc} lines 58--135 distinguish result creation from dispatch. A valid same-type, same stringified-position submission can be recognized as a duplicate while the run is still open and the normal score path is reached. It returns the stored score delta without awarding points again; \texttt{report\_id} is the current unique-report count rather than the original occurrence identifier. The response echoes the request, so this does not claim all artifact identity disappears. A relay that sends gets the response; the original scout needs an additional forwarding mechanism. The earlier direct Base-to-Scout receipt and its one-tick bound remain authored controls.

\paragraph{A quota cut changes what can be recovered.} Consider serial valid reports of three different artifacts with equal one-point credit, and enough remaining artifacts that the cap or an explicit score threshold is the operative finish. Histories begin with either \(r\) or \(x\), have their respective replies hidden, then perform the same unrelated work \(s\). Arrange the common last submission to finish both runs. Now ask for identical \(r\) again. The finished guard runs before duplicate lookup, so the echoed request, current identical count and finished status no longer answer whether \(r\) previously occurred. In equal timing controls, the stamped return does not resolve that difference either. A retry while active can complete the report now but cannot on its own prove whether it credited the earlier occurrence. If the obligation is to reconstruct an earlier result, retain evidence for that named occurrence before closure or provide a separately justified result lookup that stays valid after closure. Merely preserving radio, increasing a queue buffer or resending the same bytes cannot reconstruct lost membership behind the closed scorer.

\paragraph{A distinct loss before transport.} The reply thread copies the pending map, sends the copy unlocked, then clears the original map. An append committed between copy and clear is absent from the copy and cleared with the original under this interleaving. Split append occurrences into before, inside and after that interval. Every inside occurrence is lost from both the sent list and the next queue; every before or after occurrence is retained on one of the two sides. Atomically detach the map under the mutex and send the detached map afterwards to remove that exact loss mechanism without holding the mutex during network requests. This proposed source repair does not guarantee broker delivery, receipt forwarding, or completion before shutdown. An atomic, retained controlled forwarding record is a separate interface if those guarantees are required.

\paragraph{Verification scope.} A selected source-derived JavaScript transition model checks 1,085 cap/score-threshold state pairs and 210 ordered queue schedules. Lean checks four abstract membership and queue lemmas. The paired report experiment uses recognized valid inputs and assumes no other state-dependent path, distinct artifact keys, and a serial score order. It does not claim all returns are indistinguishable under any telemetry, or that Gazebo executed this schedule. For a timed mission with a genuine artifact, test both stock scoring and the extra relay hop with explicitly controlled serialized queue timing. For a generic receipt that must survive station restart, use the keyed two-store warehouse interface rather than treating process-local score deduplication as durable settlement. Keep the independent cave unspent.

\paragraph{Tutorial comparator, independently read.}
The runnable ROS sample at osrf/subt\_hello\_world commit
\texttt{3c694290d543a12f75b6b5a9b00f30852212f05e}
uses \texttt{report\_relay.cpp} and \texttt{artifact\_reporter\_comms.cpp}.
In the installed relay callback, the \texttt{else if} has an empty
statement as its body; the following block is unconditional.
For a scout's first legitimate artifact, the callback enqueues both
a Base-bound forward and a Scout-bound echo of the original body,
in this order. The tutorial reporter's bound callback clears the
pending flag without inspecting the sender or body. A routine
modeled interruption of only the Base-bound path therefore allows
the outgoing artifact itself to be mistaken for a confirmation.
There is no need for an invalid payload or for a genuine score reply.
This is an effect of the pinned tutorial code, not a claim about
all SubT solutions, production runtime, or any particular deployed
mission.

For one immediate dispatch to each dedicated bound recipient, with
payload size $b>0$, existing live debit $u$, capacity $C$, no expiry
between forwards, and clear receiver budgets, the echo can be
admitted iff $u+2b\le C$. The Base attempt takes $b$ before path
resolution even if that path is down. Thus if the Scout-bound path
works and the Base-bound path doesn't, the bad flag clear is
possible exactly when there is room for both. If $u+b\le C<u+2b$,
the extra echo is blocked by the selected model; that accidental
protection is not confirmation. Only one receiver per forward and
the sourced TX-before-path order are used; surrounding broker queue
and receiver effects are not silently assumed absent in full runs.

Removing the unsolicited echo eliminates this exact source of
confusion but does not fix a delayed receipt for a prior report or
a legitimate reply from scoring after the run finished. In the
authored repair the receiver checks the response kind, named current
request, the qualified accountable sender or forwarding authority,
and a response status that proves the required effect. Body typing
is a modeled new envelope, not a claim that protobuf shapes in the
tutorial are disjoint. The repair can keep an obligation open; it
does not deliver the report, or by itself preserve a route or improve
the strongest typed comparator. The source-derived finite replay
checks 86,480 capacity and path combinations and three response
controls. Lean checks four typing/byte lemmas.

\paragraph{Consequence for the stack.} An artifact deployment needs
a genuine same-occurrence result, possibly preserved before the
score-close transition and later forwarded through a qualified
successor. A stock report ID, a received echo, and a late
\texttt{scoring finished} reply cannot be substituted for that witness.
The strongest typed direct controller can make the same distinction.
No operational gain, completed inventory disposition, or independent
mission acceptance is established.
