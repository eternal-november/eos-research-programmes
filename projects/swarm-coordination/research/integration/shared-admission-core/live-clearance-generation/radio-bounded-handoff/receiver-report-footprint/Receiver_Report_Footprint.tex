\section*{A receiver-budget report can invalidate the budget it reports}
The protected old operation is a keyed warehouse result. Its successor
needs a certified digest of the fenced state before retry. In this
held-in fixture both authorized senders already hold the digest. The
primary uses one radio ingress; the backup uses a distinct ingress
controlled by the same successor, and also has an optional report.
Those authority, provisioning, link and service assumptions are not
assertions about an external deployment.

\paragraph{Pre- and post-observation feasibility.}
Let $C$ be the primary receiver's allowance, $R$ its live spend
before evidence, $M$ the old-message size, and $w$ any additional
amount charged to that same receiver through commitment. Suppose
the primary's own transmitter can fit the old result, the link is
good, and old rows remain live until commitment. A truthful
pre-evidence bit $R+M\le C$ is not sufficient to authorize the old
message. The condition is exactly
\[
                 R+M+w\le C .
\]
If a later slot might add a charge, it belongs in $w$ whether or not
the intervening packet is itself called a diagnostic. When the source
has a valid upper bound $W$ on $w$ and no smaller possible envelope
is known, it can send the stronger bit $R+M+W\le C$. A successful
positive reading guarantees the old fragment's receive allowance;
each later decision still checks the sender, link, identity and other
retained premises. If the only remaining uncertainty is the footprint
$w\in[0,W]$ and $W$ can actually occur while $R$ is live, no larger
fixed cutoff can safely admit. The bound is a joint one if $R$ and $w$
are not independently attainable. Data that arrive too late or fail
to arrive are not interpreted as a positive bit.

\paragraph{Transfer boundary.}
If a reserved read is moved to an independent receiver, $W$ can be
tightened to zero when there are no other charges. A certified
positive still applies after tightening but may miss feasible
primary choices if a broad old bound is retained. Moving the read
back to the shared receiver can instead invalidate the unchanged
pre-evidence bit. Reuse then requires the old slack bound to
cover the new possible consumption, or the source must recalculate
the bit. This is a same-payload distinction driven by the footprint
of acquiring it, not by a different interpretation of the capacity
unit. A local checker actually seeing post-read headroom can
recompute the condition directly. Where the exact transported bit is
available and correctly priced, it agrees with that check. If the
bit is erased or conservatively priced for an unresolved receiver,
the post-read checker can know more.

\paragraph{Native test.}
The pinned SubT pose cache, queue ingress, dispatch, TX/RX debit
and actual application callback are used. The read occurs before
the old send, receiver use is charged at callback admission, and the
older debit at time $0.25$ remains live at $1.25$. In the main
witness $C=320$, $R=147$, $M=173$ and the report has one byte.
If routed to the old receiver, the one-byte report arrives and moves
its live spend to 148. Its original positive answer is true of the
earlier cut. The sender-only or unpriced-bit rule nonetheless fails
the old delivery. The priced source switches to the independently
eligible backup, which delivers the old result but uses capacity
otherwise available for its separate 160-byte report. If routed
to an independent verifier, the report has the same byte size and
can retain the primary and the optional report. The receiver with
the old mandatory packet is kept distinct from the independent
verifier and the joint authority destination: being the same logical
station is not a reason to merge or separate the physical accounting.

The replay runs the actual cached station result after the matching
callback, or leaves it fenced and refuses apart from receipt. The
range predicate, work priorities, visibility/observer ability,
transport bindings and timing are authored; this is not an RF
prediction. A matched direct rule agrees on the fixture, and no
independent case or architecture acceptance follows.
