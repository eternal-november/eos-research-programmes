\section*{Revocation of a prepared supplier between read and emission}
\paragraph{Declared cancellation law.}
An acknowledged revocation prohibits later emissions by the named
grant. It does not retract packets already emitted or cancel the
recipient's distinct authority to reconcile the old effect. Also
measure the stronger requirement that a revocation requested before
the effect be committed by the effect cut. These are different
requirements because processing the revocation can be deferred.
The modeled emission is invoked at the native serial dispatch cut;
no claim of continuous-time hardware authorization.

\paragraph{Native and durable cuts.}
Retain the exact warehouse/SQLite archive and the native route and
receive callbacks of PR 862. The same first callback, receipt bytes,
and copy preparation are present throughout. Q can send after the
late near update; with the late far update P can also send. Inject
a write through a separate SQLite connection before the late authority
read, or after the read but before native dispatch. Compare a cached
grant, a refreshed grant and a grant checked while a write reservation
is held through the native callback. The revoker uses a zero-timeout
autocommit update and can retry after release. This is an ordered
simulator protocol, not a stock distributed transaction.

The refreshed arm sees an already committed revocation. It can use P
where P's route still works, or withhold the old return where there is
no authorized route. Refresh does not survive a later revocation
between reading and dispatch: the tested native emission uses the old
copy and there is no lower-level gate that would stop it. The
experiment detects that unauthorized delivery and withholds receiver
installation. Withholding installation cannot undo the emitted bytes.

\paragraph{Cost of the lock.}
Holding the reservation prevents the revocation from committing in
the measured gap. A subsequent retry succeeds after the callback.
This satisfies the no-emission-after-acknowledgment order in the
tested serial cut. It fails the stronger demand for a committed
revocation by the effect when its request came in the gap. No
bound on waiting in an unrestricted live process follows.
A single ready database additionally blocks a writer for a distinct
independent workload, even though independent radio traffic can
continue. Separate database scopes allow that write in the same cut
while still excluding the competing Q revocation. That framing requires
a real independence argument: operations or safety rules that jointly
change the two grants cannot be moved to separate scopes without
another cross-scope proof.

The scoped transaction is an ordinary exclusion mechanism at the same
interface, so a direct implementation ties. Sender epoch, immutable
copy and current authority remain independent concerns. This is a
held-in failure and a bounded positive model, not a deployed gate,
new physical authority, or independent mission acceptance.
