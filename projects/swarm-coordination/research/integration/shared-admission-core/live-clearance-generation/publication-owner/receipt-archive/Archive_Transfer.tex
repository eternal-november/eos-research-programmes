\title{Retaining an old result before its source closes}

\paragraph{Audit.}
A later useful action may close an earlier result's normal lookup.
This study uses one unchanged archive-consumer rule on two selected
native producers: the SubT score and finish logic, and the RWARE
station with the existing SQLite publication fence. The rule
distinguishes returning a confirmed result from permission to apply
a missing operation. Results concern the declared sandboxed plants,
not physical motion or an independent I1 mission.

\paragraph{Shared rule.}
A producer supplies an evidence record for the exact named
operation and current archive scope before the ordinary source
is lost. The archive commits this record locally, independently
of the final recipient's acknowledgment. After closure, the
controller compares source, identity, epoch, and authorized
capture cut. A qualified positive result can be forwarded
without applying the operation. A negative result alone does
not authorize replay. An application is admitted only with a
coherent current publication fence and an actual successor
permit. In the executed warehouse implementation, installing
the snapshot verifies the frozen source tag, and the successor
worker separately rechecks its own permit before changing state.
A raw equality of old and new result values is not a fence.

\paragraph{Scorer cut.}
The exact pinned OnNewArtifact and ScoreArtifact methods are
extracted. Message types, world pose, logging, and the Finish
side effects outside the selected score branch are small
test stand-ins. The exact native report-key lookup, duplicate
result, total-score update, cap check, and selected event
strings execute. An authored serial producer adapter exports
the exact named positive after the original score call returned;
the selected current echo and native lookup agree. The archive
writes while that source is still open. The unrelated call then
scores a different real fixture artifact and triggers normal
closure. The ordinary retry says scoring finished; by the time
the common consumer reads, the original process is gone.
The stored exact positive still supplies the old result.
Without the valid archive, the recipient refuses: a rounded
same-score sibling, stale archive, lost archive, and an absence
followed by a late actual old commit are separate controls.
The late-old control allows an extra report slot to let the
unrelated work still score, and confirms that prior absence
became stale. There is no applicable post-close score writer
permit. In particular a new submission is not generated
from the missing old confirmation.

\paragraph{Warehouse cut.}
The second adapter runs the exact selected RWARE action and
the previous SQL fence and permit fixture of PR~643.
After the old decision, a different real simulated carrier
makes a native move to cell \((2,1)\).
The reader loses access to the old owner at that boundary
by the authored application rule; movement itself does not
prove data are unavailable. The same archive consumer either
returns the completed step result or authorizes one actual
successor apply after a fenced absence. The old owner refuses
a late operation. Stale cut, denied permit, and missing
fence evidence are verified controls. The original matched
mixed-cut replay is also rerun, including its separate
unfenced duplicate-publication counterexample.

A positive read-only result does not require giving the
new consumer authority to execute further station work.
In the paired test, the scoped result path skips the
32,768-byte SQLite snapshot while returning the same
result and allowing the same independent move as the
full-copy arm. Both arms still write their own result
archive. The absent-result replacement does need the
verified full snapshot and the permit in this fixture.
This is a measured snapshot-copy difference for a
read-only scope, not a complete migration or a claim
to beat a direct typed archive using the same optimization.

\paragraph{Comparison and scope.}
The native duplicate in an active scorer can retain its
original delta while receiving a newer global count;
after closure the same query does not perform that lookup.
The archive uses the named result before closure, not
the rounded event string, current count, open flag, or
an evaluator's later reconstruction. A strategy that waits
for the final confirmation before allowing closure cannot
perform the selected useful work at that cut; the typed
local export does not wait for that final receipt.
An equally informed direct consumer can make the same
typed decision. Eleven cases exercise the two adapters,
with additional native closed/replay and exact projected
alias controls. Four Lean statements audit the consumer
algebra, not the implementation-source correspondence.
No power-loss persistence, full ROS scoring, new
physical actuation, frozen held-out transfer, or I1
acceptance is asserted.
