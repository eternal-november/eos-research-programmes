\paragraph{Audit.}
Two continuations from the same old acceptance have the
same archived receipt, current reported pose and orientation,
and authenticated episode. In one, unrelated work moves a
different carrier while the first still owns shelf 1. In the
other, the first actually returns and unloads shelf 1, then
goes back to its original pose and orientation. Matching a
prior receipt and current pose is insufficient to permit a
new custody-dependent motion.

\paragraph{Execution.}
The positive source is the same exact keyed RWARE acceptance
as in PRs~716--717. Both continuations advance actual selected
native steps. The new consumer receives that named historical
result, but the consuming transaction also needs the permitted
native owner, the current carrying relation for shelf 1, and
the expected starting pose. It holds the same SQLite write
transaction through checking and publication of the bounded
three-step motion. The claimed motion contains turns and a
forward step, not a shelf toggle. A partial publication cannot
run after a failed check. The same intent's repeated return
uses its keyed result without another native step. This is an
atomic author shim for a managed simulator, not a claim that
database isolation controls physical robot motion.

\paragraph{Observed comparison.}
In the side-work case, the old result remains available,
the first carrier is still at \((4,1)\) with the original
heading and shelf, and the stamp has nevertheless changed
to tick 10. The action is legal: it reaches \((3,1)\) at
tick 13. Its retry is cached.
In the other case the first carrier is back at \((4,1)\)
with the same heading, and the old result survives, but
the actual custody is gone. The consumer refuses at tick
17 without another append. Declaring the old proof valid
whenever pose and receipt agree would wrongly admit this case.
Rejecting all changes since tick 8 instead loses the good
case. The typed rule permits the legitimate change while
demanding a real fresh witness for the newly consumed property.
A direct atomic guard with exactly the same current information
also works; this supplies a witnessed distinction and a safe
construction, not a gain over that guard.

\paragraph{Scope.}
The carrier identity, shelf, planned motion and scope are
preinstalled and test specific. Permission is a local
fixture owner check, not an authentication or consensus
protocol. Nothing here implies that native control outside
the transaction can neither interfere nor move an actual load.
The prior archive interfaces still need broader independent
transfer and mission evidence. The replay uses the parent
pinned inputs; a fresh extracted package reruns the original
publication and archive controls as well.
