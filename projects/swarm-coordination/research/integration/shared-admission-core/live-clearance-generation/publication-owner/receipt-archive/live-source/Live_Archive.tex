\title{A stable old receipt is not a current custody witness}
\date{27 November 2026}
\begin{document}
\maketitle
\paragraph{Audit.}
Continue the warehouse branch of PR~716 on the same source
database and native RWARE plant, not a separate side instance.
Three cuts distinguish preserving a named historical effect,
knowing absence at a later cut, and knowing current custody.
The world is a selected native simulation with a SQLite WAL
journal. No physical handling or independent mission is claimed.

\paragraph{Live writer, stable result.}
Expose the exact named positive at tick 8 from a read
transaction. While that transaction remains open, another
operation on the same station journal takes the other carrier
from \((2,2)\) to \((3,2)\) in two native steps, to tick 10.
The original writer remains enabled; the old receipt is
immutable in this declared operation set. The positive archive
can still serve the exact old result, without publication
freeze or newly authorized plant writes. A global state proof
would need to account for the changed state, but the consumer
only asks the old result. The other carrier's move leaves the
old shelf's custody unchanged. A same-scope direct read of an
available receipt ties; no transport improvement is inferred.

\paragraph{Absence does not survive a repeated read.}
Take the same WAL reader at tick 7 with no old receipt.
The old source then really applies at tick 8 and the other
carrier again moves through tick 10. The same reader's later
query still shows no old receipt, although a new connection
sees the exact accepted result at tick 8. This is the
\href{https://www.sqlite.org/isolation.html}{documented WAL snapshot behavior},
not a defect in SQLite. The read timestamp alone is not a new
source cut. The archive consumer correctly refuses to retry
from this unfenced absence. The old actor's own subsequent
keyed lookup gives the existing result, not a second apply.
An absence must be revalidated after the final possible
publisher, or consumed through a coherent fence and suitable
successor permit; re-reading the same view cannot replace that.

\paragraph{Changing what the receiver asks.}
Keep exactly the same old result at tick 8. Follow the
native return-and-unload sequence of the first carrier
through tick 13. Its carried shelf is now absent despite
the unchanged old acceptance receipt. A reader asking
whether the old named operation happened can still use
the positive archive. A receiver whose next motion requires
current possession cannot transport that proof unchanged.
The appropriate current plant read separates the two
contexts; it still needs a future stability or interlock
argument if action is delayed. Conversely, merely seeing
a different global tick is not evidence that custody changed:
the independent side-move branch preserved it.
This is the boundary of the inherited result, not a new
custody policy or closure of the broader replacement obligation.

\paragraph{Checks.}
One native selector, two actual concurrent WAL views in
separate connections, all selected native moves observed.
The package also reruns both parent archive adapters and
the source ownership/fence cases. Intent keys and result rows
are checked by the same archive consumer. The source-specific
retention and authorized operation set are assumptions; the
result does not cover destructive rewriting, generation reuse,
physical hardware, or arbitrary post-read changes.
