\paragraph{Question and fixed evidence.}
The receiver has a checkpoint taken before one possible final donor
transition. Does the failed donor's silence prevent a safe takeover?
Three distinct SQLite stores represent the donor state, receiving
checkpoint, and independently retained transfer envelope. The
exporting process actually exits. Its database is no longer in the
receiver's request workspace; the receiver runs using its own
checkpoint and the retained envelope only. The managed effect is a
committed step of the pinned RWARE simulator plus its canonical
completion record. That is not physical actuation, a wireless middlebox,
or distributed crash-tolerant consensus. Independent survival of the
envelope store, the local trusted path to it, and the chosen scope and
incarnation are premises to this reference, not guarantees proved by
the fixture. Sources are pinned in \verb|SOURCE.tsv|.

\paragraph{Where the crash matters.}
The first station worker exits after staging or after committing the
keyed step. Both look silent. A second process then (i) durably
disables old publication on the station's write boundary and (ii)
may publish separate evidence of that exact closed cut. The replay
kills this exporter before freeze, after freeze, before the envelope
transaction commits, or after the external write commits and before
any application reply. All give the same direct symptom. SQLite
correctly retains a frozen donor even when the external write rolls
back. Thus the old effect may really be fenced without safe progress
being recognizable elsewhere. The two transactions do not form one
atomic commit. The side carrier's native progression is unaffected.

\paragraph{Four alternatives for the surviving evidence.}
A genuine stop indication does not identify what the donor committed
before stopping. Retaining only that indication never suffices in
this envelope. With a seal identifying the exact post-freeze logical
cut, the receiver may mark its checkpoint closed in a private
transaction and compare the exact state, keyed completions and
permissions to the seal. If it matches, no further state is needed:
the donor had not committed the extra step. If it does not match,
a digest demonstrates disagreement but does not reconstruct the
missing state. A checkpoint-bound keyed suffix can add the missing
logged transition and its canonical result (or replace an obsolete
right) before the same validation. In either successful case
installation transfers the publication epoch, and a new native
worker either completes exactly one pending request or returns the
retained result. A complete trusted stock snapshot contains the
closure and all its state; it is not necessary to preserve a
redundant application reply in that case either.

The validation compares the complete named logical envelope of
this finite one-origin fixture, using a canonical digest as its
identity check. Reconstructing the native state additionally
checks the proposed history. A mismatching seal leaves the staged
checkpoint unchanged. With no durable envelope, the receiver
cannot tell a genuinely frozen execution from a still-live donor,
nor a still-pending effect from an already-published effect.
Executing based on that view risks duplication; declaring
settlement can be false in the pending case. Waiting is safe but
does not meet the affected service target. If the latest permission
was withdrawn after the checkpoint without changing the native
log, a bare seal still mismatches and the suffix correctly refuses
because the right is absent. A complete attributed result cannot
manufacture an execution right.

\paragraph{Checked results and comparators.}
Thirty crossed phase/outcome cases, plus an initially missing right
and three tests of withdrawal after checkpoint. A committed external
seal lets the pending native case resume, not the already-published
case omitted by the checkpoint. A durable suffix or full snapshot
handles both, applied or cached as appropriate. Every earlier
external publication cut leaves the receiver waiting. In the
completed-effect case the compact envelope is 286 logical JSON
bytes after the common 32,768 logical-byte database pre-copy.
A frozen copy is another 32,768 logical database bytes at this scope;
the measurements do not benchmark storage I/O, replication latency
or wire formats. A keyed-log direct checker using exactly the same
cut and suffix agrees. The suffix is an instance of checkpoint
repair, not a claim to beat incremental checkpointing or
\href{https://web.stanford.edu/~ouster/cgi-bin/papers/rifl.pdf}
{RIFL's migration of completion metadata with objects}. The strong
comparator already preserves the completion record. No independent
transfer, unchanged live-radio integration, field recovery, or I1
acceptance follows from these tests.
