\section*{A late binding chooses an effect, not a new history for an old effect}
\paragraph{Frozen interface and source cuts.}
The same four-byte named request reaches the same native SubT dock
as in the parent in-flight binding replay. The declared actor at
dispatch may be blocked by an actual RWARE step before actuation.
Trusted local control at the dock can then use the other actor.
A single native warehouse journal atomically installs the named
effect and the exact four-field result. The independent warehouse
move and the optionally competing delivery are retained.
When independent radio traffic fills the caller's receive budget,
the first reply is transmitted but does not arrive; the request is
then retried at a later cut at which the earlier debit has aged out.
The dock reopens SQLite for the later callback, and the registry
may now give the old held actor, the other actor, or no actuator.
Authority to disclose the recorded result is separately supplied.
The two current rights are admitted fixture inputs, not inferred
from success or connectivity.

\paragraph{Observation and action obligations.}
For a fresh pending duty, choose only a current permitted actor.
After the named duty settles, a retry with a valid disclosure
right asks for the already recorded result, not a new action.
An unavailable current actuator is not a reason to suppress an
authorized history read. Conversely loss of permission to read
the receipt does not turn that completed effect into a pending
actuation. Lean checks both rules for the stable exact key.
With receiver-local reopening of the journal, the first result's
actor can remain A while a newly permitted B actually has an open
cell at the retry. The legitimate response is still A's exact
result. The diagnostic that treats the same query as a fresh
physical duty moves B too and returns a different value. It is
not an equally correct implementation or an alternative work
definition. This distinction connects the live actor choice
and the exact-result rule in
\href{https://github.com/eternal-november/eos-research-programmes/pull/813}{the earlier restart test};
it does not model atomicity between the radio and a real actuator.

\paragraph{Native checks and comparator.}
There are 48 cases per arm for the frozen policy, the ordinary
exact-result-cache-first direct implementation, and the deliberate
fresh-binding ablation. The first two each return 36 exact answers,
with zero repeated moves. The ablation returns 24 exact answers
and causes two extra physical movements under the old request.
It also sometimes returns no reply where the journal could have
served the exact authorized result. The twelve no-reply cases in
each correct arm have no current disclosure permission after losing
the first reply. The direct exact cache ties, so neither superiority
over ordinary keyed-result recovery nor independent I1 acceptance
is claimed. The code compares actual decoded native return bytes,
packet counts, and the physical steps recovered from the SQLite log.
