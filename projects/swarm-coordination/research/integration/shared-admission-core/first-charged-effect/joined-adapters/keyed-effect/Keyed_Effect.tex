\paragraph{Matched restart pair.}
The joined \href{https://github.com/eternal-november/eos-research-programmes/pull/812}{first-effect replay}
assumed that one old duty was still unsettled. Here a separate worker
performs the same native RWARE entry into cell A in two executions.
It exits after the database commit without producing a reply.
The durable motion logs and reconstructed plant observations are
identical. In one execution the step settled the named old duty;
in the other it belonged to a different authorized key. The old
logical intent permits either A or B to complete a still-pending
duty. An exact historical result includes the station that actually
performed it and the committed tick; naming a new receiver does
not rewrite that result.

The fixture uses the journal-authoritative technique of
\href{https://github.com/eternal-november/eos-research-programmes/pull/633}{the atomic-commit replay}.
A SQLite WAL transaction records the native simulated motion
and keyed result together. The stock simulator's transition is
privately evaluated and the authoritative state reconstructed
from committed actions. Neither the radio nor a physical vehicle
participates in that transaction. Both receiving endpoints may serve
the fixed old key under the same scope. This is not proof of stock
owner migration or of an arbitrary route-payload equivalence.

\paragraph{Different use conditions under the same symptom.}
The old request itself is sent through extracted native SubT broker
code at a tight four-byte cap with competing native background
traffic. In the calibrated pair, a live debit at A sends the old
request to B. B locally checks the exact journal key and returns
A's old result if present, with no new native movement. If the
old request was still pending, B actually enters cell B and
records that different result. It cannot substitute an unrelated
movement for settlement. If B is occupied, it can still return A's
authorized record in the settled history, but may not spend a
radio attempt on an impossible new move in the pending history.
The recorded result returns via the local simulator pipe;
no over-radio reply or distributed recovery guarantee is claimed.

The same selector reads a disjunction: either there is a valid
keyed result, or a new effect at this candidate is physically
admissible. The native read, upcoming selected step, ownership
and journal lookup are scoped locally and held through use, as
in the positive parent fixture. The receipt transaction also
rechecks under the writer lock. No actor can invalidate those
local decision premises between the guard and callback in this
fixture. Where such an interleaving is possible, the parent
unheld negative control still applies. A source that stores
just a Boolean has not shown it can answer the exact query.

\paragraph{Comparison and status.}
A direct scheduler using the same keyed native journal and commit
cut ties. A position-only dispatch guard misses some old results
it could lawfully have replayed; a radio-only ablation can waste
its debit on an impossible pending action. The proof checks the
kernel that a resolved key keeps and returns the original result,
while an authorized new candidate is needed only for a pending
key. The checked scenario family varies background receiver
placement, exact age of one second, prior key association,
later occupancy, and four controller arms. It is a matched
same-symptom restart on a shared source history, not an
independent compound holdout or an operational advance over
ordinary correctly scoped keyed execution and local guards.
