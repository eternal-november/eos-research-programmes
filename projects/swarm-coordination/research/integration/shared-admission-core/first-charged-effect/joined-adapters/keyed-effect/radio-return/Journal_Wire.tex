\paragraph{Source and authority.}
The predecessor \href{https://github.com/eternal-november/eos-research-programmes/pull/813}{matched restart replay}
returned a native keyed result through local IPC from a shared
journal. Here a crashed donor and B have distinct SQLite stores.
The actual donor worker exits after committing a native RWARE step,
before replying. Two histories still share identical native motion
prefixes, but only one settles the named old key.
A local recovery exporter can read the donor's durable state after
the worker exit. At that source, a single transaction installs
insert guards so its ordinary motion and receipt writer can no
longer append to either table. The fixture replays an old
motion request and checks that the database refuses it. This is
not a distributed fence, an actuator guard, or a guarantee against
arbitrary SQL privileges.

The exporter sends a deterministic motion prefix and later an
explicit keyed status through pinned native SubT dispatch. On
receipt of the prefix, B locally replays native actions and
atomically installs the motion rows. An admissible keyed message
either says pending, or carries the exact four-field prior result
and has to match the reconstructed motion row. It installs a
local authorization at the declared scope. No old process or
database is consulted again by B. Status omitted or tagged from
the stale namespace does not install that authorization. The
export and schema are trusted in this finite fixture with one
prebound key, epoch, and deterministic plant. Prefix size is
three or four payload bytes, valid pending is one byte, and the
full prior-result form is five. Registration, epoch binding,
key and schema setup are not counted as payload or assumed
free in deployment. No general-purpose authentication,
successor agreement, or prefix compression is being proved.

\paragraph{Native bidirectional accounting.}
The request and exact response each use four payload bytes on
their actual radio directions. An initial transfer to B can
have been authorized by a separate sender with a higher cap,
but the native broker later tests B's live receive debit
against the new request sender's cap. With the transfer debit
still live, a pending transfer requires cap $1+4=5$ and a
settled transfer requires cap $5+4=9$ in this format.
At exactly one second the debit remains live; after $17/16$ it
has expired and four is enough for the request. This uses fixed
high RF power and the inherited deterministic draw seam, not
field RF observations.

A separate already-delivered report at Q can block the four-byte
return under B's cap even when the request and physical
effect are achievable. The end-to-end guard checks both
directions before dispatch, under the declared one-cut law and
the serialized source loop. When the unrelated report is
allowed to be scheduled after the returned result, both fit:
the independent sender's larger cap still admits its report.
No improvement is claimed from reordering an actual prerequisite.
If partial progress without a deliverable reply is required by a
different service law, this admission choice has to be reconsidered.

\paragraph{Exact effect and comparison.}
The singleton use of the unchanged selector reads only B's
actual journal and occupancy, plus the broker's own ledgers
at the declared local cut. The exact past result is returned
without attempting B's movement even if its cell is blocked.
An authorized pending key instead needs a successful native
B move, and missing evidence allows neither in the safe arm.
The result is delivered by the native B-to-Q callback, not
just returned to the process pipe. Treating absence like
certified pending can perform a second physical action for
a duty already settled by the donor. Both can yield a successful
callback, so receipt counts alone overstate lawful service.

The exact direct guard ties across the 3,456 cases.
Omitting just the radio capacity guards can spend a request
without achieving the complete response. The missing-as-pending
control has actual duplicate effects; its additional returns
are not additional legitimate service. The small Lean check
covers the two budget directions and the difference between
no evidence, explicit pending, and a settled result.
The joined simulator source loop is serialized and the local
stores it uses are authoritative simulation state. This is
not atomic radio/physical motion, a controller that remotely
reads another node for free, or an independent I1/I2 mission.
