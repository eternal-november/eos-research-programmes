\section*{Exact provenance capacity for a late choice of audit key}
\paragraph{Fixed support and cut.}
The extension of \href{https://github.com/eternal-november/eos-research-programmes/pull/818}{the changed-consumer witness}
preinstalls a shared ordered log basis of $k$ distinct eligible
result rows, the identity of the possible keys and their fixed
query order. All keys are acknowledged, but a later authorized
audit may ask for the exact result of one key. A trusted assignment
could name any bijection of keys to rows. The notification of the
new query conveys only its key, not which row it actually owns.
For $r$ fixed potentially audited keys, that query is selected after
compaction. There is no access to the original recipient or the
producer's exact association once decoding starts.

\paragraph{Exact criterion.}
Two associations are equivalent precisely when they agree on all
$r$ permitted queries. If any answers differ, choosing the differing
key after compaction separates them. Equal answers suffice because
the decoder already has the shared motion rows. There are
$k!/(k-r)!$ distinct ordered selections. Any exact summary
must separate all these classes, even if its receiver runs only
one query. Mixed-radix ranking of the ordered selection is injective
and takes all values in that range. If one key is fixed
\emph{before} compaction there are only $k$ answer classes.
An observed rank is justified only relative to the preinstalled
log basis and scope. Preinstalled basis/identity is not costed
as payload, no late field authority or transmission is tested,
and a result-dependent query grant would change the lower bound.

\paragraph{Native fixture and quantitative boundary.}
Seven actual pinned RWARE movements yield seven different rows,
six candidate rows and one unchanged independent result.
A durable evaluator enumerates all 720 admissible associations over
the six candidates, preserving the same underlying motion log.
The recipient reopens its separate SQLite copy of native rows; a
late query only uses the migrated rank and its own fixed basis.
The associations are fixture authority, not an inference from
warehouse positions. Three potentially audited keys give 120
exact classes and fit in one byte. Four give 360 and cannot fit
in one byte under any injective fixed-width encoding; nine bits
are necessary and sufficient. Truncating the computed rank to
eight bits collides on two distinct three-agreeing, four-key
associations. Lean checks the concrete cardinality boundary.
This is an exact retention bound under a declared finite query
family, not a generic bound for a changed basis or admission
policy and not an independent I1/I2 mission.
