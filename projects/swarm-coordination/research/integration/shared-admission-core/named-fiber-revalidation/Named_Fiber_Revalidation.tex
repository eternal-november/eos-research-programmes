\paragraph{Audit.}
This is a finite R1/L2/L3 and I1 development check, not an architecture acceptance test.
The recipient, issue cut, menu, deadlines, resource semantics, and old obligations are fixed.
A certified edit replaces entire \emph{named fibers}: sets of jointly possible source histories.
The name is a verifier key, not an observation available to the recipient.
An edit may change which local observations those histories yield.
Its evidence, recipient and deadline must be checked outside this checker.
The callable interface assumes a qualified edit with complete coverage; it does not infer its
scope, reconcile inconsistent source reports, or verify freshness of native notices.
The examples couple the pinned radio and warehouse sources by the same authored gate
as the ACK packing experiment. No held-out case is selected here.

\paragraph{Replacement law.}
For name $i$ and recipient view $v$, the semantic value
$p_{iv}$ is \texttt{none} if that fiber contains no row with view $v$.
Otherwise it is \texttt{some} of the set of actions feasible on every row of the fiber
with that view, including the empty set. Feasibility checks all carried obligations
and actual resource uses; a timely receipt alone cannot establish either.
Let $N_v$ count live fibers and let $B_{va}$ count live fibers whose menus exclude
action $a$. From a view with $N_v>0$ the frozen recipient can issue $a$ precisely when
$B_{va}=0$. With $N_v=0$ there is no admissible issuance, not a vacuous approval.
This aggregation loses row multiplicity, but not the old contributions of
each name. Names may be retired only when unreachability is certified; a missing
input is not evidence of unreachability.

A complete edit subtracts the touched old profiles, evaluates their replacements,
and adds the new profiles. Untouched names need not be queried.
The proof is partitioning a conjunction by fiber and adding
nonnegative indicators. For a patch touching $k$ names, the exact row work
is at most $m$ times the number of rows in the replacement fibers ($m$ is the
number of named actions); bookkeeping visits the old and new supported
view/action entries for those names. Afterward, one view query uses $O(m)$
counter reads. The observed scaling excludes construction and validation of the
complete patch, source replay, and transport. If one global shared fault changes
every name, a correct complete patch may have to touch every name.
With a bounded namespace, profile storage is at most $n$ times the fixed
view/action table; retaining tombstones or unbounded versions has its own
cost. The proof does not support epoch reuse with indefinitely delayed edits.

\paragraph{Why name and atomicity matter.}
At cut 9 in the prior packet experiment, one retained row with shared debits
permits packing or use of a spare; a second with disjoint debits and a tight old
consumer permits splitting or use of a spare. The aggregate only permits the
spare. Swapping the names leaves the aggregate and even the blocker counts unchanged.
Retiring the same name then opens packing in one system and splitting in the
other. Neither the eventual fields nor a terminal receipt can substitute for
the earlier consumer and old physical clearance. In a separate batch, swap
these two profiles together. Applying the first sub-edit alone can temporarily
and incorrectly permit packing; neither complete version permits it.
The implementation validates every base version, treats the input batch as atomic
in a single-threaded checker, and forbids edits to an issued decision.
It does not enforce a multi-process transaction or allow a historical approval
to undo an executed act.

\paragraph{Restricted composition.}
For one receiving interface, admissible pre-issue edits are partial arrows
between support versions: composition is defined when versions line up
and both edits are qualified at that cut. Sending those edits to profile
replacement respects sequential composition; disjoint edits commute in the
absence of an intervening issue. That is a quotient of \emph{how the verifier
updates}, not a generative model of which faults occur, or a license to
commute physical events. For an inventory-driven generator, the missing
obligation is to justify which named joint fibers a source intervention can
change, including new correlations and formerly impossible histories.
Using today's output profile to guess that scope is unsound.

\paragraph{Exact information bound.}
Pin one view, a stable namespace of $n$ names, and $m$ candidate actions.
If the admissible workload realizes all labeled profiles independently,
and future certified patches can isolate each name by retiring all the others,
then exactly $(2^m+1)^n$ states are distinguishable for decision reuse
at a fixed edition. Any two different labeled profiles differ at a name;
isolate that name using the same edit and query the resulting optional menu.
Conversely the tuple of optional menus determines every decision and update.
This gives a fixed-width lower bound $\lceil n\log_2(2^m+1)\rceil$ bits excluding
version, schema and patch-validation metadata. The bound is for that representation
interface, not a claim that the two pinned plants realize every mask.
If all names must remain present the alphabet changes to $2^m$; if future edits
can inspect or retract individual rows, these menus need not be sufficient.
Refining the ambient fault laws can therefore change either the admissible
patches or the information bound. No theorem here picks those laws from the inventory.

\paragraph{Replay and direct comparator.}
The replay verifies 3072 pinned packet cases and obtains 20 old clearance
traces through the existing source producers.
Nine resulting row types vary physical carry, radio aliases, receipt loss,
staleness, early data, and timely versus late view. The checker agrees with
fresh and exact factored direct evaluation on 6561 whole-fiber replacements.
In an instrumented 512-fiber case, it needs four new row/action checks instead
of 2044 for a full fresh scan; an exact direct cache also needs four.
A direct cache may keep the same counts and achieve the same aggregation cost.
This is a proof-locality and state result, not a performance advantage over a
matched direct method and not an I1 or I2 pass.
