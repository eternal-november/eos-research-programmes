\section*{What must cross a change in the allowed partner outages?}
The consumer asks one Boolean question: can the unchanged
old diagnostic be delivered at some genuinely eligible cut before
its deadline? The service window \(W\), time correspondence, old
content, capacity and link qualification are fixed as in the
temporal membership replay. There is one committed-ready set
\(S\subseteq W\) from the first observer's modeled source history.
Another observer's admissible outage set satisfies
\(U\subseteq W,\ |U|\le b\). Then no delivery occurs precisely when
\(S\subseteq U\).

Retain \(S\) exactly when \(|S|\le b\), and otherwise export a single
class meaning \emph{too many ready cuts for the partner to block}.
This is sufficient for that Boolean consumer. It is also exact
among factorwise summaries: if one candidate set \(S\) has size at
most \(b\), use \(U=S\) to discriminate any other candidate not
contained in it. If the other is properly smaller, use that as
\(U\) instead. The large sets all agree because none can be covered.
Lean checks exact comparison, transport to a smaller partner cap,
and a precise failed-lift witness for increases. For \(|W|=n\),
there are \(\sum_{i=0}^{\min(n,b)} {n\choose i}\) ordinary classes
plus the single collapsed class when \(b<n\). For example \(b=1\)
on four eligible cuts needs six classes rather than sixteen.

\paragraph{Context amendment.}
A finer, larger-cap profile always projects to a smaller-cap one.
The reverse is not generally a function of the stored profile:
an amendment can make a new covering test legal. In the native
four-cut fixture, one history is ready at cuts 1 and 3, another at
2 and 3. They have equal counts and last-ready time; both were in
the large class at cap 1. Admitting a partner outage on cuts 1
and 3 gives no old delivery in the first and exact delivery in the
second. This is a lawful-change witness for the audit/interface
query, not anticipation of the new outage by a real-time planner.

\paragraph{Verification and boundary.}
The unchanged scoped fixture and native broker exercise all 272
ready/outage pairs across four-eligible and two-eligible calendars.
Cuts with live charges are removed using the same source history,
not by fitting the profile to outputs. Every native Boolean output
matches the set test. Across all partner caps 1,328 equality tests
agree with the exact quotient. This describes proof-side ready
supports or supports supplied by a separately qualified temporal
reservation. It gives no clairvoyant read of future poses. Nothing
here summarizes the exact first delivery time, diagnostic payload
or raw pose trace, covers workloads that change the eligibility
window, or proves that a proposed cap change will physically
occur. Those questions may refine or invalidate the stored
interface. No independent acceptance claim is made.
