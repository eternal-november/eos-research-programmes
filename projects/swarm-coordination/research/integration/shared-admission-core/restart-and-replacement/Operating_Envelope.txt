DEVELOPMENT DECLARATION — not independent confirmation freeze.
One station acceptance obligation, ID 7, due at tick 7 exactly once;
one unrelated work acceptance due at tick 3, productive during ACK loss.
The adverse class comprises an absent old ACK across owner restart,
an old paid or terminal-unpaid attempt (a separate admissible branch
leaves the old attempt still entitled and pending), and optionally Q
losing its path between preparation at tick 3 and use at tick 4.
The monitored station is physically abstracted as a durable one-key
gateway. Old P, replacement Q, backup Second all reach that same
application effect on surviving paths; Independent→Far is separate.
Old, Q, backup and side callbacks are in the same replay instance.
No arbitrary gate outage, station split/merge, duplicate ID alias,
time drift, corrupted witness, or simultaneous side-link loss is
claimed. All schedules use one-byte payloads in five-byte per-node
rolling ledgers (the replay scales one tick to 1/8 second). The
preparation step includes one such byte and an authored setup lag.
Cut 2 uses only serialized intent, missing prior ACK and an optional
valid application-state read; a negative read is not a terminal fence.
At most one backup preparation; paths and staged slots above are fixed.
Backup use at tick 6 if prepared before loss, tick 8 if reacting after.
The signal arm requires real Q-to-backup notice delivery at tick 5.
The installed gate/timer arm admits erasure of that notice, and schedules
the pre-staged backup regardless of Q's result. Every issued backup
and every attempted cue is charged on its actual native ledger.
Application acceptances are authored simulated effects, not cargo moves
or deployment. Native source and comparisons are in README.
