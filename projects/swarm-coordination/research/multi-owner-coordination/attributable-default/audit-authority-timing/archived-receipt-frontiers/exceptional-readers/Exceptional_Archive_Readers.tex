\title{Retaining exceptional readers without expanding a complete-prefix graph}
\author{}\date{}
\begin{document}\maketitle

\paragraph{Context.}
The
\href{https://github.com/eternal-november/eos-research-programmes/pull/692}
{common archive-frontier result} requires all slots to expose complete
prefixes of the same ordered manifest. A successor can instead inherit
several complete readers plus a small number with independently
qualified named evidence. Treating the latter's ordinary latest tick
as a complete prefix is invalid. Keep the slot scopes separate.
A slot enables one authorized completed historical read, not clearance
or a new execution of the old duty. Observations and source provenance
are held fixed in this study.

\paragraph{One exceptional scope.}
Order selected requests by descending required cut \(q_1\ge \cdots
\ge q_n\), and the complete reader frontiers in descending order,
padding missing ones with zero. Match the two lists in rank order
to test complete-reader feasibility. If it passes, no exceptional
slot is needed. If even deleting the hardest request does not make
it pass, no single deletion can: every coordinate of the remaining
ranked list is at least as hard as after that first deletion.
In the remaining case let \(h\) be the first failed comparison in
the original two lists. The exceptional slot must supply one of the
first \(h\) requests. Deleting a later request leaves failure \(h\)
unchanged. Deleting any earlier one, including \(h\), keeps the
original (passing) comparisons before the deletion, and uses the
passing shifted comparisons afterward. This proves the exact
eligible rank prefix, even when the exceptional scope itself is an
arbitrary subset. After the initial sorts the two scans and intersection
test are linear in the number of selected requests. Use the actual
named eligibility test on the critical prefix: a count or last tick
does not replace it.

\paragraph{Several exceptional scopes.}
Do not pool distinct exceptional authorizations into a single common
scope. Instead take the distinct required cuts and positive complete
frontiers, ordered increasingly, as a chain. At each threshold \(v\)
let the chain send at most the number of complete slots with
frontier \(v\) to the sink. Each subject can send one unit into
its requirement node and travel up the chain to a sufficiently
late frontier; capacity at least the number of subjects suffices
on each intervening chain edge. In addition, give that subject
its explicit qualified edges to exceptional slots. Each exceptional
slot has sink capacity one. The source sends exactly one unit per
subject if the selection is feasible.

An original matching routes through the chain by the associated
frontier whenever it uses a complete slot. Conversely, an integral
unit flow decomposes into paths; each terminating complete-frontier
unit can be assigned to a distinct actual slot counted there and each
exceptional unit repairs its own authorized subject. The two reductions
therefore preserve decisions and decode an actual assignment, not a
putative combination of individually valid rows. If the actual role
can change after the choice but before assignment, run the per-role
test over the admitted paired domain; this resource packing result
does not make apparently independent role marginals implementable.
No elapsed-time bound follows simply by counting edges.

\paragraph{Checks.}
The harness reuses the exact earlier pinned RWARE/SQLite archive
producer. Its named receipts, including the three actual sparse
archives, supply the scope sets. It checks all selected subsets
in that fixture, 705,024 finite one-exception comparisons against
direct matching, and 1,024 additional comparisons for several
different exceptional readers. In the declared 100-subject specimen
the explicit flow graph has 5,304 forward edges while the chain
representation has 453; the same matching problem is solved. An
equally structured standard flow implementation can use the same
compression. This is a scoped algorithmic representation result,
not a new deadline, an actual read budget measurement, independent
I1 acceptance or a published-solver speed comparison.
