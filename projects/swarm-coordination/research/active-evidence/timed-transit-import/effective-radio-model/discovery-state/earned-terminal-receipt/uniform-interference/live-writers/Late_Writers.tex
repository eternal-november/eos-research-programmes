\paragraph{Boundary.}
A terminal-local guard in the earlier study used a sealed primary
prefix. Keeping the reserve guard perfectly current is not enough
if an older writer can still add a matching native debit after the
reserve dispatch. The resource law needs a closed producer prefix
or complete enforceable control of all relevant writers as well
as a lookup at the point of admission. This is a development
study of changing authority (R2/L3), not an independent mission,
a proof of stock middleware atomicity, or a production patch.

\paragraph{Source.}
The build hashes the parent fixture and preserves its pinned native
SubT visibility, pathloss, broker, endpoint and RF window setup.
The primary sends the same nine-byte report with its actual fixed
RF success or failure derived from the retained breadcrumb
representative. The independent second report is ten bytes and
is due at the native event at time~5.0. Compare $q=18,r=19$,
where a real duplicate interferes, to the inherited adjacent
configured limits. A previously stored old key is retained but does
not qualify. The exact ledger is counted only from actual current
receive callbacks. The same authorized gate request, already
issued in time as in the parent, submits $Q$ before $R$.
No extra robot motion or gate opportunity is credited in these
time-order comparisons.

The allowed selected timelines move only $P$: before the estimate
(4.0), between the estimate and Reserve $Q$ (4.5 versus
$Q$ at 4.625), after $Q$ but before $R$ (4.75), or after the
measured second deadline (5.125). The estimate read is after the
independent native side dispatch at 4.125. All decisive timing comparisons
use the same packet key, movement promise, slot deadline, and
budget. The simulation can observe retained history to evaluate
outcomes; the guard itself reads only the local estimate or
the named authoritative committed receipt, as specified.

\paragraph{Distinguishing failures.}
A reserve-only snapshot of the ledger suppresses a successful
primary duplicate if $P$ completed before it read. If $P$
completes in the gap, the negative snapshot admits $Q$ even
though its application result would be redundant. The native
receive window gets two nine-byte debits and rejects $R$.
A reserve-only inline guard fixes that gap: $Q$ is suppressed
when $P$ has already committed at the decision. It does not fix
the reverse effect order. If $Q$ arrived first and a still
authorized $P$ then commits at 4.75, $P$ supplies the duplicate
and $R$ still fails. A fresh guard at only one writer does not
control a second writer's already authorized future effect.

An explicit single admission owner with real authority over
\emph{both} pending actions can fold the live exact record into
each pre-enqueue decision. Serializing the guard with the actual
receive/commit while both end-to-end actions remain controlled
makes the first success visible before any second matching
debit. When the first physical attempt fails, there is no
committed receipt and the reserve must not be suppressed. In
the authored one-thread source seam the positive guard reaches
both reports at all four primary positions and in both native
radio histories. Giving the owner both switches but making
both guards use the earlier frozen estimate still fails in
the middle two successful-primary cases. Authority and current
qualified evidence are separate requirements. If an action is
already on the wire so neither liable owner can cancel it,
the check must account for that debit or establish a closed
prefix; it cannot claim the conditional result by relabelling
the writer as now owned.

An after-$R$ duplicate can leave both due reports intact, while
still adding a native debit for any later work. We report both
the settled deadline result and the final ledger. Reusing only
the deadline result across a longer horizon would omit a live
charge.

\paragraph{Verification and limits.}
The exact integer reference checks all 480 native histories,
including receive limit neighbors, actual $P$ sender charges,
scope of each suppression guard, and all independent side
deliveries. The Lean kernel proves that once a current fence
over all remaining admissible writers sees one exact committed
effect, no later controlled writer can increase the count. One
uncontrolled writer or two stale views have a checked two-effect
counterexample. The proof abstracts link and credit admission
into an explicit input; it does not by itself establish that
any real writers satisfy that fence. The experimental in-process
serial callback is not a guarantee about multi-process concurrent
native senders. A same-information and same-authority direct
rule ties. The discriminatory advance is in the required
guard scope and freshness, not an independent operational win.
