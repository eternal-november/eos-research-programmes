# Global population and finite local representation

Status: derived representation observation for the fixed-port family, with source inspection; the final compiled source still needs its exact local bounds. This resolves an interface question raised by the larger hard-capacity/current-cut constructions. A large global population is a real architecture cost. It does not by itself require a globally addressed runtime word or a larger local policy.

## Which identities the policy carries

Fix the local design data d: forty maintenance ports, eighty candidate bays per side, thirteen logical observation slots, the local source/target key layout, image length, word width, physical uncertainty/rate bounds and finite timing/counter parameters. INCIDENCE supplies a physical interpretation for every even m>=72 and R>=6, N=mR. No runtime instruction in PROGRAM reads N, m, R or an absolute host identifier. Publication, queries, write leads and comparisons use local port/slot ordinals and finite per-target keys. Their translations to actual objects are established by wiring, not by a global name in a packet.

This statement concerns that actual interface, not every distributed system. A replacement protocol that serializes absolute host numbers, iterates over the cohort, uses a global quorum denominator at runtime or allocates one local record per remote host needs different word/storage/work bounds. A larger local catalogue cannot hide behind the forty-port count. The resource and graph maps must include the real local incidence.

Physical identity and its representation are distinct. RECEIVER's diagnostic tuples `(receiver,side,body)` name the actual physical destination for a proof/checker. A completion uses a fixed return lead to that cartridge; it does not serialize the analyst's receiver index into a 256-bit register. Candidate keys and local side/bay indices are runtime data with exact bounds. Rebinding a socket to a different body remains forbidden until actual old completions drain; deleting an identifier from a payload does not delete that obligation.

## Uniform-policy argument

For two admitted populations with the same local design data, the stored instruction image and local memory/primitive signatures are the same. Relate actor states when actual local C, private machine state, pending instruction, locally addressed I operands, local clock/port outcomes and delivered history agree. Every ordinary instruction then has the same successor private state and locally addressed output: arithmetic and memory instructions use the same bounded words; a primitive reads the same actual local operand or produces the same local offer; fixed completion leads preserve local body identity. Induction on executed instructions gives identical actions for identical local histories. No global size or hidden fault identity enters that argument.

The environmental histories need not agree across populations. A larger network has different aggregate flows and physical resources. Its safety/service result remains the parameterized plant/incident/renewal theorem at the selected source parameters. The local-policy argument does not simulate the entire smaller world inside the larger one, add new actors during a run or supply their initial correctness, power and apparatus for free. One complete finite roster and initial source are selected before each indefinite execution.

The incidence proof is parameterized rather than based on enumerating a huge ring. Each local offset lies in [-20,20], and the relevant overlap calculation fits an arc of length eighty. N>=432 prevents the relevant wrap aliases. Translation preserves maintenance groups; an odd translation exchanges the plant-row types. Direct barrier stations at offsets up to three, if adopted, need their own bounded intervention/observation maps, not a global search. Increasing N does not enlarge those fixed offset sets.

## Consequence for hard-capacity sizing

HARD-BOUNDARY selects a sufficient regional population from actual faulty export M. Its checked point happens to fit global names within 256 bits. That is a convenience, not a consumed PROGRAM premise. If honestly priced current-cut apparatus yields N beyond 2^256, the local program is not thereby ill-typed: first check whether a runtime operator carries that identity. Here none does. Reducing physical strand counts merely to fit the analyst's N into one word would be unjustified unless an actual source inventory supported the smaller count.

Local bounds still bind. Code must fit its installed image; private indices, encoded replies, descriptors, raw counters and progress/watch parameters must fit their actual types; relative intervals must respect counter wrap; new stations/meters must be paid and fit their physical selectors. Increasing warm travel or a watch interval requires recompilation and renewed work/geometry checks even though increasing N alone does not. An arbitrary-precision analysis integer cannot substitute for those checks.

The current baseline and prospective-provider sources were inspected for global-size/name reads, alongside their compiler design signatures and INCIDENCE address maps. The baseline has3315 encoded cells and the checked provider replacement3423; these are their own bounds, not a claim that the later dwell/current-cut image is already bound. Final verification must repeat this local-interface audit and bind the complete new image/constants. The result separates global model cardinality from local representation size; it does not make the enormous hardware cost of a conservative existence construction practical.
