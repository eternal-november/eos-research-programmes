# Institutional recovery in the common execution core

This is the explicit phased adapter for [INSTITUTION](INSTITUTION.md), implemented in [institution_adapter.py](institution_adapter.py). It instantiates the general execution carrier with actual local commands and a total response to Byzantine requests. It does not call the earlier end-to-end `control_epoch` helper and infer nonblocking from the absence of an exception. Its invariant is constructed phase by phase; outside that invariant an unavailable mission has an explicit failed transition and verdict. This is a derived mathematical adapter with executable checks, not a Lean extraction of Python or an assertion that physical isolation and cryptography have been implemented.

## State, observations and move order

The actor universe is the twelve sensor/authorizer identities from the existing two-configuration family, plus trusted administrative identity 12 and gate identity 13. One global B is fixed before execution. It is exactly the prior family: at most one member of each configured sensor triple and authorizer triple, across both configurations. It excludes the administrative/gate roots. Active membership changes in state; correctness of an identity does not change or reset. The bypass remains a separate bounded interface of the same adversary, available even when B is empty.

`World` contains the physical/institutional `State`, a stage, a natural-number tick, actual signature-event records, received packet queues, sampled readings, an administrative input, actor-local histories, a service-age monitor, duty events and a failure label. The stages are `admin → report → endorse → effect → admin`. The tick increments at every transition, including rejection and failure transitions. There is at most one administrative attempt in each epoch. Repeated malformed administration cannot create an unclocked sequence that indefinitely postpones a mandatory effect stage.

Actor i sees only `observe(world,i)`, its own retained local history. An observation contains the public epoch/configuration/institution/mode, current stage and tick, clean-repair acknowledgment, its own received packets with individual public verification results, and its own sensor reading when it currently occupies a sensor role. Only the administrative actor receives the administrative input. Authorizers receive no reading merely because their identity is in the global universe; neither they nor the gate receive x or B. A `LocalVerifier` reconstructs only the valid packets present in this actor's own inbox. Its `verify` method does not inspect a global authentication log or a fault object.

The analyst's global signature-event set realizes ideal authentication: an accepted signature denotes an actual signing event in the model. Correct actor commands produce only their prescribed current messages. A Byzantine `Issue` can create a signature only under that issuing actor's identity; forwarding a `Signature` never adds it to the authentication log. Thus a claimed different signer is not a signing capability. The actors consume the public verification results of received packets, not this global semantic implementation of authentication.

Correct policies are explicit functions of actor and local history. At the administrative stage, the trusted office submits its observed input to the existing power/permission/access checks. At the report stage in live mode, a correct active sensor sends its own current measurement to every active authorizer. At endorsement, each correct active authorizer invokes the existing local median/certificate policy on its own inbox and signs every permitted result. At effect, the gate invokes the repaired assembler on its own inbox and selects the least current certified control. In isolated/repair/ready modes it selects constant control one, subject to the permission cap. Correct sensors and authorizers wait in these isolated modes: the constant-control argument does not acquire an unnecessary fresh-sensing premise.

An environmental move supplies correct sensor offsets at the administrative-to-report boundary and a hostile flow at the effect boundary. In live mode each correct active sensor's offset is in {-1,0,1}. Its reading is x plus that offset; x remains unchanged through administration, reporting and endorsement. The hostile flow lies within the current physical mode's bound. The executable `environment_admissible` predicate checks these input bounds against the installed mode and role map without consulting safety, certificate availability or the output verdict. Sampling is checked after the administrative interface update because that update determines which sensors are active. Noise, faulty requests and hostile flow may be correlated and chosen using the admitted current prefix; no stochastic independence is used. These bounds describe the environment and physical interface, independently of whether control succeeds. Wrong bounded-data assumptions are visible failure cases, not successful scenarios selected after checking the result.

The representation keeps accepted signing events and all correct local inputs, own commands and receipts. It does not describe arbitrary Byzantine subjective memories. Actual requested commands remain edge data; faulty local histories retain a marker rather than treating those requests as a correct actor's memory. The model retains every possible finite Byzantine request at every next stage, so this omission does not constrain subsequent hostile choices. Its other kernel is the selected zero-delay, synchronous, finite-message-per-stage interface. Parsing costs, unbounded traffic latency, real packet arrival times and physical evolution between these stages require a different timing model. Historical signature acceptance proves the attributed event/sample label, not an unqualified physical generation timestamp.

## A total request interface

The decoded request language includes ordinary command tags, finite raw packet batches, own-key `Issue` requests, forwarded signatures and malformed finite data. Unknown tags, absent payloads, unsupported packet types, negative eras, wrong routing and malformed administrative records are rejected as no-ops. An unhashable forged `Signature` is removed by `signature_shape` before any authentication-membership operation. The adapter's normalization is the boundary before the typed `institution_model` APIs; those APIs are not claimed total on arbitrary raw Python objects. The data model covers finite ordinary decoded values, not executable objects with attacker-defined methods or cyclic in-memory graphs.

For any well-formed reachable world, every joint request profile following its correct components has a successor. This stronger nonblocking statement is established by cases on the stage, rather than by exhibiting one successful profile.

1. At administration, the office's observed input is either a recognized typed request or a rejected attempt. Power, permission, access and proposed-configuration checks terminate on finite data. All faulty requests at this stage have no protected administrative authority. Exactly one transition installs a permitted change or leaves the plant unchanged, then advances the clock and stage. The public configuration test quantifies over the entire fixed fault family; it never consults the actual hidden B to choose membership.
2. At reporting and endorsement, every finite request batch has a finite normalized packet sequence. Correct transmissions are inserted independently of faulty traffic; a faulty actor cannot remove or overwrite another actor's packet. Invalid/unknown packets either remain harmless typed inbox material for the public verifier or are discarded before typed operations. Every batch produces the next stage even when all faulty actors are silent, replay messages or submit malformed material.
3. At effect, the gate policy returns either a selected control or a named unavailable-mission result. Both have a physical successor. If no current authorized control exists, the defined zero-input failure transition still incurs the stipulated one-unit withdrawal and hostile flow, and sets the failure flag. It is not asserted safe. For cap one at x=2 and hostile flow -1, this produces x'=0. The counterexample therefore remains in the transition system rather than being removed as an empty run.
4. A failed state has a clocked absorbing verdict transition for every following profile. It produces no additional service. This is a representation of an already failed mission, not an assertion that the real plant safely stops. Post-failure diagnostics or recovery of a mission with a different objective would require retaining more physical behavior.

The ordinary profile type fixes one request component per actor. A profile that changes a correct actor's prescribed command is outside the `Follows` antecedent; `step` identifies that interface error explicitly. Every Byzantine component of a following profile is still unrestricted within the decoded finite-data language. In particular, no missing/invalid Byzantine response is a reason to raise an exception or return an empty successor set.

The transition is a fixed-implementation realization, not a synthesis oracle for arbitrary replacement software. Correct issued commands are the profile entries actually passed to packet generation and effect execution. Checking them against the actor-local policy is the `Follows` condition; the implementation does not overwrite them with a global-state policy. Changing the correct policy activates a new implementation/protocol obligation.

## The invariant that makes failure unreachable

The positive mission begins with x in S={2,...,8}, an admitted B and publicly admitted configuration, norm cap at least two, a recognized physical mode, an empty authentication history, no failure, and a service-age counter of zero. Arbitrary asserted initial signature events are rejected: a nonempty event history must be reconstructed through actual transitions. This prevents a fabricated initial honest endorsement from bypassing the operational provenance argument. Older events generated by earlier epochs remain available for later replay tests.

Maintain the following additional phase facts together; none resets the joint fault family.

At every stage, the signature-event record attributes each correct signature to the correct actor's prescribed earlier action, with its actual era, epoch, kind and payload. The current epoch advances only after effect. Correct actors cannot have signed current-epoch commands under an earlier administrative state, because administration precedes all current reporting and endorsement and occurs only once. Proposed changes are checked against every B in the public family. Thus every installed triple contains at least two correct identities under this same B.

At a live report stage, every correct sensor has a current reading within one unit of the same x. Administration has not changed inventory. At the following endorsement stage, each correct authorizer has both honest sensor reports by the stipulated delivery cutoff. Duplication, replay and recipient-dependent Byzantine values cannot replace the two honest error bounds: an accepted current signature from a correct sensor carries its unique current reading, and there is at most one faulty current sensor. The median bound and envelope coverage C1 therefore apply to each actual local inbox.

At live effect, every correct authorizer has signed all controls certified by its local envelope and allowed by the same public institutional digest. C2 supplies the analyst witness a(x) in every honest local control set. Since the normative cap is at least two, that witness is permitted. Both honest signature events have been delivered to the gate. The repaired assembler first validates each share and only then deduplicates identities; arbitrary invalid/replayed packets cannot erase this support. Consequently the unavailable-certificate branch is unreachable. Every accepted certificate contains an honest authorizer and thus supplies a robust-safe, permitted action. This proves both service availability and safety for the same implemented policy, including alternative controls that a Byzantine authorizer can help certify.

In isolated, repair and ready modes, the physical bound is b=0 and the gate uses u=1. Direct arithmetic gives x'=x while delivering one unit. This argument needs neither a measured median nor fictitious evidence obtained from hidden x. The capacity in repair is one and in the other isolated modes two. Hence the selected action is realizable. The adapter specifically checks an isolated-repair epoch with no fresh sensor readings.

Administrative steps preserve inventory and either leave the interface unchanged or follow the existing guarded mode transitions. Beginning repair requires actual acknowledged isolation; reinstatement requires a ready, clean interface and a newer publicly admitted configuration. The chosen positive invariant retains norm cap at least two across reinstatement, so returning to live mode does not silently lose the common permitted action. Fresh correct keys, sound physical acknowledgment and a reliable service port remain named roots of this conditional construction. They are not inferred from signatures or status names.

The effect transition is x'=x+u-1+b and increments actual delivered work by one. In all positive cases it returns to the administrative stage with x' in S. The age monitor increments at the three non-service transitions and resets on effect, so its reachable values are 0,1,2,3. Exactly one unit is delivered in every four-transition epoch, and every four-transition window of an infinite successful execution contains a service event. No-op administrative input consumes its one scheduled stage; it cannot starve later service. An infinite execution exists constructively: each phase has a next state, each live stage admits a correct offset choice and each physical mode admits a bypass choice. Universal phase preservation covers all such admitted choices, not just this existence witness.

Administrative progress and service are separate. An inaccessible or unpermitted reinstatement can leave the system serving in repair indefinitely. The documented successful schedule constructs actual suspension, isolation, capacity reduction, repair, replacement and reinstatement. Eventual completion of repair requires the clean/access inputs for that schedule; recurring service during an isolated wait does not require eventual repair completion.

## Core and property maps

For the general `Model`, let I be the fourteen actors, F the admitted static coalitions, and X the well-formed `World` states with their histories. Define `correct(f,i)` as i not in f, `observe_i` as `observe(world,i)`, and the local policy as `policy(i,history)`. Initial states have `world.plant.faults=f` and the positive initialization just stated. The action-indexed transition relates world, profile and successor exactly when an admitted environmental move makes `step` produce that successor. The external fault index and the stored coalition agree initially and are unchanged by every transition. Failure worlds remain explicit points of this carrier, excluded by the success predicate rather than by the transition generator.

This is a direct instance of the general carrier, with identity local-history and request maps; it does not infer strategy realizability from a centralized winning set. All actor observations expose the tick, which starts at zero and advances once on every transition, satisfying the observable-clock interface. The protected administrative and gate components have their own actor actions; hostile bypass remains an environmental control interface with the stated physical bound.

The independent property projection retains inventory, physical mode, institution/configuration, epoch, delivered-work count, failure and the service monitor. `check_decode` recomputes clock, fault, inventory and delivered-work changes from the actual edge record. It does not call `control_epoch` or accept its success flag. All non-effect phases preserve inventory and delivered work; effect alone has the balance and delivery increment. Local-history prefix extension is checked separately. The service property is decoded on this same four-phase time scale; no elapsed-seconds guarantee is inherited.

At epoch boundaries, define x_e from the administrative stage, u_e and b_e from that epoch's effect edge, and the effective mode from the completed administrative update. The intervening phases preserve x, so the decoded recurrence is exactly x_(e+1)=x_e+u_e-1+b_e. The live-phase evidence argument supplies `Accepted`/`LawfulAccepted` in the existing Lean theorem; the isolated branch uses the constant-control identity. `recovery_invariant`, `lawful_gate_sound` and the service-count argument therefore apply to the actual decoded recurrence. This is an explicitly indexed macro-step argument: one epoch corresponds to four core transitions, so it is not presented as a same-tick quotient that silently preserves deadlines. The full core retains those four phases and the age monitor.

Duty records are generated by actual epoch start/end events and evaluated by the existing trigger/deadline history predicate. Institutionally valid registration, permission and installed physical effect remain separate. Rejected administrative requests do not perform a valid registration, and logical status changes do not by themselves alter x or the bypass cap. The existing raw institutional machine still represents valid-but-prohibited registrations outside this enforced path. Its presence does not weaken the positive implementation's guards.

The relation to delayed physical control remains the existing context boundary. This adapter has no pending-command FIFO and no drift between current sampling and effect. It does not compose the reduced-capacity recovery mode with a retained radius-one delayed tube. A timed recovery uses its own queue, mode-admission and effect-time evidence contract.

## Executed checks and review boundary

Run `python -B institution_adapter.py`; `run_checks()` returns a JSON-safe dictionary. The adapter checked 1,344 phase transitions over 336 completed recovery epochs, seven initial inventories and six global-fault contexts chosen to exercise absent faults, each active role fault, joint role faults and retained faults in the replacement configuration. These are adapter checks, not a duplicate of the original component's 256-coalition full-cycle enumeration. The public configuration validator still checks its full 256-element family on every proposed installation.

It separately checked 4,200 following joint traffic profiles: all 100 pairs of ten decoded traffic classes for the two current faulty roles, with inactive-fault traffic present, at every stage and initial inventory, and all three bypass choices at live effect. Classes cover silence, unknown/malformed requests, signed Byzantine reports/endorsements, equivocation, stale replay, spoofed honest identity, duplication, wrong era, unhashable signature payloads and non-signature packets. These counts do not claim an exhaustive enumeration of all integer payloads. General nonblocking and support preservation use the structural finite-request arguments above. A large integer report is also exercised without rendering it or relying on a bounded numeric sentinel.

The local-history audit records 4,637 correct action classes. A full carried-evidence example has true x=5, honest readings 4 and 6 and selective faulty reports. The honest authorizers compute {1,2} and {0,1}; with the faulty authorizer withholding, the gate obtains the common control one and the realized successors are 4,5,6. An actual forged-share overwrite attempt at x=2 is rejected without suppressing honest support. The unavailable normative mission with cap one reaches an explicit failed successor x'=0 and then clocked failure verdicts. A proposed configuration mixing fault domains is rejected even when the actual B is empty, demonstrating that admission uses public uncertainty rather than hidden truth. Malformed administrative inputs advance as rejected attempts. Repair without fresh sensing still delivers one unit.

The structural argument and executable checks are author-side work until independent review. They establish the adapter within its declared static-fault, authentication, sampling, synchronous delivery and physical-root assumptions. They do not constitute empirical validation of those roots, arbitrary-memory-corruption tolerance, generic mobile-key recovery, or a whole-program completion verdict.
