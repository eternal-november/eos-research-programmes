## Physical root and node-entry law

There is one root work/authority ingress for the processor's existing20480-work parent compartment. Launch requires the actual full ready cell and absence of an outstanding physical root claim, in addition to the ordinary power gate. A writable busy flag alone cannot open recharge or mint a second claim. The ready/pending cell and any issued private-link work are one partition of that same20480 allocation. An accepted ordinary port child has its own already inventoried source compartment and does not become another CPU parent.

The private address trees have the existing fixed topology and installed C/R/W leaves. A node stores bounded header/phase/busy data and a return-capability qualification. Its entry transition is driven by a real energized ingress, not by reading a stored valid bit. Entry first revokes the old returning qualification, then overwrites the local header/phase from the new request, and only then selects the next branch. The executable uses that newly written node header to choose the branch. Old busy/header words may all be wrong; they do not veto entry and do not themselves generate an ingress. Unvisited data is left unchanged. This is an actual priority-capture primitive with bounded local operations, not an assumption that every routing word was cleared.

One active path uses the same parent claim and pays20 native work per level. RoutedBody calls that path on the real parent’s C fetches, operand captures and R/W accesses. The routed work is debited when performed and subtracted from the later frontend reservation, so it is not paid twice or financed after the effect. A captured native C target retains its actual selected word; it is not rebound when source operands or PC change. Invalid/uninstalled private leaves have zero/no-write outcomes. Missing route work or a stopped route controller retains a real wait; it does not supply nominal instruction service.

The primitive has a fixed root/return cutset. Closing it suppresses new private grants, outgoing offers and architectural-result strobes. A private return signal already emitted carries its captured256-bit payload and original claim. The finite witness has one such live signal, with20 work taken from the parent and no refill path. Its dissipative law loses20 work/q until empty, giving an all-mode conforming tail at most1q even when the CPU clock stops. Dead return authority at stock1 is not empty physical storage. Route access, slot replacement, normal completion and retirement reuse remain blocked until both the actual remaining tail and stored work are zero. Only then is the same depleted WorkCell archived and the slot reused. A separate combined parent/link balance retains delivered work, live link stock and actual link dissipation exactly once. Closing the cut also rejects new private-link emission. The source does not turn residual work into a new reserve or refund it to E/T.

Recharging the root later creates only a new physical ingress at the root. It does not re-energize old link compartments or turn stale node data into an ingress. This no-backfeed/no-rearm relation, the priority entry above, and the actual return cutset are the material source laws licensing lazy overwrite. They are not consequences of the phrase “one token.” The implementation makes them explicit and tests old return rejection after reuse. A physical defect that adds an input path, forks the grant or bypasses the return gate needs its real reach/work projection and receives no positive retirement guarantee from this leaf. Arbitrary native data and index residue is retained within the conforming fixed physical graph; physical rewiring is a different failure mechanism.

Whole-array reset is consequently unnecessary for this selected source. If those entry/power laws cannot be realized in the eventual admitted graph, the alternative is to pay for the actual routing/capture array reset. The5,248,640 bits per bank are not silently included in the smaller bitmap below, nor can a shared block containing the active keeper be erased as cold-side cleanup.

## Actual native-write inhibition and work

The inhibition event denotes completed physical cold-side contacts, not receipt of a requested command or a permission report. It closes parent launch/recharge, every outgoing and architectural strobe, and both the native force path and its high-mobility path. These contacts are ganged to the actual cold-side cut. Their motion is paid by the existing ordinary maintenance fields; the added joint reaction is explicitly checked below. The later reset-cell control debit is not retroactive funding for an initially empty reset reserve.

GuardedNative uses the same captured body, target coordinates and parent cell as NativeWrite. A stopped control clock is not a frozen bit: `flow` can still move the held bit and debits actual parent work at the conservative512/q driver rate. That rate exceeds the current force times the complete bit plus D*i/pose velocity bound. Once the work floor or physical cut is reached, both native force and high mobility are disconnected. No drive parcel is supplied by a new clock call. The retained partial C coordinates are not reset to zero or changed to P.

For an uninterrupted native word, the additional explicit flow debit is at most512*2080/2^30<1. The old one-unit completion charge remains a conservative dissipated margin. With the separately counted640-work installed-leaf qualification, this qualified implementation uses at most20098 parent work, still below20480 with a positive floor margin. Its nominal programme contains no STOREC; its distinct hostile/native suffix is not relabelled an ordinary retirement cycle. A paused drive can consume more than that nominal one-unit flow allowance, but never more than its actual remaining parent work. Such a depleted operation waits until paid retirement.

The source preserves the physical word selected by the captured native address wires. ## A live SET_FIELD child blocks the parent

RetirableParent interprets the actual captured IO instruction. A valid SET_FIELD offer creates SetterChild over the real SettingWriter and the CPU's immutable captured argument view. The CPU parent remains occupied and publishes no architectural completion until the child has finished its literal payload, paid control expansion and actual refill. The child may continue its separately funded native work after CPU power/capture stops. A clock or work failure retains its exact partial state and argument ownership.

The child executes each original payload tick, then its paid bounded cursor/control tick, plus256 fixed control ticks. Two of those control ticks perform actual entry initialization before payload capture; the remaining254 finish stage/control cleanup, including the used cursor bits. Valid payloads still require7486 ticks and119776 work; invalid payloads have the existing shorter total. The underlying setter stays in a non-refilling control phase until those ticks end. Refill uses the actual capped setter charger after child work stops. No new child budget is supplied by CPU reset. The complete nominal child plus refill remains within the inherited1/64 allowance under the stated local clock/bit-port laws.

A native setter tick is a qualified bounded local bit-port/control transition. It cannot perform a new alias read once the actual child-valid/read-enable falls or the native-write inhibit closes. Previously completed ticks may already have changed held settings; those effects remain. The writable child.done word is diagnostic and supplies no completion or quiescence authority. Normal return consumes the actual terminal native continuation, completed paid control path, closed parent/operand aliases and fully refilled slot. In the executable, an exhausted generator represents that terminal native continuation; a running generator remains a live operation regardless of the diagnostic word. Retirement alternatively requires actual native inhibition, consumed child-valid/parent/latched state and a separately funded1/64 read/control-tail closure. The CPU operand block remains owned until the corresponding physical relation holds. A source implementation with a longer outstanding alias-reading operation must replace this allowance; a changed returned flag, done word or clear cursor is not evidence of closure.

In particular, the check starts the cam with valid stale mode7, clear_i4096, parent_aborted false, and a genuinely live setter child paused after twenty ticks. The old controller may issue its abort before the planned clear corridor. The wrapper observes the actual child-valid/read-enable change, closes future alias reads and retains the CPU Capture and argument view. It does not infer quiescence from clear_i or `returned=False`. A separately funded bounded detach acknowledgement precedes CPU operand clearing. Additional probes forge child.done both directly and under stale mode8; neither releases a live alias. A later actual CUT starts the fresh cam-slot timing allocation without refunding or erasing any earlier work or partial state. The subsequent real cutoff/clear sequence recovers the state, preserving the seeded old held setting throughout.

Ordinary accepted IO effects are different. Their captured return record may be consumed, but their actual ports, held WORLD command, conversion job, data record or already emitted packet are not erased by CPU retirement. The WORLD case retains its actual(-100,-100) latch after the parent is retired. Their further physical tails and authority retain the existing ordinary-port owners and suppliers. The new primitive closes only the old CPU return path, not the external world history.
