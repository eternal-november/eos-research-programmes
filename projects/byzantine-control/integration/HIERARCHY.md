# A finite causal compiler and a decidable information subclass

Status: derived compiler and preservation argument, with first-pass executable and Lean support. A checked primary-source theorem supplies the distributed-synthesis conclusion; its synthesis algorithm has not been implemented or executed here. The source/strategy maps, complete-arena hierarchy certificate and positive physical instance are concrete. This contribution does not close the full research program or enact repository acceptance. [HIERARCHY-SOURCES](HIERARCHY-SOURCES.md) records the exact import.

## Scope of the characterization

Fix a finite causal Kernel, finite nonempty command domains, finite initial local-input and observation alphabets, static joint component faults, and complete finite enumeration of observations and effects. Every nominal program interface in this subclass is invoked once per physical tick. The executable fault, world, observation, local-input and command carriers use stable immutable native equality and hashing. Every source callback, local policy interface and consumed judgment must be extensional on that equality: equal carrier values cannot yield different behavior, information or verdicts. Cache/base merging relies on this source well-formedness condition. If two Python values compare equal but a source consumer distinguishes them, use an explicitly tagged carrier before compilation. The declared integer/string/tuple/dataclass source families satisfy this condition; it is not a guarantee about arbitrary custom Python objects. This carrier equality is separate from the event codec's deliberately type-sensitive structured-value semantics.

The source adversary has the stated strong causal power: it may choose faulty commands and independent effects after seeing the current compliant commands and current world, but not future private inputs. The controlled mission combines actual initial validity, world/rights and prescribed-conduct edge verdicts, actual-delivery deadlines, and recurring delivery. Other finite ω-regular monitors can be included in the retained world and objective; this does not permit forgetting a consumed history.

The general unclocked kernel is not identified with this subclass. `compile_kernel` rejects any missing invocation rather than delivering an observable None every physical tick. Changing this restriction requires a new information-preserving adapter. No finite bound on controller memory is chosen by the imported characterization. In particular, the compiler does not put the state of a candidate finite table into the plant and then call the resulting bounded search an unrestricted synthesis result.

For a successfully compiled arena whose complete history system satisfies dynamic hierarchical information, the inspected synthesis theorem supplies a decision procedure and finite-state controllers whenever a deterministic perfect-recall solution exists. This is an effective theorem import with the adapter below. The implemented algorithm decides the information condition and checks supplied finite controllers; it does not pretend to execute the source's synthesis construction. Failure of the information test means this import does not apply, not that the source control mission is unrealizable.

## Decision-boundary compiler

The compiler consumes the maintained `finite_model.Kernel` interface. Its base state retains the same f, physical/kernel state, the current joint observation tuple, actual service ages, and initial local inputs at the first boundary. A game position additionally retains a hidden incoming whole proposed action profile and a declared finite event record. The actor observation exposes only its own initial input and observation at startup, then its own observation at subsequent invocations. Neither f, the other actors' inputs, the hidden profile nor the mission record is automatically supplied to the program.

There is one distinguished root. Its outgoing choice is inert: after the policy family is fixed, Nature selects f, an admitted initial state, the actual initializer-input tuple and the first jointly admitted observation. The root's observation is discarded. This bootstrap adds no physical command, service delivery or elapsed tick. Every admitted fault has a nonempty initial family; an empty family is rejected as a defective instance. An initial violation or missing initial observation becomes a losing completion, not an omitted branch.

At a productive boundary, the players supply one whole nominal command profile. The compiler passes a command to the source effect callback exactly when that executor is compliant under f; other program recommendations are replaced by None. The callback still selects actual faulty issued commands and independent actuator effects, including wrongful effects. The same f governs observation, compliance, effects and continuation. The compiler enumerates every callback outcome, updates delivery ages using the actual delivered-event set, retains the chosen event record, then enumerates every next joint observation. It never forms independent products of local observation projections.

An actual effect with a failing verdict or expired service deadline becomes a marked losing position. An entirely empty effect iterator and an outcome with no following observation also produce explicit losing positions. These terminals have successors under every nominal profile, so empty behavior cannot win. This is the source verifier's first-failure semantics with an absorbing completion: the prefix through the failure and its recorded cause is retained, while later physical behavior is deliberately not reconstructed. Terminal stuttering has no source delivery. Initial selection, missing-continuation markers and terminal stutters are bookkeeping; successful effect edges advance one physical tick. A mission that permits rehabilitation after a recorded violation needs a different monitor/verdict interface.

The callback must explicitly represent any individually admitted primitive adverse move that lacks an outcome. No iterator-based compiler can detect a branch the model silently omitted. A resource guard aborts compilation if its base-state limit is exceeded; an abort is not an unrealizability or completeness verdict. Finiteness and terminating, repeatable callbacks are input obligations.

## Source, strategy and mission transport

For each productive boundary and proposed profile, the target set is exactly the image of all admitted source outcomes and subsequent joint observations, with the explicit failure completion just described. Initialization likewise enumerates every source scenario before choosing a controller response. Induction gives two directions: each source execution has a compiled execution with identical f, source worlds, invoked observations, actual deliveries and consumed event records; each compiled execution decodes to such a source execution or its declared finite failure. The compiler's state-space traversal is independent of the selected policy and includes histories that lose the mission.

Structured event data is encoded exactly once as each source outcome is yielded, before asking the generator for another outcome. Thus a source may reuse a mutable list/dictionary while its successive event values remain distinct; immutable source carriers and event snapshots have separate contracts.

The event projection is an explicit kernel of the representation. By default `EventCodec` retains the complete supported structured event value using distinct constructor tags: None, Boolean, integer, binary64 floating-point bits, string, bytes, list, tuple, insertion-ordered dictionary, set, frozenset, and dataclass record. Tags also apply recursively to dictionary keys and every nested field, so True and 1, or [1] and (1,), remain different event colours. Float encodings retain signed zero and NaN payload bits. A dataclass record retains its class identity and every declared field; a per-compilation registry checks that its module/qualified name denotes one actual class and rejects a collision rather than merging distinct types. Opaque values, cycles, identity-equality dataclasses, undeclared instance/slot payloads and unsupported subclasses are rejected. Finite identity-sensitive event data must carry an explicit identifier; live Python reference identities are not serialized as a supposedly finite alphabet.

The type tags and recursively retained payloads give an injective representation of this declared structured-value algebra. Consequently type-sensitive event predicates and finite omega-regular monitors over these values retain their distinctions; their query class is not restricted to excuse a lossy codec. The default selector returns the raw event and the compiler encodes it once, including when the outcome is a terminal failure. Kernel fault/world/input carriers retain their existing hash/equality contract and are not silently converted to event records. A supplied `event_key` instead deliberately chooses a projection and owes the corresponding preservation argument. The physical instance retains actual delivered quantity in addition to the actual world sequence, proposed commands, delivery set and failure verdicts; it drops duplicate diagnostic fields such as the explanatory faulty-engagement flag. Its exported judgments concern motion, heat, current conduct and actual service. Attribution or a query about the identity of a past engagement would require restoring those event fields. No adverse outcome is discarded because several outcomes have the same deliberately projected image.

The hidden incoming profile prevents a quantifier error. One player must not justify a target edge using profile (0,1), another using (1,0), and thereby count that target as an outcome of (0,0). Every productive target stores the same entire profile used for its edge. `unique_incoming_profile_couples` proves the corresponding component-to-joint implication. Root and losing-terminal actions are deliberately inert and have successors for every profile, so their erasure creates no such incompatibility.

The game observation omits own-action labels. For a deterministic source policy, its compliant commands can be recursively reconstructed from its initializer, observation history and the policy itself. At each invocation evaluate the policy, append that actual own command to the reconstructed local history, and continue. Equal observation histories therefore yield equal reconstructed commands for that fixed policy. Conversely, an observation-word game strategy is a source strategy that ignores redundant own-action fields. These transformations preserve the admitted source outcomes and winning status. They are policy-relative strategy translations, not equality of information sets on all histories generated by all different policies. Static faults matter: a faulty slot's program need not match its actual Byzantine actions, and that slot does not silently become compliant later.

Finite-state implementations are preserved by substituting the locally determined output into the source memory update. `own_action_memory_transport` and `own_action_command_transport` prove this substitution for arbitrary state, observation and action types. Initial memory must be a function of the actor's actual local initializer input. The game compiler exposes those inputs faithfully; it does not silently replace a deliberately lossy fixed initial-memory interface by perfect recall. The positive instance uses the fixed local input `boot`.

Initial validity, actual service ages, fault-indexed response duties and global protected outcomes retain their original meanings in the objective. Recurring obligations are delivered-event Büchi conditions, with a separate condition for each required service; hidden fault-dependent relevance remains in the verifier/objective, not the policy. The implemented supplied-policy replay checks every reachable edge and every reachable service-free cycle for unbounded recurrence. It updates the hypothetical finite program memories at all slots without reading f; only the physical effect interface masks faulty recommendations. Thus an actor is never given the actual fault to decide its update.

## Checking the whole information structure

The fast certificate checks every compiled position for a fixed observation-refinement order. If player i's observation determines player j's observation, the same factorization holds for their complete observation words. A total such order certifies hierarchy on every history. Common observations make all information sets equal, even while the true world, fault set and objective colours remain hidden. `common_observations_same_information` and `refinement_orders_information` check these logical steps.

If that sufficient positional test fails, the implementation performs an exact finite triple search. For each i,j it follows an actual path and two alternative paths from the root. The first alternative must match i's observations of the actual path; the second must match j's. Two persistent flags record whether the alternatives differ on the other observations. Reaching both flags produces two incomparable information alternatives. If every finite triple state is exhausted without such a witness, no history violates the required total ordering. The checker independently replays returned witnesses. Each path keeps its own initial f; different paths may have different faults. Known-fault checks and a selected policy's reachable graph are not substituted for this combined arena.

Regressions exhibit a game whose individual known-fault arenas are hierarchical but whose unknown-fault union is not, independently varying private initializer inputs, one safe private refinement of public information, empty continuations, a later hostile outcome following a harmless one, bounded and unbounded starvation, and missing-call rejection. A separate game reveals the first player's private information before giving new private information to the second: the information order changes, the positional test fails, and the complete triple search certifies the dynamic condition. Adding own-action observations to an otherwise common-observation arena produces an explicit information fork, illustrating why the strategy rewrite is not a universal epistemic equivalence. The primitive profile regression records the different-component/different-profile obstruction. Actual source-kernel regressions emit pairs of type-distinct events with the same physical successor, proposed profile and observations; the compiler must retain separate target positions and both event colours on subsequent transitions. Unsupported or ambiguous event values are tested through the compiler and must raise an error. None of these negative information verdicts is reported as physical unrealizability.

## Public evidence without a physical execution gate

The physical specialization has two independently commanded brake paths, at most one index in the union of faulty planners and actuators, an independently faultable motor/output chain, and a one-tick FIFO. A compliant planner remains subject to its command duty when its actuator is faulty. The dynamics are the declared floor-quantized family with c=1/2, T=6, normal input 4, brake strength 1, lower normal speed 1, upper speed 10, heat bound 4, thermal retention 1/2 and heat coefficient 1/10. The threshold is 3, intact scalar error bound 1, response threshold 2 and effect delay 1. These are discrete model parameters, not calibrated hardware.

The changed observation interface supplies the same finite report vector to both planners on every invocation. Each vector has three declared source paths with at most one affected path. Intact paths supply their threshold bits under the error-one sensor relation; faulty bits may be arbitrary. Majority gives a common LOW/HIGH label: LOW is possible exactly at x<=3 and HIGH exactly at x>=2. The executable checks the exact image for each source-fault mask and every speed in the physical carrier. The source-fault identity can be erased for this label interface because its possible labels have the same image for each admitted mask. A raw-report controller can consume distinctions lost by this frontend; no strategy reflection for that richer interface is claimed.

Reliable timely common delivery is an explicit communication/input premise. It does not make the report content trustworthy, nor does it mediate motor or brake effects. A physical channel implementation would have to establish that premise under the declared failures. This is a deliberately more structured information subclass of the earlier local-report family, not a claim that unreliable private deliveries already have hierarchy. Every nominal program sees the same label and fixed initializer; hence the complete compiled arena satisfies the hierarchy certificate without exposing the true fault, speed, heat or commands.

The existing parameter theorem has nonempty margins here: normal-supply slack 3/2; surviving-force slack zero; delayed growth bound A_2(4)=10; thermal slack zero; and the factive ON lower bound 3-1=2. The policy is LOW->OFF, HIGH->ON. Initial speeds are 0..4 for a faulty motor and 1..4 for a normal motor, heat is 0..4, and queues are OFF. The integer proof can also be read directly: a prior sample at least four forces the surviving brake ON; otherwise two unbraked updates from at most three reach at most nine. Normal input four preserves positive speed against both brakes, and two engagements at speed ten preserve heat four. All source, planner, actuator and motor projections use one static joint scenario.

The source verifier checks the selected policy on 938 states and 29,033 edges over fourteen reduced fault classes. The complete compiled arena is built from every nominal profile, not only this policy, and includes its losing outcomes. The separate compiled-policy replay then checks the mapped controller. Counts and source hashes are in hierarchy_results.json. Neither replay is reported as execution of the imported general synthesis algorithm.

## Actual-service composition

A faulty motor/output chain can withhold every delivery, so one such device cannot promise unconditional positive delivery. For J>=2 distinct devices with at most p<J faulty motor/output chains, retain the same local physical relation and one global fault whose projections meet the local bounds. Broadcast the full finite tuple of target labels to every nominal program. The target-j policy extracts coordinate j using its fixed identity; it receives no true state or fault. Thus the fleet still has common observation information while every physical output remains independently faultable.

Every global transition projects to an admitted local transition under the corresponding projection of that same f. The local policy and FIFO invariants therefore hold on the same global run. Each normal output actually delivers its next speed, at least one; faulty output is nonnegative. Summing gives actual service at least J-p per physical tick. Separate heat stores sum to at most 4J. A smaller common cooling resource requires its own summed-load invariant and is not obtained by renaming the separate stores. No probability independence is used.

`PublicFleet` instantiates this interface for two devices and at most one bad motor, including every permitted joint role projection. Its probes include initialization and mixed high/low interior states, every admitted public observation there, and all physical outcomes. They check actual aggregate quantities and the common-view projection. The general product proof and local invariant, rather than these probes, establish the all-run J-device claim. A full fleet graph is not claimed to have been enumerated.

## Boundaries and reproduction

Variable private initializer inputs or independent private sensor refinements can create incomparable information despite later common reports. One extra private refinement at a single player with all others receiving only the common part preserves a fixed order; multiple refinements require the actual full-arena check. Adding own-action labels to observations on every possible arena history can also change hierarchy, which is why the policy-relative reconstruction matters.

The stronger imported theorem used here permits hidden objective colours. The recurring-hierarchy alternative has an additional observability requirement and is not used. Randomization, mobile corruption, asynchronous absent invocations, unbounded numeric messages, unrestricted continuous plants and post-failure recovery are outside this exact import. A failure of one of these hypotheses reopens the adapter; it does not undo the scoped positive family or prove a general impossibility.

Run `lean theories-and-designs/byzantine-control/integration/Hierarchy.lean` with Lean 4.33.0 and `python -B theories-and-designs/byzantine-control/integration/hierarchy_model.py --check` with Python 3.12. The five Lean declarations have explicit axiom reports and introduce no custom axiom. The Python report binds the compiler, proof, documents and reused Kernel/checker source. `--write` regenerates the report only after a reviewed change. The whole-program entry point and completion judgment remain outside this component's authority.
