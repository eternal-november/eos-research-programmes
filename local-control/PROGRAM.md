## Source state, actual code and primitive boundary

For each fixed design d, the machine has a padded array C of L192-bit writable cells, a finite256-bit register array R, a finite256-bit working array W, a program counter, a bounded64-bit retired-instruction counter and ordinary power/halt state. Instruction fields are an8-bit opcode, three24-bit register indices and a signed112-bit immediate. All2^192 cell words, including malformed code, belong to the source alphabet. Input records, captured requests, raw ADC words, calibration operands, assembled replies and cache words remain external I surfaces. Four-limb receipt assembly occurs inside one origin's I before atomic publication of the complete256-bit word; independently changing limb reads do not implement the one-word comparison operation.

The intended P(d) occupies3315 cells in the checked version. L8192 therefore means196608 physical image bytes, not8192 bytes. Its unpadded instruction content is79560 bytes. A192-bit symbol and key k<160L produce an encoded reply k·2^192+symbol of at most213 bits at B80,L8192, fitting the256-bit record with a distinct all-ones unavailable sentinel. Transfers pay three64-bit limbs per code cell and four per reply/private word. The prior64-bit/byte-symbol acquisition example is not reused under a new name.

The generic transition fetches C[PC], advances PC and executes the decoded ordinary instruction. Loads/stores, signed modular arithmetic, branches, calls, returns, actual C loads, C stores and bounded raw I/O have explicit meanings. A malformed opcode is bounded inert work; invalid register/memory accesses have explicit zero/no-write behavior; an invalid PC or exhausted call stack halts. C stores exist for arbitrary code, although the intended source emits none. Launch and completion are separate. A funded launch latches the actual instruction cell, private operands and return location; at most one instruction is pending per processor. Completion samples its raw I operand at the declared strobe and applies the latched operation even after power loss or reset. Reset does not delete that object, and later C/R writes do not rewrite it. The reservation witness comes from HYBRID's physical energy account; this module does not establish that account. Atomic step is a convenience for launch followed by completion. A timeout suspends further interpreter execution without reverting any previous C/W mutation, command, request or publication. Physical queues and held effects are outside this private state. Runtime arrays, bounded queues, held records and converter state are finite for a fixed design; unbounded event/publication/step traces in the checker are provenance instrumentation, not program memory. The bounded-step timeout check is an explicit prefix cutoff; a deployed pause/preemption additionally needs the stated real-time bound or remains a timing-fault/boundary case. Reset sets the declared PC entry and releases halt; it does not repair C, clear W/R/I, reset the retired counter or cancel external effects.

A hardware instruction counter is an actual per-executing-processor register, incremented modulo2^64 on that processor's completed instruction. It is neither a host/bank-wide sum nor a counter that another powered cartridge can advance. It is not the unbounded checker step count or a read of analyst time. Its unknown offset cancels in a frame difference; finite-width reuse is proved only while a frame contains fewer than2^64 instructions. The physical counter has no input-record, primary-clock, DMA or sibling-update lead in this source map. Direct processor-state intrusion may change its offset, and a counter-circuit/oscillator defect may violate its step/rate law; those are separately represented powers, not names assigned after a bad outcome. An implementation where an input-only writer can spoof the counter read is a different interface and cannot waive intact-executor duties by relabeling that writer. Corruption of this execution/timing state remains an actual fault. A source lacking the stated local counter/rate relation needs a different pacing refinement; an arbitrary claimed timestamp cannot replace it. After an offset change, a newly reset program captures a new local start; no comparison to a pre-repair offset is used. An offset change within a frame invalidates that frame's pacing conclusion and remains in the actual source history. Power loss freezes retirement but not physical time: every repowered activation takes the reset/formation path, and source caches/receipt circuits still need actual invalidation, expiry and queue drainage. ADC conversions, delayed packets, physical motion and energy consumption can advance without any instruction retiring. The check model has an explicit physical-elapse transition and verifies a halted CPU's pending conversion/reply completion without changing its counter. The nominal instruction-rate lower bound applies only while the required powered processor and bounded I/O/preemption conditions actually hold; it cannot hide an unbounded pause.

Each raw I/O operation is narrower than its consumer. A fast comparison consumes one actual scalar word and returns a Boolean; a reply comparison compares one complete encoded word for equality. Neither returns a median, truthful value or permission. Raw source operations capture one physical request slot, compare or arithmetically transform one I operand, select/start one actual head conversion, observe its completion bit, offer one record to a fixed physical lane, or invalidate the local cache field. Selection, key decomposition, encoding, calibration addition, fair polling and publication loops are instructions in C. The head/route map must establish physical target and quantity binding. A common receiver remapper, target-controlled read server or unrenewed programmable decoder does not satisfy this ABI.

One Machine represents one cartridge processor. Processors on one bank share that bank's physical force/energy caps and origin identity. Pending operands, PC/counter and flags fit a32-word256-bit metadata allowance beyond R/W; trace logs are checker-only.

The maintenance command is a bounded46-bit record carrying actual route, side, cam/mode effort and one selected stroke field/index/effort. Nominal instructions construct it in W and perform one ordinary record send; they never transiently clear the applied force while computing its replacement. CYCLE's raw contact routing, latency and held-record semantics supply the physical interpretation. This does not restrict the parent's adversarial physical overapproximation to the nominal record format; independently available hostile paths and arbitrary-code effects remain within their declared caps. Any implementation of the held-record decoder by mutable software requires that software's renewal; fixed finite decoding is the declared elementary circuit option.

## Elaboration and nominal refinement

The source subset consists of finite integer expressions, named variables, W/C array reads, W assignments, conditionals, while loops, returns and nonrecursive procedures. The compiler assigns disjoint finite register intervals to procedure locals and temporary expressions. Calls write actual argument registers and use a bounded stack in W; the call graph has depth6. Structured branches and loops elaborate to jumps and ordinary comparisons. No stored instruction carries a Python function or an intended-program predicate. Encoding/decoding is checked for every emitted cell, including signed immediates.

A separate definite-assignment pass checks every source procedure: formal parameters and previously assigned locals are the only nominal register reads. The nominal refinement proof is compositional. Literals, names and array reads establish their designated result register; the arithmetic/Boolean cases follow the bounded-word operation relation. Short-circuit branches preserve the selected expression's result and skip only the unused branch. For assignments, the compiled address calculation followed by STORE changes exactly the named W word. The conditional jump selects the same branch; for a loop, induction over the displayed decreasing variant composes the expression/body refinements. A call copies actual parameters into the callee's disjoint interval, saves its actual return address and uses the callee induction hypothesis; nonrecursion supplies the stack bound. Returns restore that saved address and place the result in the explicit return register. Raw I/O is related by the same actual operation and operands, not by whether it succeeds. These clauses give finite-segment action and W-state refinement for the complete source at its stated source-operation assumptions.
