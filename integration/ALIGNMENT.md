# Operational alignment of evidence, signing and control rows

Status: derived adapters with executable checking and fifteen Lean declarations. These applications close specific interfaces between [STRUCTURE](STRUCTURE.md), the maintained source-evidence construction, operational quorum signing and the recovered signed-broadcast baseline. They do not assert a new quorum threshold, unrestricted protocol synthesis, empirical cryptographic security, repository acceptance or whole-program completion.

## The common comparison

The source objects are actual causal kernels with a single retained fault f, local observations, issued commands, independently admitted hostile effects, initial verdicts, edge verdicts and actual delivery. The target is the shared-variable row construction: one variable for each actor/local-view occurrence, universal quantification over the actual alternatives of that scenario, and one assignment chosen before f. The already established supplied-Q and local-memory scope remains in force.

Alignment carries four maps: the actor-local observation encoder; the actor-local command decoder; the analytic state/fault projection; and the transition correspondence. The analytic projection may inspect f; neither runtime map may. Issuance and receipt are different event fields. A support test is a verifier predicate, not a mechanism that compels an independently controlled actuator.

Integration's Assembly.lean and APPLICATIONS.md provide the general bridge from these homogeneous Kernel interfaces and their joined assignments to CoreBridge source rounds, local programs and runs. The present artifact supplies the missing application-specific fields and checks. It does not edit those integration components or infer an implementation from separately compatible-looking premises.

## Ordinary quorum rows with separate executor and key failures

The concrete SigningKernel has four identities, binary values and a fixed slot/context. Its fault is the pair f=(E,K) of compromised executor and key sets, with |E∪K|≤1. The executable includes thirteen role scenarios: no compromise, or executor-only, key-only, or both roles at each identity. Kernel.compliant depends only on E. A key-only compromised actor therefore still follows its local program and owes its protocol duties.

The certificate projection uses B=E∪K, because either compromise permits authentic signatures from that identity outside correct signing discipline. This projection is adequate for the imported certificate-exclusion judgment. It is not a quotient of the entire execution problem: E and K remain separate in the source, its local observations and its rows.

A state contains actual authenticated signing facts and each executor's own code-issued log. These are not identified. Key-produced signatures enter the authentic history without being inserted into an intact executor's private code log. For identities outside B, code-issued and authenticated own facts agree. The protected substrate assumption is attribution for identities whose executor and key are both intact; it is not an assumption that every valid signature records compliant issuance.

Each invocation supplies one identity with a request value and its own code log; other identities receive no invocation. The local command is SIGN or REJECT. The selected protocol contract implements the existing own-history guard: sign if the log is empty or contains only the requested value, otherwise reject. A different compliant command is an explicit protocol-contract violation; this specialization imports that signing program rather than claiming it is the only useful signing strategy.

Every actual command, including an invalid compliant command, has an effect. SIGN appends an authenticated fact and, for an intact executor, its code-issued fact. REJECT leaves these facts unchanged while the round occurs. An identity in B can additionally produce either or both binary signatures independently of the scheduled request, including during a round with no invocation. Executor compromise grants this own-key signing ability even when the key field is not separately compromised. Those events are retained, not blocked by the local guard.

The supplied envelope consists of histories exclusive outside B, matching code histories outside B, and consistent code logs at intact executors. The initial histories are empty. The compiled relations contain 24 actual local variables, one for each identity, possible intact code-log view and request value; each nonempty scope is unary. Their join extracts exactly the existing local guard. The fault label and role distinctions remain in the scenario constraints, not in the runtime lookup.

The analytic map sends the source state to its actual authenticated fact set and f to B. Each actual round serializes its command-produced signature, if any, and autonomous adversarial signatures into existing quorum_alignment.step events. Each primitive append is either locally guard-licensed at an intact identity or belongs to B; each rejection maps to a fact-preserving step. The resulting fact set equals the mapped actual successor. This is a macrostep-to-finite-event correspondence, not equality of physical time and signature-event counts. Order and duplicate events are deliberately forgotten because the own-set guard and certificate queries do not consume them; chronology or signing-deadline claims would need a richer carrier.

Alignment.lean proves the executor/key projection, the local guard characterization, actual-append equality with the imported issue operation, preservation by compliant issuance and by arbitrary sequences of compromised-identity events, and receipt exclusion using the existing theorem. The source code independently computes its bit-level effects and compares them with the imported operational updater.

Receipt is separately generated as any subset of the actual authentic facts. Acceptance requires three distinct identities for one value. This map discharges ReceiptSound before invoking certificate exclusion. It does not test agreement in the acceptance predicate, claim that a signature proves the payload's physical truth, or turn receipt into issuance. Cross-receiver and cross-time exclusion use persistent authentic facts and the same B.

### Safety and service have different premises

The row construction proves guarded signing and ordinary certificate exclusion for every admitted request, autonomous signature production and receipt choice. It does not guarantee that requests agree or shares arrive. The executable retains the split-value stall: the three intact identities first sign 0,1,1, the faulty identity withholds, and later opposite requests are rejected. Neither value obtains a three-share certificate. Idle receipt-free continuation is also admitted.

For a concrete positive publication contract, start a fresh empty slot, request the same known value from each identity during four scheduled request rounds, and require that every authentic share issued by an identity outside B be delivered by the fourth cutoff. All hostile executor choices and autonomous signature subsets remain possible. Every identity outside B signs that value, so at least three such shares exist; every cutoff bundle satisfying the delivery premise contains a certificate. The checker explores every terminal signing state of this sweep and every qualifying authentic receipt subset. This is a four-request publication bound under explicit common-value and delivery premises, not consensus termination under arbitrary requests.

The support specialization is therefore actual: shared local row variables construct the guard, the transition map establishes Exclusive, actual receipts establish ReceiptSound, and three-of-four supports supply honest intersection and availability. Only then does the ordinary Q3 theorem apply. No physical effect gate is introduced.

## The operational BFT baseline has a different certificate justification

The maintained digital_model source has three participants, at most one faulty identity, two signed-message decision rounds, and a third-round terminal-publication cutoff. Its two-share terminal certificates do not satisfy ordinary Q3 honest intersection. Their soundness uses the already proved D2 agreement of correct decisions. Treating them as a three-of-four signing quorum would be a false transfer.

DigitalProtocolKernel is an explicit implementation embedding of that source. Local observations encode the source's actual own-input/own-action/receipt history; a public finite codebook decodes commands into the source's propose, echo, terminal, wait, retain and observe actions. The executor fault is the source's original fixed faulty identity. The embedding's admissible program contract is the existing local_action function. Other compliant instructions enter an explicit immutable DigitalFailure state rather than being silently normalized into successful executions. It retains the last valid Prefix and the actually issued masked command tuple. Every kernel method handles this state: its initial verdict rejects it as a valid start, its ongoing verdict remains failed, its observation tuple is all None, and every continuation is an absorbing failure with no delivered service. Absorbing events retain the original failed command, phase and epoch rather than overwriting them with later absent commands. The source round's invocation-memory update is committed before failure and held during subsequent absent calls. This gives exact source behavior for the imported protocol, not strategy-complete synthesis for alternative broadcast algorithms.

For every source prefix the adapter constructs the row on its compliant actor/local-view variables. Its sole admissible tuple is computed locally by the imported program. Shared variables agree across fault and input alternatives. The singleton row characterization follows from the explicit deviation verdict and the universally checked successor relation; it is not a guess that arbitrary local programs compose.

At a nonterminal prefix the kernel's complete successor set equals digital.successors, including selective delivery, Byzantine signing and late terminal attestations. At the successful phase-four boundary it supplies an explicitly completed absorbing state. That stutter emits no new decision, certificate or service event. The rank 4−phase strictly decreases before completion. Initial coverage, nonempty successors and that rank give finite-slot completion; the actual decision and evidence cutoffs remain logical rounds two and three. The comparison does not turn a completed slot into an endlessly serving machine.

The state projection retains terminal signing facts for the current epoch. Proposal and echo events map to stuttering in this terminal-fact projection; terminal send and late faulty signatures serialize into the generic guarded-signing updater. This preserves the factual history and correct-signer exclusivity. Every public receipt remains a subset of actual terminal issuance. The generic QuorumAlignment certificate predicate is instantiated with two-element supports, then mapped to Digital.Certificate using actual terminal provenance. Theorem digital_receipt_row_sound uses Digital's legality/agreement theorem for the additional step to the common correct decision. digital_cutoff_available uses actual delivery of the correct terminal shares, not merely their existence.

A checked obstruction removes the required correct echo behavior while retaining exclusive honest terminal signing. The two honest participants can then decide differently, and the faulty signer completes two conflicting two-share certificates. This demonstrates precisely why Q2 plus own-history exclusivity cannot replace D2 for this baseline.

The adapter checks all 117,017 generated prefixes, all 117,010 nonterminal source edges, the completed stutters, all actual receipts and the command-deviation branch at every compliant occurrence. Its 586 local variables reconstruct the supplied protocol. Repeating fresh epochs and preserving earlier entries remains the already established Digital.lean ledger result, with the same fault and fresh context tags; a finite one-epoch table is not claimed to be a complete new implementation of arbitrary unbounded ledger histories.

## General source and witness alternatives become the same control rows

The evidence carrier is the existing Hypothesis relation

\[
H_e(x,B)=F(B)\ \land\ \forall s\notin B,\ c_s(e,x).
\]

A component constraint may express a nominal measurement, calibration/pose relation, or a nominal physical relation. It is consumed only for components outside the same B. The interpretation of c and actual-world coverage are premises to establish, not consequences of receiving or authenticating a report.

For a joint command a, define the effect judgment

\[
L(x,B,a)=\mathrm{Allowed}(x,B,a)\ \land\
(\exists y\,T_B(x,a,y))\ \land\
\forall y\,[T_B(x,a,y)\Rightarrow Q(y,B)].
\]

The evidence row is the intersection of L over H_e. The imported actual_hypothesis and robust_decision_sound theorems establish actual-world soundness; Alignment.lean instantiates them with permission, nonblocking and all actual successors. When several actors have different views, the compiler retains the jointly admitted observation tuple and identifies only each actor's own repeated variables. It does not replace that joint family by a product of independently selected per-actor fault hypotheses.

The finite application has two independently realized output devices, exactly one faulty actuator, and three source channels with at most one faulty source. The eight admitted f values retain the actuator and source identities together. The sole planner is compliant in this specific evidence experiment; the separate structural enforcement family supplies fallible-planner cases. Every actuator and source can fail in some admitted scenario. An intact source reports the actual bad-actuator mode; a faulty source may report either bit. That nominal sensing law is an explicit calibration premise.

The physical command selects one output device. An intact selected device delivers one unit. The faulty device independently emits zero or one, whether selected or not. Thus selecting the intact device forces actual delivery, while selecting the faulty one admits zero delivery. The same command is checked against the permitted-route set. No certificate, sensor vote or permission predicate filters the faulty output.

To instantiate the general Hypothesis signature exactly, the component universe contains both actuators and all three sources. The world variable x is the physical bad-actuator mode. For each intact actuator i, the nominal constraint is x≠i; for each observed intact source s, it is report_s=x. With exactly one faulty actuator, these constraints force x=f.actuator. The adapter proves this equality by exhaustive construction, then projects (x,f) to the same compiled fault-labelled scenario. It therefore drops only a redundant coordinate, not the fault identity that determines intervention.

The mode coordinate x is not literally the Kernel world or Node. The source scenario also retains probe stage, local memory and service age. In the mode-only hypothesis calculation, the legal-action predicate \(L_\sigma(x,B,a)\) closes over that current source scenario \(\sigma\) and invokes its complete Outcome relation, permission verdict and actual-delivery monitor update. Equivalently, the generic EffectLegal theorem may use the augmented carrier \(\widehat X=(x,\mathrm{stage},\mathrm{memory},\mathrm{age})\), with the initial hypothesis restricted to the current scenario fiber. Successors range over the full augmented carrier; they are never projected into the current fiber before safety/service is checked. The executable source_scenario_legal evaluates this actual successor predicate directly. A regression holds mode, fault and report fixed while changing service age from zero to one: a possibly withholding route stays in the deadline-two envelope at age zero but leaves it at age one. Thus no identity between the mode-only and full-state carriers, or service theorem based only on the mode, is inferred.

For every raw report vector, the source-alternative intersection equals the action set obtained by the generic kernel compiler. The three reports determine which actuator to avoid, but need not identify the faulty source: report 000 retains four different source-fault labels with the same permitted robust choice. Keeping only the first report makes the selected Q problem unrealizable; retaining all three makes it realizable. Forbidding the needed route makes the same problem unrealizable despite accurate evidence and unchanged physical capabilities.

The majority label and raw-report interfaces happen to have exactly one winning decision rule each in this finite family. The checker proves the commuting action map on all eight raw vectors, so strategy reflection for this family follows from unique forced commands. It does not upgrade the earlier brake threshold quotient to raw-report completeness or assert that arbitrary evidence labels preserve every distributed strategy.

### Passive refinement and active sensing

A passive evidence refinement strengthens the nominal constraints while leaving the fault family, actual transition, permission law and timing unchanged. Existing added_evidence_refines and evidence_expands_safe_actions then apply. Alignment.lean also proves the local implementation transport: if each actor can locally forget its new observation to obtain its old one, pulling an old policy back along that map preserves its robust row in the unchanged kernel. An analyst's pooled inference is not such a local map.

An active probe is a command with effects. In the checked instance, inspection changes the observation stage from one source bit to the full report vector and consumes the compliant routing opportunity during that tick. Autonomous faulty output remains present during inspection; the adversary may withhold it. The inspect-then-route policy therefore fails a service deadline of one but satisfies a deadline of two and then continuously routes to the intact device. The changed verdict arises from the actual service-age transition, not from treating information acquisition as free passive refinement. This is a particular policy and timing comparison, not an all-policy impossibility theorem for every possible active-sensing interface.

The imported scene/witness example is also translated into action rows using its actual witness_effect function. Equal reports alone give an empty common safe-action row; adding pose gives a singleton row at each calibrated scene; admitting the uncalibrated scene makes one witnessed row empty again. Pose, registration and reported content do not establish calibration. This is a one-step witnessed-control correspondence, not a validated physical detector or an unbounded dynamics claim.

## Verification, imports and boundaries

The closest support was inspected before these adapters were developed: QuorumAlignment's issuance, persistent facts, receipt and availability definitions; its finite operational updater; Evidence's Hypothesis, Robust and refinement theorems plus scene/witness effects; and Digital's actual source transitions, local program, terminal provenance, agreement and ledger theorems. Those unchanged Lean modules were recompiled as imports. Their primary-source assessments remain [SOURCES](../research/SOURCES.md), [evidence_sources](../research/evidence_sources.md) and [digital_sources](../research/digital_sources.md). This session does not silently refresh every external citation in those historical assessments; their reported primary inspections remain scoped to their stated dates and passages. The new claims are adapter derivations, not novelty claims about quorum systems, secure estimation or Byzantine agreement.

[Alignment.lean](Alignment.lean) supplies fifteen checked declarations. [alignment_model.py](alignment_model.py) constructs the actual maps and [alignment_results.json](alignment_results.json) binds the results to normalized source hashes. Run the executable with --check to reproduce them. The failure-continuation regression imports the actual adjacent core_bridge.py and records its normalized hash and the imported source-kernel hash. In an isolated worker where that integration module is absent, pass --core-bridge with its read-only path; the test never substitutes a mock or copied reimplementation. It exercises initial_boundaries, prepare, profile(kernel,tables,boundary), masks and core_successors on actual protocol prefixes at every phase and fault/input setting, then perturbs compliant commands and advances their failed boundaries repeatedly with changed ghost values. Positive initial successors are compared with the original protocol; failure provenance, committed memory, absent invocations, unchanged fault identity, immutable node keys and zero future delivery are checked. To compile Lean, build Structure, Control, Evidence, Digital and QuorumAlignment into a private build directory, put that directory on LEAN_PATH, then compile Alignment.lean with Lean 4.33.0. These imports are mathematical dependencies, not a dependency on the old protected physical gate.

The trust boundary remains explicit. The Python interpreters are not extracted from Lean. The compiled signing relation is exact for its supplied envelope and imported guard contract. The digital kernel is exact for its supplied protocol, not every possible protocol strategy. The evidence experiment assumes its nominal measurement/effect laws and declares its intact planner. No map installs hardware, supplies missing keys, validates real calibration, establishes legal recognition, creates a reliable universal actuator, or turns mathematical certificate acceptance into physical enforcement. Independent review of the new adapters and repository acceptance remain separate obligations.
