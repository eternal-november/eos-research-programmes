# Addressed reconstruction with fallible maintenance paths

Status: derived construction and operational proofs for the admitted disjoint-path source subfamily; selected store, timing and schedule statements are checked in [Restoration.lean](Restoration.lean). The joint safety/service theorem, precise decoder implementation and their independent integration are separate I/C/V responsibilities. This result repairs writable target execution and consumed influence, not every hardware failure or the maintenance tools themselves.

## Program, image and the nominal primitive boundary

Each target has a finite list of behavior-relevant writable addresses A_i. An address stores a bounded-size source word or block. The image contains the actual selected program bytes π_i(d), local control-flow/data initialization, recognition/configuration, receipt/admission state, local queued commands and bounded phase/cache fields needed by that program. These may be grouped into finitely many bounded blocks, but grouping does not erase their bit cost. The nominal write capacity B_write and per-block size b_a must justify the declared write duration, for example ceil(b_a/B_write) ticks. The illustrative m=8 groups program/interpreter bytes, control phase, model/configuration, admission/receipt buffers, query phase/cooldown, local query transmission queue, local command transmission queue, and clock/epoch/cache state into eight bounded blocks; this is not a claim that an arbitrary estimator fits eight fixed-width machine words. The bit bounds are consumed parameters of that exact discrete source.

The program's correctness is not an image premise. I/C must identify the program, its bounded runtime state and its response law. R proves that actual stored bytes equal the selected image and that the permitted initializer is executed. An initializer depends on d and legitimate local inputs/clock phase, not true x, θ, γ, fault/cure identities, or future opportunities. A broad initial evidence region is the already-maintained source enclosure proved by C, followed by new acquisition and decoding proved by I. This is an initialized joint induction, not a claim that overwriting memory creates valid evidence from nothing.

Every nominal maintenance tool receives its own image/schedule/clock data at commissioning. They may be corrupted under the joint source scenario. If the tool or its image has ever been corrupted, its reachable footprint stays in P and this theorem does not assume that tool recovers. A shared source that can corrupt many tool images is one common cause with all those footprints. Different serial numbers do not multiply independent survivors. No named tool is guaranteed intact: the positive theorem quantifies all allowed footprint placements. The required primitive is local bounded physical write/halt/boot behavior, not an omniscient enforcer or a primitive successful repair.

The general persistent set P also includes irreparable hardware targets and retained write/effect capabilities not removed by the declared transient access relation. Its cardinality is a joint footprint bound. The numerical branch uses |P|≤1; this does not permit one bad-tool target plus an additional unrelated permanent hardware target while keeping r=1. Faulty reporting credentials remain in the distinct cumulative evidence support; any credential with actual installation/effect reach belongs in P or active A until genuinely removed.

## Local finite sequence

The tool follows a fixed per-target schedule, without a corruption test. At a scheduled start it issues halt, waits the primitive halt duration, writes every listed image/initialization block while keeping halt applied, waits every bounded write completion, and then boots. Halt suppresses the target processor's instruction execution, internal memory writes and new command issuance. The actual physical hold can retain an adversarial last output, so the whole target is conservatively unavailable/arbitrary during the extended maintenance interval. Neither halt nor a local queue overwrite clears the world queue.

While halted, resident malicious code cannot rewrite completed cells: that conclusion comes from the explicit halt relation. A separate hostile tool, DMA engine or remote installation capability is not silently stopped. Its reach must be covered by halt's actual source specification, remain in current A/P, or be excluded only by the declared primitive opportunity relation. Concurrent writes to the same cell obey the source's actual completion order; an adversarial final writer can defeat installation. The theorem's uncontested interval is a condition on primitive access/availability, not a predicate saying installation succeeded.

After boot, the selected program discards preboot receipts/partial computations and starts its actual new inquiry. Local stale network packets remain adversarial inputs under I's finite admission/freshness rules; the reset does not clear another agent's memory or erase valid signatures. For the concrete I binding, the postboot program first waits the twelve-tick old-query drain, clears the new epoch slots, then starts the fresh eight-tick query/processing round. Thus T_I=20 includes drain and actual new evidence rather than presuming a trustworthy query epoch. Reporting credentials authorize reports only; a compromised query endpoint/parser/scheduler is a damaged responder path until these cells are reconstructed, and surviving endpoint hardware or impersonation reach remains in A/P. The first reconstructed response is issued only after this finite acquisition/decoding sequence. The source command/effect law must then install it and exclude later execution of older commands within the stated L_Q. If old commands can remain scheduled indefinitely, R supplies no finite influence-restoration time.

The tool does not trust READY. An intact tool executes its local sequence and waits nominal upper duration bounds. A faulty tool can lie, omit steps, misdirect within its physical reach, alter its image or repeat writes forever; its target is already in P. An observer need not learn which repair succeeded. The theorem guarantees enough actual capacity through cardinality and time bounds while local responders continue to use their ordinary robust evidence mechanism.

## Addressed coverage and residual preservation

For a store m and image I, let put(m,a,v) replace only address a. Define install([],I,m)=m and install(a::rest,I,m)=install(rest,I,put(m,a,I(a))). By induction, an address already equal to I(a) remains equal through any later image writes. For a in the write list, split at its first occurrence: that write establishes I(a), and later image writes preserve it. An address absent from the list is untouched. These are `install_preserves_correct`, `installed_member` and `unlisted_untouched` in Restoration.lean.

The checked interpreter has actual halt/write/boot operations: writes performed before halt do not receive the protected store effect. `execute_writes` proves the whole finite write tape while halted; `actual_script_installs` proves halt followed by that tape followed by boot yields the installed image and an unhalted processor. `actual_script_member` gives address-wise coverage. The script has exactly m+2 operations. A source realization with variable operation durations replaces each operation by its bounded waiting sequence; completion induction preserves the same cell result and sums the actual durations.

The full actual source image may use typed bytes/words and multiple finite blocks; the checked proof is generic for pure stores and uses Boolean cells in its explicit instruction interpreter. A source binding maps the finite typed image to those addressed operations without merging omitted state. The executable independently enumerates Boolean image/initial-store pairs through four cells and all write orders. Neither the Lean check nor that enumeration proves an omitted peripheral address irrelevant. A new relevant address reopens the coverage obligation.

L and world Q are separate fields. `release_keeps_residuals` and `write_keeps_knowledge_queue` in Evolution.lean check that release and address writes preserve them. Fresh image equality therefore cannot be cited as proof that old credentials were forgotten or in-flight commands were canceled.

## Real elapsed-time and recurrence laws

Let T_h be the halt bound, T_w the sum of all addressed write bounds, T_b the boot bound, T_I the complete postboot inquiry/processing/dispatch bound, and L_Q a bound covering both exclusion of preboot world effects and first prescribed effect installation. A conservative extended duration is

    D = T_h + T_w + T_b + T_I + L_Q.

Some physical queue expiry can overlap writes, so this sum can be conservative. It is deliberately not reduced until a parallel timing argument justifies the reduction. In the unit-operation specialization T_h=T_b=1 and T_w=m. Memory completion is m+2; physical completion is D. A tool failure or direct access during any part of the sequence puts the target in P or the rolling A window rather than making D a guaranteed cleanup time for that adversarial target.

Choose a spacing S≥D (the numerical instance uses D+1) and period P_period=nS. Target i starts at times iS+kP_period for k≥0. Given any nonnegative tick a, its next start s satisfies a≤s<a+P_period; this follows by the least nonnegative residue of iS−a modulo P_period. The finite local schedule uses its legitimate clock phase, not analyst fault state. A known bounded clock skew can be absorbed by padded start/outage intervals and a larger S; no skew-free physical deployment claim is made. The selected exact-tick source has the requisite nominal clock interface, with clock-compromised tools included in P.

The schedule's extended intervals are disjoint when D≤S. If k<l, then kS+D≤(k+1)S≤lS; a tick cannot lie in both [kS,kS+D) and [lS,lS+D). `maintenance_nonoverlap` checks this argument for arbitrary natural parameters. A healthy target is counted unavailable throughout the same interval as a damaged target. Intervals contain pending hold/effect tails; counting only halt/write time would undercount outage.

If a target with a nominal tool has no external access interference from a through a+P_period+D, its next scheduled attempt completes nominal influence before that endpoint. The actual uncontested writes establish the image; nominal boot and actual inquiry follow; queued effects are bounded by L_Q. Thus H=P_period+D is a conservative restoration horizon. This is a quantified result for every eligible starting tick a; a single favorable trace is not its support. The local tool need not detect a favorable interval. The condition can hold for some targets while other tools and current targets remain persistently malicious.

For primitive availability allowing missed attempts, give a source bound G such that an available complete scheduled operation interval begins within G ticks whenever the target has no other interference for the required duration. Replace P_period by G. Availability is expressed through port/tool accessibility, supply and interfering capabilities, never image equality, READY or successful restoration. If no such waiting bound is supplied, safety during missing opportunities may still follow C's capacity envelope but this theorem gives no bounded functional return. Merely eventual occurrence is insufficient for a quantitative physical-loss window.

For the shared candidate n=13,m=8,T_I=20,L_Q=4, the results are D=34,S=35,P_period=455,H=489. `numeric_horizon` checks the arithmetic. With the E window assumptions and r=f_target=f0=κ(H)=1, at most four targets are conservatively impaired. The concrete initial exposure footprint P0 includes all initial active access, contaminated targets and retained report credentials and has size at most one; its identity is unknown. Separate additional initial exposures require a larger f0 and reporting support. Using a five-loss initial transient in C is a valid conservative strengthening, not evidence that this bound may omit an initial identity. The evolving access trace can contain eight acquisitions spaced by at least 490 ticks, with persistent adverse tactics within currently held access and one permanently compromised tool. No time of last acquisition is announced or consumed. C must demonstrate the same-mission regime in which the larger accumulated no-repair loss fails; R does not substitute bookkeeping reduction for that physical necessity result.

## Shared work and physical-resource liability

Each port has a nominal finite physical operation rate and cost envelope, including failed operations. In the unit-operation specialization a port can perform at most one bounded operation per base tick, each costing at most c_op units and creating its declared bounded side effect. This is a physical interface bound even for a bad tool, not an instruction that a Byzantine tool obey the local repair schedule. All side effects enter the common p_t and all costs enter the same stock as inquiry and actuation.

At most one nominal maintenance sequence is in an extended interval at any tick under the staggered schedule. Hence honest scheduled halt/write/boot work is at most one operation per tick. Up to r_tool bad tools may additionally use their ports outside their schedule, contributing at most r_tool operations per tick. A safe joint bound is (1+r_tool)c_op, irrespective of overlap. For r_tool=1,c_op=2, this liability is four units per tick, not two. A sharper periodic average n(m+2)c_op/P_period may be used only with a burst/stock proof and the extra persistent faulty-tool demand; it cannot replace instantaneous feasibility for a small stock.

This accounting is valid over an unbounded run, including healthy maintenance and failed attempts. It is a demand bound, not a proof that supplies cover demand. C must combine it with bounded input admission, sensing, computing, all actual actuator consumption and environmental liabilities, then prove the stock recurrence under the stated supply and initial stock. The controller never resets resource history when a repair starts. C10 is active for this indefinite operation and renewal; no infinite sequence of free recovery opportunities is assumed.

## Failure witnesses, verification and integration boundary

The executable checks: corrupt memory remains after access release; learned identities and queued effects persist; without halt resident code can undo previous writes; omitting a relevant address leaves poison; last-write completion precedes functional return; simultaneous healthy maintenance destroys a single-outage assumption; unrestricted tool reach defeats identity counting; and repeated acquisition of one identity consumes two events. The quantitative trace exercises eight actual return-to-nominal transitions while retained evidence identities accumulate and a tool continues interfering indefinitely. All check families and source hashes are recorded in [evolution_results.json](evolution_results.json).

The generic whole-trace restoration and support proofs above are written induction arguments grounded in the actual operation interface, with the store/timing components kernel checked. The executable is an independently executed finite interpretation test, not a formalization of every infinite acquisition history. Neither this artifact nor the Lean modules independently proves I's estimate precision, C's coupled physical invariant, empirical write reliability, or correctness of a deployed firmware. These are exact stated integration/application duties, not permission to close R/C with an unexplained clean-state or winning-image assumption.

The chosen boundary leaves ever-bad tools and irreparable hardware unrepaired, but faults in their enforcement paths remain consequential in the positive physical budget. Stronger recovery of those tools would require another construction, not different labels. The prior-art comparison in [SOURCES](SOURCES.md) explains why proactive protocols with supplied pristine reboots or tamper-proof correct-code recovery are components/comparisons rather than imports that discharge this mechanism.
