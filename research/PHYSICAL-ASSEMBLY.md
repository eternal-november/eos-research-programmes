# Actor-local physical execution and refinement adapter

[physical_adapter.py](physical_adapter.py) instantiates the common execution interface for the implemented Evidence controller and timed-recovery controller. It supplies an actual pipeline from observed measurements through attributed reports, locally calculated intervals, gate selection, protected reservations, FIFO execution and continuous flow. It does not give the controller true inventory, actual fault identity, or future disturbances. The finite checks are explicit witnesses for this adapter; the universal nonblocking argument below uses the proved coverage/intersection laws, not an extrapolation from an enumeration.

The shared definitions remain in [Execution.lean](Execution.lean). The adapter does not replace them with another authoritative execution core. Its imported mathematical premises are E-A through E-H from [EVIDENCE](EVIDENCE.md) and TR1–TR5 from [TIMED-RECOVERY](TIMED-RECOVERY.md), under their corrected finite-message, schedule and entry contracts. The already checked FIFO/refinement sources in [timed_recovery_sources](timed_recovery_sources.md) cover the relevant prior-art boundary. This is application and assembly, not a claim to invent controller refinement.

## Explicit instance of the common core

The concrete actor set is `{0,1,2,gate}`. Identities 0–2 each have a sensing and authorization role; the gate is correct in every admitted scenario. The fixed fault index f ranges over `{empty,{0},{1},{2}}` and is retained across all phases and modes. Physical hostile flow is a separately bounded interface of the same environment; it is not inferred from this cardinality. The role-lifting extension below handles separate roles under a larger single global fault family.

The concrete carrier X consists of `Frame` values. A frame retains the current sampled plant/FIFO and recovery state, actual evolving inventory and delivered service, the protocol phase, a readable event tick, current registered measurements, raw inboxes, actual signing-event records, selected command, the pending administrative observation, a bounded administrative-event credit, and each actor's local view history. The source may therefore distinguish a failed-authentication packet from no packet, or two different historical traffic patterns. Actual f and the analyst's physical coordinates do not belong to actor observations.

`observe(frame,i,p)` returns only actor i's history of `View` records. A view carries its clock/phase, protected public mode and schedule, its own registered reading when i is a sensor, its own received report artifacts and verification results, and the gate's received interval artifacts when i is the gate. In particular an identical raw signature object may be valid in one execution and invalid in another: the observed verification result is part of the local view. The policy never receives `auth.events` or the fault set. The analyst's signing-event ledger generates these local authentication observations under the ideal provenance model.

The stored history does not explicitly repeat an actor's own requested commands. For a correct actor following this fixed deterministic policy, those commands are reconstructed by applying `policy` to its earlier views; thus they are not silently ambiguous. This is sufficient for this implementation and its control query. Arbitrary replacement strategies, compromised internal memories, and epistemic statements about those strategies need an expanded history carrier. No perfect-recall or general strategic equivalence is inferred from the compression.

The action alphabets are decoded requests: send one report, send recipient-dependent entries, sign an interval, replay a token, select/commit, reserve, append a maintenance command, apply an observed administrative request, or idle. Unrecognized and malformed objects normalize to omission or rejection. A source actor can originate a token only under its own identity. Replays are not granted new signing authority. The trusted gate has its own policy and is not one of the Byzantine request components.

`Follows` is instantiated by `follows`: every correct actor's component equals `policy(i,observe(frame,i,p),p)`; faulty components are unrestricted decoded requests. Requests that change a correct component are outside this antecedent, not failed executions attributed to a legal adversary. `advance` supplies the next relation for a following profile and independently admissible physical/noise and protected administrative inputs. `initial_condition` is the checked Model.initial domain: valid parameters, fixed admitted f, clock/slot/era/delivered service zero, empty past schedule, the single initial measurement sample, no reservation or release witness, zero drain counter, no previous isolation, correctly sized capacity-feasible FIFO, and either a certified live pending tube with active full permission and no clean acknowledgment or a safe isolated-ready state with clean readiness, full permission and a constant-d FIFO. Correct registered measurements are supplied by the total quantizer. The ready entry is broader than the certified-live drain's reachable endpoint set; no such reachability is invented. `start` constructs only one of these initial frames and rejects other inputs. A continuation retains its existing `Frame`, histories and clocks; it never calls `start`. The initialization regressions reject, among other malformed internal states, a live phantom reservation with an empty-signature certificate and an overlapping conflicting past schedule.

## Local history and action maps

The abstract carrier is `AbstractPoint`: phase and physical registers, the current canonical input schedule, normalized attributed reports and interval permissions, and a ledger of attributed issuance facts. Raw unaccepted traffic and cryptographic wrappers are removed. The issuance ledger remains in the analyst's state so that future token provenance is generated correctly; it is not exposed as a pooled actor observation. This is an abstraction of the ideal event-authentication implementation, not a cryptographic security reduction.

For each actor i, `history_map(i,h,p)` reads only the actor's final local record. It checks the observed authentication results, epoch, round, source identity, message kind and context; it constructs an `AbstractView` with typed report or interval meanings. `abstract_policy` uses that record to compute an interval permission, gate decision or predetermined maintenance action. `lift` realizes an abstract reading as a send request and an abstract permission interval as a signing request for that actor. The concrete policy is literally their composition:

\[
\pi_i^{C}(h)=\operatorname{lift}_i\bigl(h,\pi_i^{A}(\operatorname{history\_map}_i(h))\bigr).
\]

The projection `alpha=projection` satisfies `history_map_i(observe_C(i,x))=observe_A(i,alpha(x))`, where the target observation is its corresponding `AbstractView`. This identity is checkable from the implementation and uses no hidden physical or fault coordinate. The current-view compression is sufficient because this particular policy uses current attributed evidence plus the retained nominal-history/FIFO snapshot. It is not asserted sufficient for blame, arbitrary nested knowledge, policy optimality, or all strategies that could exploit older observations.

`communication_image` computes the semantic action projection from the current source state and joint requests before selecting a successor or future disturbance. It exposes the valid attributed report lists or interval permissions generated by those requests. Correct action components correspond to the above local lift. The analyst may use the current signing ledger to project a Byzantine replay; this is allowed for the simulation proof and does not become an input to any honest policy.

The target next relation has four flow cases and two boundary cases. The source and target are compared by `abstract_next_matches`, including separately evaluated state-flow and channel clauses:

1. Report phase: the correct source's current registered reading is signed and delivered to every authorizer. A Byzantine source can provide different values, omissions or replays. Only provenance-valid, current-scope reports enter abstract inboxes.
2. Endorsement phase: every correct authorizer applies the Evidence or recenter interval rule to its own inbox and canonical schedule. Correct issuance facts must match that result. Byzantine intervals may be arbitrary; invalid scopes, reversed/malformed endpoints and extra identities are rejected before deduplication.
3. Gate phase: a correct gate selects from current supported interval intersections or installs the protected recenter reservation. During drain, repair or reservation execution it appends the prescribed d or reserved input. The source executes the actual `ev.gate_select` or `tr.reserve_batch` component; the target selection is calculated from interval meanings. These outputs are compared, not assumed interchangeable.
4. Physical phase: the FIFO consumes one old input and appends the committed input; the physical state, delivered service, mode counter and nominal schedule update by the explicit plant law. Canonical schedule clipping/extension, target slot and time increments are checked independently from the source component's update.

At each physical round boundary, phase -1 is an explicit environment-input selection event. All correct actors idle. Its successor enters report phase 0, or phase 4 with a pending administrative observation if credit remains. Selection occurs inside `advance(next_admin=...)` and consumes an event tick; a caller does not mutate an already-returned frame to install an unrecorded event. Phase 4 then consumes the observed request through the gate's local action and the actual `tr.admin` component. Other correct actors idle, so these events do not falsely record sensor transmissions. `abstract_boundary_next_matches` independently compares the resulting public state with `target_admin_public`, which evaluates authentication/scope/office/mode/queue guards and the permitted institutional updates using only public inputs. Both boundary edges preserve actual inventory, delivered service, FIFO, physical time, and all previous local history; each appends its current view and advances the event tick. The phase-4 result returns to phase -1.

Administrative ingress is a protected-input contract, not authority supplied by constructing an `AdminObservation(authentic=True)` object. The external ideal authentication provider retains actual office-signing events and computes `admin_observation(auth,signature,order,...)`; `admitted_admin_input(auth,observation)` checks that the observation agrees with this provider. The environmental next relation admits only those observations, with `effective`, `clean`, and `consent` equal to the protected physical/repair/recognition acknowledgments stipulated by TimedRecovery. A manually forged positive authentication verdict is outside this input contract and is rejected by the regression predicate. The officer's signing ledger and the production of these protected acknowledgments remain external root state; the adapter preserves their observed consequences and does not prove them from message bytes. `LocalVerifier` is a local snapshot of that already-observed verdict, used to connect the actual component API. It is not a replacement signature-generation theorem. Gate observations and policy inputs contain the verdict and packet, never the root ledger or actual f. The same raw packet can have different verdicts in different root states; those are different local observations.

The executable ingress additionally normalizes structurally malformed root observations before the typed administrative component. For example, `AdminObservation(None,True,"isolate",effective=True)` is outside the provider contract and also becomes a failed-verification observation, so it cannot reach an attribute access on a supposedly verified nonexistent signature. Structural rejection does not certify the provenance of an otherwise well-shaped positive verdict. Likewise, `initial_condition` checks the rational, tuple, natural-number, Boolean and role-identity field types used by the pipeline; floating-point measurements/FIFO entries and Boolean pseudo-identities do not enter the rational execution model by Python's permissive numeric equality.

The target ledger admits a new correct signing event only if it is the prescribed current report or permission; a Byzantine event does not acquire a correct identity by being projected. Thus provenance is retained as a generation rule. The semantic target is not allowed arbitrary false reports attributed to correct sources, and it is not defined by requiring the desired safety conclusion.

## Action-indexed nonblocking, including malformed requests

For every f and frame reachable from that initial domain through the prescribed protocol and guarded administrative transitions, fix any joint request profile following the honest policy. This is the invariant-domain quantifier in `Nonblocking`, not a totality claim for malformed internal phase states. In particular a ready frame has its clean d-FIFO context, and a reserved frame carries the actual accepted reservation. Every permitted Byzantine request component is handled by a total phase-specific normalization: a valid rational send becomes an attributed report; a well-formed recipient vector becomes separate delivery choices; a verifiable replay is processed under its original scope; all other objects become omission/rejection. A syntactically well-formed but unusable interval is harmless absent evidence, rather than an exception that stops the protocol. An unhashable forged signature is explicitly rejected at the ingress boundary before calling the typed reservation verifier. The regression exercises this through the entire report–endorsement–reservation pipeline.

This normalization does not repair a false physical premise. The `disturbance` argument denotes an actual realized effect, which must lie within the declared physical bound. An out-of-bound realized bypass is not silently clamped to zero. By contrast, arbitrary message requests are processed by the gate/channel interface and can be rejected without blocking clock progression.

The proof of nonblocking is by phase. Input selection always has a successor, entering the administrative phase when permitted or the flow phase otherwise. Administrative processing applies a guarded transition or returns the unchanged recovery state; every attempt, including rejection, consumes one credit. Neither case blocks the clock. In a report phase, at least two correct source reports are generated and delivered under the independent channel deadline, regardless of faulty requests. At an endorsement phase their constraints cover every permitted target state, so each correct authorizer's envelope is nonempty. E-F in live mode, or TR3 in an eligible ready state with positive delay, clean d-FIFO and effective permission/capacity at least d+r, establishes a common member of the honest action intervals. The two honest endorsements therefore give an available gate support even when every faulty packet is absent or invalid. Every accepted support contains an honest endorser, so any action selected because of a Byzantine interval remains certified for the actual target. A ready state awaiting sufficient permission is a maintenance case: correct interval policies return None, at most one faulty signer cannot form a two-identity support, and the gate appends d. Physical isolation gives w=0, while capacity and the retained normative cap are at least d; the d-FIFO therefore keeps x fixed and delivers service. In particular, finish_repair with cap=d and r>0 follows this branch until grant_recenter. Delay-zero ready states likewise use maintenance rather than the positive-delay recenter formula. Other maintenance phases have a predetermined enabled d or reserved command under their queue/capacity guards. Finally, the affine plant with a committed input and any admissible disturbance has a successor, and the total sensor quantizer supplies the next correct observation. Thus the same policy has a successor for every following request profile, and the safety/service invariant is closed.

This argument quantifies over all values in the decoded request alphabets; the finite corpus is not its proof. The executable mathematical functions terminate for finite decoded inputs. They do not establish an implementation's worst-case bit complexity or network denial-of-service bound. The clock theorem remains conditional on the declared bounded ingress/processing and correct-message delivery interfaces. Raw byte parsing, resource policing and cryptographic implementation must realize that interface before exporting a deployment deadline. Malformed request rejection here establishes semantic nonblocking, not a benchmark of those external components.

Off the invariant or channel contract, an empty live certificate is represented by an explicit uncertified d continuation. It can fail safety; it is not an empty successor set that accidentally certifies success. `advance` also keeps physical transitions whose endpoints are unsafe. The positive proof excludes those outcomes through the constructed honest-information/support premises, not by filtering executions by their verdict.

## Clock, continuous flow and round contraction

For positive m, the executable instance expands each round into four ordered phases of duration T/4. This is an explicit allocation of the admitted total round budget, not a deduction that a physical channel meets these deadlines. The analytic argument also works with other declared phase durations totaling T, provided report collection and endorsement precede commitment and commitment finishes before the first target slot. Sensing occurs at the round's initial instant, and the current FIFO head drives the plant throughout these phases. Commitment occurs before the T boundary at which the new tail can first be needed when m=1. The source retains both the sampled round-start inventory and the actual evolving inventory. Neither is an authorizer input. The pending-tube theorem protects the actual state while communication occurs.

Every microtransition, including input selection and administrative processing, advances the readable event tick by one. This is the discrete clock used by the common core, and it is not globally proportional to physical time. `physical_time(frame,p)` is the round-start timestamp plus phase times T/4 in positive-delay flow phases; boundary phases have the round-start timestamp. Each zero-duration administrative processing event consumes one of six credits, and only completion of a full T-duration round restores those credits. At zero credit, input selection forces flow even if another administrative request is offered. Consequently each elapsed round uses at most `2*6+1+4=17` events: six selection/processing pairs, one flow-selection event, and four flow phases. Any fixed finite credit would prove the same non-Zeno law with its corresponding bound; six is the implementation choice, not a physical constant. The separate m=0 idealization performs three zero-duration communication/computation phases followed by one T-duration flow interval; the same finite event bound holds, but it must not inherit the positive-delay physical latency claim. These finite bounds plus the independent phase deadline prevent an infinite sequence of rejected inputs from starving elapsed time or fabricating service.

For a general bounded measurable disturbance, replace each executable constant quarter value by that quarter's integral average. It remains within the declared bound. The affine source solution gives the same endpoint update; E-E/TR3 supplies the full intersample tube, including points not represented by a sample. Summing the four disturbance integrals gives the round successor equation

\[
x_{k+1}=x_k+T(u_k-d)+\int_{kT}^{(k+1)T}w(s)\,ds,
\quad D_{k+1}-D_k=dT.
\]

`advance` checks this equality against the actual Evidence/TimedRecovery FIFO update, and the test independently recomputes the endpoint and queue append. The Python instance uses exact rational samples; the universal real trajectory statement follows from the integral and interval arguments, not from enumerating rational averages.

Apply `refinement_maps_run` to the phase-preserving source and target relation: the event tick, current scope, fixed fault index, local action realization and semantic successor clauses match on every flow, input-selection and administrative edge. The separate round contraction selects completion of physical phase 3; these boundaries are not uniformly spaced in event ticks once administrative events are included. It is not incorrectly passed to a same-index theorem as though several source events were one target event. Its clock decoder maps physical round completions to kT and retains the continuous tubes, with finitely many zero-duration guarded boundary changes at that same physical time. Safety decoding uses the tube invariant and guard-preserving administrative updates; service decoding uses actual elapsed time and the delivered-flow coordinate, which does not jump on boundary events. Hence both properties are transported for the same implemented controller. A bare endpoint-state quotient without the tubes or the guarded boundary relation would not support this conclusion.

Administrative mode changes are admitted only at round boundaries, through the guarded TimedRecovery interface with unchanged physical state. The adapter now implements their bounded sequencing as actual source/target edges. Its complete recovery test retains one frame through isolation, drain, reduced-capacity service, restoration, locally endorsed reservation, release and resumed live operation; it checks every edge's action lift, target match, history extension, elapsed time and delivered service. It does not reset f, event history, or physical coordinates when composing these phases. Repair completion and consent remain conditional environmental events; if they do not arrive, continuing isolated rounds still supply d continuously. Six rejected requests exercise credit exhaustion; a further offered request forces flow and physical progress.

Independent review corrected a scope overstatement in the first timed artifact: a certified live FIFO with zero-disturbance draining has nominal endpoint z with `[z-r delta,z+r delta] subset S`, so z already lies in J and constant-d repair preserves it. The recenter block is redundant for that stricter entry contract, though the unified implementation can safely run it. It is useful for the separately admitted arbitrary-safe isolated-ready entry, whose states can lie outside J. Both entry contracts are represented in the adapter tests. The lower-boundary release failure belongs to the latter slice, not to the ordinary certified drain.

## Role lifting without resetting the fault model

`Roles` supplies injective sensor and authorizer triples. For a single global B, define the two local projections by source-role and authorizer-role membership respectively. The projections can differ and can overlap; they are not independently selected fault sets. The source-hypothesis family is the image of the whole original family under the sensor-role map. The actual B remains fixed while correct sensor events and correct authorizer policies are selected by their respective global identities.

`roles_admitted` checks every candidate role triple against every admitted global B. For the two Institution configurations and its 256-member static global family, every source triple and authorizer triple contains at most one faulty member. The scalar Evidence diameter argument therefore applies to the projected measurement family; the gate's two-share support contains a correct global authorizer; and two globally correct authorizers remain available. Their interval compatibility is still supplied by the physical theorem, not by the role counts alone. `role_round` performs the actual per-recipient report, local-inference, endorsement, gate and plant calculation under those maps.

The checker covers both configurations against all 256 global coalitions: 512 lifted instances. It rejects the mixed sensor triple `(0,6,7)` because an admitted global B can corrupt both 0 and 6. It separately realizes the colocated case by taking both role maps to `(0,1,2)` and restricting the global family to the four singleton-or-empty coalitions. That is the concrete timed instance. No independent budgets or new actual-fault choice are smuggled into this specialization.

This role adapter proves per-configuration control compatibility. It does not by itself migrate active membership, queues or keys between configurations. The Institution adapter owns recognition and historical/current-scope behavior; an actual timed membership transition must additionally preserve the release and pending-command conditions. A proof for each configuration separately is not presented as that transition proof.

## Reproduction and exact verification scope

Run `python -B physical_adapter.py`; `run_checks()` returns the same dictionary without file writes. The selected finite corpus uses delays 0,1,2, live and restored ready states, four fixed joint fault sets, multiple inventories, bounded quarter disturbances, malformed commands, distinct faulty report values, broad/narrow/reversed interval requests, unverified forged objects, and authentic stale replays. It checks action-indexed successors, current local policy factorization across hidden-fault cases, source/target communication images, target phase/register laws, current schedule scope, actual gate results, FIFO contraction and continuing service. An additional complete recovery path executes through the same microstep pipeline, including an actual waiting-ready round with only a broad Byzantine interval, no honest interval certificate, preserved inventory and delivered service. All counts in the returned audit describe this finite corpus, not arbitrary numeric enumeration.

The source code exposes `Frame`, `View`, `AbstractView`, `AbstractPoint`, `observe`, `history_map`, `abstract_policy`, `lift`, `policy`, `follows`, `communication_image`, `advance`, `projection`, `abstract_next_matches`, `AdminObservation`, `admin_observation`, `admitted_admin_input`, `boundary_advance`, `abstract_boundary_next_matches`, `physical_time`, `Roles` and `role_round`. The generic Lean transport theorem supplies the reusable implication; this concrete adapter's generation/interpretation proof is the case analysis above and its executable checks. It is not a new mechanized Lean instance or an independently verified physical deployment. The maintained trust boundary includes the ideal event-authentication oracle and its protected ingress, accurate bounded sensor interface, protected gate/queue, actual isolation and service ports, protected repair/recognition acknowledgments, and admissible clock/processing interface.
