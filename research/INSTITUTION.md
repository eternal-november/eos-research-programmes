# Institutional control and service-preserving recovery

This component extends the maintained integer inventory controller in [README](README.md). Its central result is a constructive refinement: a current institutional action restriction can be conjoined with local physical certificates, while a versioned, physically isolated recovery cycle preserves the same inventory invariant and unit service. The positive theorem has an explicit administrative and physical trust boundary. It does not prove a system of law, a cryptographic protocol, or unrestricted mobile-fault recovery.

[Institution.lean](Institution.lean) imports the existing Control module and checks sixteen declarations. [institution_model.py](institution_model.py) generates signed reports, local endorsements, assembled certificates, institutional registrations, physical administrative effects and repeated service transitions. It exposes `State`, `GateView`, `authorizer_policy`, `gate_observation`, `control_epoch`, `register_order`, `administrative_step`, and `run_checks()` for integration. [institution_sources.md](institution_sources.md) records the source assessment that preceded construction. Mathematical verification is separate from repository acceptance.

## Common state, faults and policy information

The physical plant is exactly the existing integer benchmark: inventory x is initially in S={2,...,8}; each completed epoch realizes x'=x+u-1+b, where the subtraction is an actually delivered unit. Live mode has control capacity two and hostile-flow radius one. A physical mode is a statement about the true installed interface, not a registry label. The gate receives that mode through the trusted isolation/repair interface described below.

A configuration k carries an era and two ordered triples of sensor and authorizer identities. The operational family uses configuration 0 with sensors (0,1,2), authorizers (3,4,5), and configuration 1 with sensors (6,7,8), authorizers (9,10,11). One static global coalition B is fixed before the execution. The joint fault family consists of subsets of these twelve identities having at most one member in each sensor triple and each authorizer triple, across both configurations. This gives 256 subsets, not independently resampled fault choices. The same adversary controls the bounded bypass at every epoch, even if B is empty, as in the original benchmark. Correctness never assumes statistical independence. The trusted gate, reliable service port, isolation/repair interface and administrative registrar are outside B. The administrative office is represented by identity 12.

The integer counts are a finite realization of parameterized role maps. The necessary reusable condition is that each installed configuration's role projection of this same B has the proved sensing and authorization properties. The executable admission test is public: `configuration_allowed` checks the proposed distinct-identity role maps against every member of the fixed fault family, never against the analyst's actual B. Both selected configurations pass; a proposed sensor triple mixing identities (0,6,7) fails because a jointly admitted coalition can contain 0 and 6. A duplicate-identity triple also fails. Configuration transitions cannot discard B or silently reinterpret leaked keys as honest capabilities.

`State` retains x and B for the execution semantics. Neither is given to an authorizer or gate policy. `GateView` contains the installed configuration, current institution, epoch and acknowledged physical mode. An authorizer additionally receives only its own authenticated report messages. Every correct sensor chooses one current reading within one unit of x and sends that same value to each authorizer; a faulty sensor may send recipient-dependent values or omit messages. Current collection occurs only at the synchronous cutoff that guarantees honest reports have arrived. Signature verification certifies an attributed signing event, not measurement truth.

The representation kernel excludes within-epoch drift, fractional states, delayed cross-epoch measurements, lost correct messages, faulty service/interlock roots, and unbounded administrative processing. A protocol epoch consists of at most one administrative attempt, then sensing/endorsement as needed, then a mandatory service transition. Administrative work cannot create an infinite sequence of zero-service internal steps. An uncompleted maximal execution with a pending epoch has a failed service verdict (`maximal_verdict`); a merely pending prefix has not yet missed its deadline. This is synchronous logical time, not seconds or a continuous physical guarantee.

## Institutional state and genuinely separate judgments

The institutional state N stores recognized status, a normative injection cap, a generation number, and recognized office holders. The modeled status belongs to the maintained device/interface; installed configuration and physical isolation are separate state coordinates. The finite status set is active, suspended, repairing, ready. Its warrant is the recovery transitions it enables; it is not a proposed universal taxonomy of institutions.

The following judgments have different consumers and are implemented separately:

| Judgment | Definition in this institution | Consumer and separating witness |
|---|---|---|
| Technical ability | An action has an effect admitted by the actual physical mode/capacity relation. | A bounded hostile bypass changes inventory without institutional power or permission. |
| Credential validity/access | The ideal authentication oracle recognizes the actual signing event; the caller also needs an effective invocation path. | A valid signature by identity 20 has no office power; a permitted powered action with `access=False` does not execute. |
| Institutional power | A current authenticated registration by a recognized office holder validly changes N according to `recognize`. | `register_order` applies a powered `grantTwo` even without consent and records a conduct breach. |
| Permission | The conduct rule for that order holds in the current status and physical mode; `grantTwo` additionally requires stipulated recipient consent. | The preceding valid registration is forbidden. The enforced path rejects it. Safety necessity does not manufacture consent. |
| Recognized status | The result of a valid constitutive registration. | Suspension changes the status to suspended but leaves the bypass radius one. |
| Obligation | A history-indexed requirement with a bearer, beneficiary, trigger, deadline and exceptions. | An otherwise safe zero-delivery epoch breaches the duty; later restoration does not erase it. |

These rules are stipulated organizational semantics and make no claim about any jurisdiction. The raw institutional machine and its enforced implementation have deliberately different transition relations. `register_order` represents a valid exercise of office power, including a prohibited exercise. `administrative_step` refines it by checking credential validity, power, permission and effective access before registering and installing an effect. The positive recovery implementation uses this enforced path with a correct registrar. The wider raw machine supplies the countermodel showing what is lost if permission is identified with validity. The theorem does not claim that arbitrary office-holder misconduct is impossible in the wider machine.

The constitutive rules are concrete: suspend sets recognized status to suspended; isolate leaves N unchanged; beginRepair sets repairing; finishRepair sets ready; reinstate sets active and increments the institutional generation; grantTwo changes the normative cap to two. Physical effects are coupled separately: isolation changes the hostile radius to zero, beginning repair reduces remaining correct capacity to one, finishing repair restores capacity two, and reinstatement installs the next fresh configuration and releases isolation. Thus a powered status update alone supplies no physical-effect theorem.

The `Duty` record identifies its bearer as the gate operator, its beneficiary as the modeled recipient, its trigger as epoch start, its required behavior as delivery of one unit, and its deadline as epoch end. The selected mission has no exception permitting service suspension during repair. The generic record can contain recognized exception epochs, but an untrusted event's exception flag has no effect and the positive cycle has no exception. `duty_breach` asks whether any triggered duty's first matching deadline missed delivery. The independent online monitor retains pending epochs and the historical breach bit. `breach_monitor_exact` proves the general indexed failure-monitor equivalence used once these trigger/deadline failures are extracted. The executable enumerates every six-epoch binary delivery history and compares its online monitor to the independently evaluated history predicate at every prefix, with untriggered ends and unauthorized exceptions tested separately. A maximal finite stalled epoch is judged separately, so removing the deadline event cannot vacuously discharge service.

A recipient claim against the operator is here the stipulated correlate of this duty. It changes the verdict because silent shutdown fails the recipient's requirement. No additional doctrine about liberties, liabilities or legal rights is imported. The office has no operation that waives the service duty; this limited absence of power can be called an immunity relative to this interface, but it supplies no physical tamper resistance.

## Norm-constrained control and incompatible obligations

For an arbitrary public permission predicate P on integer controls, define `LawfulCertified P m u := Certified m u ∧ P u`. Correct authorizers endorse exactly their locally certified controls that satisfy P. `LawfulAccepted` preserves the existing two-distinct-support rule and unknown-fault quantification. `lawful_gate_sound` proves that any such accepted control both preserves S under the hostile bound and satisfies P. One honest signer supplies both facts; it is not sufficient to take safety from one context and permission from another.

Availability is a separate theorem. `lawful_gate_available` uses the existing common control a(x) as an analyst witness and requires P(a(x)). No runtime actor is given x. This condition suffices for the same actual local policy to supply a certificate from honest transmissions. It is not asserted necessary for every coordination protocol. An arbitrary nonempty permission set may remove the intersection that service requires.

The concrete incompatibility is normative cap one in live mode. At x=2 and b=-1, every permitted u in {0,1} yields x'≤1; `forbidden_unit_cap` proves the empty lawful safe-action set. Technical capacity is still two, and u=2 would maintain the lower bound while serving one unit. Therefore physical ability, institutional permission, safety and service have genuinely different verdicts. A valid and permitted `grantTwo` registration, supplied with the stipulated consent, restores the original C1–C4 policy. The executable performs this registration and the next physical service step. If consent is withheld, the incompatibility is the supported result; the controller cannot solve it by silently suppressing delivery or treating technical necessity as new authority.

The positive recovery cycle uses cap two in live mode and at least cap one during isolation. `control_epoch` checks the remaining normative restriction even for its constant isolated control. Public institutional-state digests are bound into every endorsement. A stale institution digest cannot authorize a current action, even if the cryptographic signature remains valid.

## Public evidence contracts

There are three distinct objects: the event/fact, its witness artifact, and a verifier. Their soundness is a theorem under explicit assumptions, not their definition.

For current intervention, a signed endorsement binds signer, key era, configuration digest, epoch, institutional digest and control. `report_round` generates actual report signing events. `authorizer_policy` computes the median and finite robust-action check from each local received vector. `endorsement_round` generates its signed output. Before deduplicating identities, `assemble` validates each packet's authentication, message kind, key era, configuration/epoch/institution/control payload and signer eligibility. Only valid shares may occupy a support slot; it then selects the least control with accepted support. The separate public `verify_current` guard checks the complete artifact, including distinct identities and at least two shares. Neither function consults x, B, physical safety or the desired conclusion.

This ordering is part of the availability mechanism, not an extra cryptographic assumption. For a packet multiset M and command u, let V_u(M) be the identities having at least one individually valid current share for u. Filtering before deduplication preserves exactly V_u(M), regardless of packet order or duplicate multiplicity. Adding packets invalid for every current command therefore leaves every candidate's support unchanged. Deduplicating claimed identities first violates this law: at x=2 with B={5}, a forged wrong-era packet claiming identity 3 can replace its genuine u=2 share, suppressing the certificate supplied by correct identities 3 and 4. The regression reproduces that exact input and requires successful service authorization. It also checks authentic but ineligible senders, wrong kinds and scopes, and 2,520 distinct packet orderings containing duplicated Byzantine shares. This is an abstract finite-message availability guarantee; bounded processing and timely honest delivery remain the synchronous environmental premises, not a wall-clock denial-of-service theorem.

The refinement from this verifier to `LawfulAccepted` uses the same static B, ideal signature attribution, current role membership, correct local code, current evidence coverage, and matching public institutional state. The reverse construction uses the common-action proof and timely delivery. These different directions respectively establish soundness and attainable evidence. The executable creates valid artifacts in ordinary control epochs rather than only testing rejection predicates. Honest transmissions already suffice, so a faulty authorizer may withhold all shares. The 4,536 exhaustive median/fault/support profiles include every optional Byzantine control subset; every accepted control is independently checked against all three bypass values.

For historical attribution, `verify_equivocation` checks two actual report signatures by the same identity/era for the same configuration, epoch and sample identifier but different values. Correct code emits one sampled value to all recipients. `equivocation_sound` proves that two such recorded events refute that signer's sample-consistency rule; `equivocation_nonvacuous` exhibits a two-event witness. The executable generates the witness through recipient-dependent Byzantine reports and verifies it. It also rejects all pairs of generated honest reports as equivocation, despite honest measurement disagreement between different sensors.

The attribution fact is credential-level protocol deviation. It is neither physical measurement falsity nor human culpability. Consistent lying may leave no equivocation evidence. Omission alone is not this proof. Intervention availability therefore does not depend on complete blame assignment. Conversely, obtaining blame evidence after an unsafe physical event would not prevent that event.

Historical acceptance does not require current membership. Old signed events can remain evidence while their signatures are rejected for current execution. The checked scope theorem and executable reject old eras, old epochs, duplicate identities and mixed configurations. However, an ordinary signature's timestamp field does not prove its real generation time after key compromise. The authentication model records actual signing events; the historical verifier proves those events with the labeled sample, not an unqualified wall-clock attribution. A stronger historical timing claim would require forward-secure erasure or contemporaneous honest receipt evidence. No such stronger claim is used here.

## Effective isolation and recovery theorem

For integer bounds lo≤hi, demand d, nonnegative radius r and control cap c, `robust_region_iff` proves exactly:

\[
\forall x\in[lo,hi]\;\exists u\in[0,c]\;\forall b\in[-r,r]:x+u-d+b\in[lo,hi]
\quad\Longleftrightarrow\quad
d+r\le c\ \land\ r\le d\ \land\ 2r\le hi-lo.
\]

The endpoint inequalities and successor interval width establish necessity. Sufficiency chooses u=max(0,lo-x+d+r). This is a full-information capability theorem; the live distributed realization still uses C1–C4. It cannot be used to give actors hidden state.

The recovery construction uses four physical modes: live has (c,r)=(2,1); isolated has (2,0); repair has (1,0); ready has (2,0). Live mode uses the existing permissive distributed controller. In every other mode, the gate applies u=1, yielding x'=x while still delivering one unit. `mode_action_exists` proves nonempty action interfaces; `mode_service_step` proves actual capacity bounds and safety; `recovery_invariant` proves safety for every infinite recurrence satisfying these mode/action/effect interfaces. `recurring_unit_service` separately proves that one delivered unit each epoch accumulates to exactly T units over T epochs. The operational construction supplies those deliveries through its joint state transition; a certificate alone does not.

The enforced sequence is suspend, isolate, beginRepair, finishRepair, reinstate. Service continues in live mode after suspension, during every isolated or repair epoch, and after the new configuration is installed. Repair may last arbitrarily many completed epochs: constant replenishment preserves both inventory and delivered service. Completion of repair requires the named clean-repair premise, while ongoing service does not require eventual repair completion.

Order matters. If capacity is removed before isolation, the intermediate interface has c=1,r=1. At x=2,b=-1 its possible successors are 0 and 1, both unsafe. Logical revocation leaves this obstruction unchanged. Actual isolation changes r to zero and makes unit-capacity repair feasible. The initial and intended final states may both be safe even though the wrong transition order is not. This is the consumed R4 coupling counterexample.

The isolation interface promises that all residual hostile channels are prevented or bounded by r=0 while that mode is acknowledged. It is a physical trust premise, not a consequence of the status field or signature. Likewise, the remaining unit-capacity replenisher and service port must persist during repair. The repair acknowledgment asserts restored capacity, initialized controller state, fresh uncompromised keys for correct replacement identities, and no reusable pending old command. The implementation rejects a false `clean=False` readiness request; it does not prove that an external `clean=True` report is truthful. Assurance terminates at the stated protected root/physical restriction.

The source-level extension comparison is explicit: the old context has a fixed live interface/configuration; the new context admits scheduled capability reduction and membership replacement. Isolation plus mode-specific control replaces the old always-live capacity assumption. Restricting the new execution to a constant live mode and unchanged configuration recovers C1–C4's inventory and unit-service properties. This comparison preserves sampled safety and logical per-epoch service, not wall-clock latency, privacy, or universal fault attribution.

The positive recovery theorem remains a zero-delay context and is not composed here with a delayed-command/FIFO theorem. A queued u=2 is not realizable after correct capacity falls to one. Moreover, a controller proved against a retained global hostile radius one requires capacity at least two by the displayed capacity theorem, whereas this repair mode uses its newly acknowledged local radius zero. Carrying an old predictive envelope or queue across that switch needs a separate admission/flush/realization argument. A common semantic carrier does not discharge these physical compatibility conditions, and juxtaposing the timed and recovery artifacts does not establish timed recovery.

## Configuration, keys and the joint fault boundary

Each accepted reinstatement installs a strictly newer era and a role configuration certified against the entire public global fault family. It never queries the actual B to decide admission. All old reports and shares are excluded from current collections; commands bind configuration, era, epoch and institution. The trusted gate's current counter is not rolled back. Its mandatory transition advances the epoch after one injection, so an old certificate cannot cause a second effect. A new control epoch samples again; it does not reuse the preceding inventory estimate.

Two configuration-wise fault bounds are insufficient if shares are mixed. In the concrete family, identity 5 can be faulty in the old authorizer triple and identity 11 faulty in the new triple. Each configuration separately has only one faulty authorizer. Their two signatures satisfy a scope-blind count of two but contain no honest signer. At inventory 8 they can endorse control 2, producing 10 with bypass 1. `mixed_scopes_cannot_match` and the executable current verifier exclude exactly this false transport.

Clean repair requires more than renaming a key. The executable grants an adversary retained old-era key access, verifies the resulting old signature historically and rejects it for current actuation. It separately exhibits a falsely clean current key: one nominally correct new authorizer's leaked current credential plus the one admitted Byzantine authorizer produces a valid-looking unsafe current certificate. This perturbation violates the operational honest-signature premise even though the nominal identity count looks acceptable. The right repair is to change the effective fault/accounting premise or supply genuinely fresh key material, not to reuse the old theorem.

The positive family permits different faulty identities in different disjoint configurations only because B already contains them at the beginning. It does not prove mobile corruption, an unbounded corruption rate, or rehabilitation of an identity whose current keys remain controlled by the adversary. Reconfiguration and physical restoration are therefore selected, checked extensions with stated interfaces; broader mobile recovery is not inferred.

## Capability inference countermodels

`capability_step` is a separate diagnostic projection of the same action/effect distinction: command is 0 or 1, capacity is 0 or 1, output is min(command,capacity)+hostile, and the environment may remove capacity after an effect. An external observer sees only output. Two generated traces start with capacity one and produce output one; one retains capacity and the other loses it before the next step. Thus a past successful effect does not determine persistent capability. Two other generated traces produce zero: an able actor chooses zero, while an incapable actor attempts one. Equal external observations do not identify incapacity. Revealing the private command or observing hardware state changes the information quotient and can change that verdict.

The same finite plant separates contribution from forceability: with command one, hostile choice zero permits output one, while hostile cancellation minus one prevents it. Existential favorable cooperation is not universal robustness. These are bounded operational countermodels to proposed inference rules, not substitutes for the positive recovery controller or claims about empirical hardware failure rates.

## Verification, assembly and remaining trust

Run Python without bytecode writes: `python -B institution_model.py`. `run_checks()` returns a deterministic dictionary for the coordinator runner. It checks 560 bounded capacity parameter tuples, 4,536 local support profiles, all 256 fixed global fault sets over seven initial inventories, 1,792 complete recovery traces and 14,336 realized service epochs, 2,520 invalid/duplicate-share orderings, plus the public-evidence, administrative, key/era, breach and capability countermodels. The recovery traces use deterministic representative noisy/hostile reports; they do not exhaust all multi-epoch physical schedules. The infinite safety conclusion comes from the Lean recurrence and its operational assumptions; bounded trace counts are not its proof.

For Lean 4.33.0, compile `Control.lean` to a temporary directory as `Control.olean`, set `LEAN_PATH` to that directory for the command, and run `Institution.lean`. The sixteen exported declarations report only `propext`, `Classical.choice`, and `Quot.sound`, or no axioms. There are no task-specific axioms, `sorry`, admitted proofs, or native-computation trust extensions. Importing Control does not reclassify its authentication/effect premises as proofs of implementations.

[INSTITUTION-ASSEMBLY](INSTITUTION-ASSEMBLY.md) and [institution_adapter.py](institution_adapter.py) implement the phased common-core adapter, including observable verification results, one retained B, explicit unavailable-mission successors, local-history factorization and four-phase service decoding. The component functions alone do not establish that embedding; the linked adapter supplies its construction and proof. Independent integrated checking is recorded in [PROGRAM-AUDIT](PROGRAM-AUDIT.md).

This is author-side semantic review plus kernel and executable verification. Independent review should try to break the mode acknowledgment, current/historical evidence distinction, era-binding, global fault projection and administrative scheduling assumptions. Remaining empirical/cryptographic premises are declared roots of this conditional theorem; they are not claims that monitor deployment or software tests have physically discharged them.
