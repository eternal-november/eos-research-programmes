# Ordinary quorum alignment with operational signing

[Control.lean](Control.lean) reconstructs the Q3 characterization of available support families whose pairwise intersections contain a correct actor under every admitted fault set. The inspected prior result and its source boundary are the Malkhi–Reiter row in [SOURCES](SOURCES.md). That geometry does not alone establish a protocol's certificate conclusion. The remaining P9 obligation here is the explicit alignment with signing, artifact acceptance and allowed state transitions.

[QuorumAlignment.lean](QuorumAlignment.lean) supplies that alignment for one fixed slot and epoch. The history contains only signatures valid for that context; the guard is not a multi-slot ledger or a view-change lock rule. Correct signers retain atomic persistent own-signature state while those signatures remain valid. Clearing it without invalidating old artifacts breaks the realization premise. Fix an identity type I, value type V, joint fault family F, actual B∈F, and support family A. A state is a finite history of actual (identity,value) signing events. Seen(h,i,v) means that event occurred; an authenticated share witnesses exactly that event under the same ideal event-authentication boundary as the digital and institutional modules. A certificate for v consists of a support Q∈A and authentic shares showing Seen(h,i,v) for every i∈Q. Verification is operational and does not test agreement.

A scheduled signing request (i,v) has a total update. A Byzantine actor may append any own signature. Correct code reads only that actor's own previously signed values and appends v if every earlier own value equals v; otherwise it rejects, leaving the signing facts unchanged. The actual B selects which component implementation is followed, as in the common core's Follows relation; B is not an input to the correct local guard. Rejection is a fact-preserving event with an advancing clock, not absent execution. The enclosing scheduler may choose any request and does not acquire future information.

The invariant Exclusive(B,h) says that every correct actor's signed values in this context agree. Empty history satisfies it. For an appended event, either its actor is faulty and the correct actors' facts are unchanged, or the local guard equates the new value with every old own value. Rejection preserves the old history. Theorems empty_exclusive, issue_preserves and generated_exclusive check this argument over every finite prefix of an arbitrary infinite request sequence.

If two accepted certificates have supports Q and R, their honest intersection supplies i∈Q∩R outside B. Authentication gives two actual signing events by i; Exclusive equates their values. operational_certificate_exclusion proves this without restricting the generated runs to the desired conclusion. Combining it with conflict_family_iff_Q3 recovers the ordinary quorum exclusion result with its required signer discipline.

Issued facts and possession are separate. ReceiptSound requires every received signature to occur in the actual issued history. receipt_certificate_issued lifts an accepted receipt artifact to issued facts, and received_certificate_exclusion applies the exclusion theorem to two independently received bundles. issue_seen_preserved proves persistence of issued facts; for certificates received at different finite times, lift both to the later history. generated_exclusive holds at every finite prefix of an arbitrary infinite request sequence, so this also proves cross-time exclusion within the same fixed context. No completed infinite history or eventual receipt is assumed.

Availability has a different premise. An available fault-disjoint support and actual signatures from every correct actor on v yield a certificate in that history; operational_certificate_available checks that implication. Apply it to a received history only after establishing honest-share delivery there. Issuance alone is not possession. This is not a proof that arbitrary independently chosen requests cause correct actors to agree or that an arbitrary scheduler delivers messages. A concrete non-vacuity construction fixes a publicly known v, starts with empty signing histories, has each correct actor sign it, and delivers those shares. The guard permits every such correct command. A concrete stall has correct identities 0,1,2 first sign 0,1,1, respectively, while faulty identity 3 omits. The three-element support family has honest pairwise intersections and fault-disjoint availability, but neither value has three signatures. Later opposite-value requests at correct signers are processed as rejections and the stall persists. The finite checker retains this six-request trace. Thus even a nonblocking signing machine and available support geometry do not provide common-value production. Termination of Byzantine agreement remains the separate D2 protocol theorem; no quorum arithmetic replaces it.

The executable [quorum_alignment.py](quorum_alignment.py) checks four identities, at most one fixed fault, binary values and three-share supports. Its state projection retains the set of signed identity/value facts; own observation retains only the actor's own signed values. The kernel forgets order and duplicate events, which are irrelevant to this guard and certificate query. Induction on append/reject proves that projection commutes with the factual update. An independent bit-level updater checks the same equality for every reachable state and scheduled request. Chronological attribution, signing deadlines and cross-context evolution would require retaining more history; they are not exported from this quotient.

The complete finite graph has 513 reachable fault-indexed fact states and 4,617 scheduled request edges, including no-op and rejected commands. All 5,125 authentic receipt subsets preserve the issued-fact and conflict-exclusion correspondence. Ten honest-only common-value publications, with those shares delivered, construct certificates without Byzantine cooperation. The checker also exhibits two failures: removing the correct own-history guard allows conflicting certificates, and replacing Q3 by two-of-three Q2 support permits honest actors to sign different values while the faulty actor supports both. Neither failure contradicts the physical permissive gate, which intentionally permits several alternatives but realizes only one effect, nor D3's two-share terminal certificates, whose conflict exclusion comes from D2 agreement.

Eight declarations pass the pinned Lean kernel with the approved foundations. The generic issue definition uses classical choice for arbitrary types; the finite implementation has decidable identity/value equality and an explicitly enumerable support family. Finite graph checks establish the stated finite implementation; the general history and support proofs supply their own quantified scope. This module adds an operational theorem to the source reconstruction, not a new quorum threshold, generic consensus algorithm or cryptographic implementation.
